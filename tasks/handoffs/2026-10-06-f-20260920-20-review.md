## Mandate (fixed)

Close `f-20260920-20`: `scripts/check-tauri-command-boundary.mjs` decides the platform-facade
boundary by regex over raw source, so it cannot tell code from comments or strings and cannot
evaluate a specifier that is not one literal token (measured misses: ``import(`${"@tauri-apps/plugin-updater"}`)``
and `import("@tauri-apps/" + "plugin-updater")`); the hand enumeration of syntax has no end
condition and its comment-aware gap is quadratic. Open question: comment masking or a Babel-backed
check. Known limits (concatenation, literal interpolation, runtime assembly) must be pinned as tests.

## Planned answer

- Babel AST through the existing shared `scripts/parse-ts-source.mjs` — no masking pass, no new
  dependency. Supersedes `d-20260831-29` (regex over parser) on new evidence. `f-20260829-04`'s
  masker shipped as a Rust-grammar lexer, so the "shared primitive" argument for masking is gone.
- Module references only at grammar positions: import/export declarations, `import x = require()`,
  dynamic `import()`, `require()`, `TSImportType`, and Vitest's module-path API
  (`mock`/`doMock`/`unmock`/`doUnmock`/`importActual`/`importMock`, including the `import()` promise
  overload). TS value wrappers transparent everywhere.
- Specifiers evaluated statically (literals, literal-only templates, `+`, constant variable alias
  chains through the shared `resolveChain`, which gains a per-caller parameter-stop option);
  `path.evaluate()` not used. An unresolvable specifier whose static prefix does not rule out
  `@tauri-apps/` fails closed with `module specifier is not statically resolvable`; the
  generated-bindings rule's unresolved case is a named, tested known limit.
- Bindings, barrel, listener and native-facade rules ported to the AST with unchanged messages and
  allowlist/denylist content; a parse failure fails the gate (`Cannot parse <path>: …`);
  `parseTsSource` enables `jsx` for `.jsx`. All regex scanner constants and the two regex-gap
  performance tests are deleted. One phase, role `normal`.

## Approach

### O1 — Module references come from syntax positions only

**Rests on:** "cannot distinguish code from comments or strings"; "the enumeration has no end
condition".

Each renderer file is parsed once with `parseTsSource` (T3). A *module reference* exists only at
these syntax positions, each tagged with a kind:

| Position | Kind |
|---|---|
| `ImportDeclaration.source` (value, type-only, side-effect) | `static` |
| `ExportNamedDeclaration.source`, `ExportAllDeclaration.source` | `static` |
| dynamic `import(arg)` (`CallExpression` with `Import` callee, or `ImportExpression`) | `dynamic` |
| `require(arg)` — call whose callee is the `Identifier` `require` | `dynamic` |
| `TSImportType` argument (`typeof import("…")`, `import("…").T`) | `type-query` |
| `vi.<m>(arg, …)` where `<m>` ∈ {`mock`, `doMock`, `unmock`, `doUnmock`, `importActual`, `importMock`} — Vitest's module-path API; non-computed member or computed static string on the `Identifier` `vi` | `mock` |

The position set is closed by the language grammar and Vitest's documented module-path API, not by
observed spellings; whitespace, comments, parentheses and TS wrappers around any part of it are
irrelevant because the parser has already consumed them. Nothing outside these positions is a
module reference: a specifier in a comment, string, template, regex literal or JSX text is not seen.

### O2 — Specifiers are evaluated statically; an unresolvable one that could reach Tauri fails closed

**Rests on:** "cannot evaluate a specifier that is not a single literal token"; "Known limits to pin
as tests […] the point is that the gate states its limits rather than implying completeness".

* A `static` reference's specifier is its string literal.
* A `dynamic`, `type-query` or `mock` reference's first argument is evaluated with Babel's
  `path.evaluate()` (T6). A confident string result is the specifier: this resolves concatenation,
  literal-only template interpolation and constant bindings.
* A non-confident argument is **unresolved**. Its *known prefix* is the leading static text: the
  first quasi of a template literal, or the confidently evaluated left operand chain of a `+`
  concatenation; otherwise empty.
* An unresolved reference whose known prefix does **not** rule out an `@tauri-apps/` specifier
  (the prefix is empty, is a prefix of `@tauri-apps/`, or starts with `@tauri-apps/`) is a violation
  in **every** file, with the message `module specifier is not statically resolvable: <source text>`
  and the 1-based line. A prefix that rules it out (e.g. `../translation/`, T8) passes.
* For the `bindings/generated` rule (O4) an unresolved specifier is **not** flagged: it is a named,
  tested known limit (accidental runtime assembly of a relative path to the generated module is not
  in the threat model, and no prefix rule can tell a relative path apart from it).

### O3 — Tauri reach rule

**Rests on:** "this is the gate that keeps native capability behind `src/platform/`".

* A resolved specifier is a Tauri specifier iff it matches, anchored, `@tauri-apps/api` optionally
  followed by `/…`, or `@tauri-apps/plugin-…` — today's `TAURI_SPECIFIER` class, applied to the
  resolved string instead of to source text.
* Outside `platform/native.ts`: any module reference of any kind with a Tauri specifier is
  `direct @tauri-apps module access` (unchanged message), except that in `bindings/generated.ts`
  a `static` reference to a specifier in `GENERATED_BINDINGS_IMPORT_ALLOWLIST` (unchanged set) is
  allowed. `platform/tauri.ts` gets no exemption (unchanged).
* Type-only references (`import type`, `typeof import(…)`) remain violations, as today.

### O4 — Bindings, barrel and listener rules on the AST

**Rests on:** "cannot distinguish code from comments or strings" — these rules are regexes over raw
text today (T1) and carry the same defect.

Applies to every file except `platform/tauri.ts` and `bindings/generated.ts` (unchanged scope):

* `direct bindings/generated module access` — a `static`, `dynamic` or `type-query` reference whose
  resolved specifier matches today's `isGeneratedBindings`. A `mock` reference is legal
  (`d-20260831-32`).
* `runtime commands/events import from bindings barrel` — an `ImportDeclaration` from a specifier
  matching today's `isBindingsBarrel`, not `importKind: "type"`, holding a non-type `ImportSpecifier`
  whose imported name is `commands` or `events` (today's rule; `as` aliasing included).
* `raw .listen() call` — a call or optional call whose callee is a member access whose property is
  `listen` (identifier, or computed static string).
* `raw listen() call` — a call whose callee is the `Identifier` `listen`.
* `raw tauriEvents access` — a member access whose object is the `Identifier` `tauriEvents`.

Messages are unchanged. Behavioural change, intended: a declaration named `listen` (not a call) no
longer matches, and text in comments/strings never does.

### O5 — Native facade contract on the AST

**Rests on:** "one intermediate revision rejected a legitimate `from /* c */ "…"` re-export on the
real native facade".

For `platform/native.ts`:

* Re-export triples come from `ExportNamedDeclaration`s with a Tauri `source`: each `ExportSpecifier`
  yields `{ specifier, exported: <Babel local name>, local: <Babel exported name> }` (T7 mapping;
  `type`-kind specifiers included, kind not part of the key, as today).
* `NATIVE_EXPORT_ALLOWLIST` exact equality and the independent `NATIVE_EXPORT_DENYLIST` are unchanged
  in content and semantics (`d-20260831-28`), including their messages.
* An `ExportAllDeclaration` or `ExportNamespaceSpecifier` with a Tauri source is
  `native export star is forbidden: <specifier>`.
* Any other module reference with a Tauri specifier, and any unresolved reference under O2, is
  `native facade may only use named Tauri re-exports` (unchanged message; the O2 message is
  additionally reported for an unresolved one).

### O6 — A parse failure fails the gate

**Rests on:** the gate must not "imply completeness": a file it cannot read as code is not a
clean file.

A renderer file `parseTsSource` rejects makes `runTauriBoundaryCheck` throw
`Cannot parse <listed path>: <detail>` (the IPC consumer gate's shape, T10), so the CLI exits 1.
`inspectSource` propagates the parser error to its caller unwrapped; the runner adds the path.

### O7 — Regex scanner removed; exported surface preserved

**Rests on:** "`SPECIFIER_GAP` collapses back" / the performance annotation — a parser makes the
gap regexes, and the cost model they carried, obsolete.

* Deleted: `SPECIFIER_GAP`, `FROM_SPECIFIER`, `SIDE_EFFECT_SPECIFIER`, `TEMPLATE_TAURI_SPECIFIER`,
  `CALL_SPECIFIER`, `NATIVE_EXPORT`, `NATIVE_EXPORT_STAR`, `MODULE_CALL`, `MODULE_FROM`,
  `MODULE_SIDE_EFFECT`, `BINDINGS_IMPORT`, and the three listener regexes.
* Preserved exports and signatures: `NATIVE_EXPORT_ALLOWLIST`, `NATIVE_EXPORT_DENYLIST`,
  `inspectSource(path, source, { allowlist, denylist })`, `inspectCapability`, `inspectCsp`,
  `inspectAssetProtocol`, `runTauriBoundaryCheck({ workspaceRoot, listFiles, readFile })`.
  `inspectSource` still returns a de-duplicated array of message strings; `path` is the

## Approach

### O1 — Module references come from syntax positions only

**Rests on:** "cannot distinguish code from comments or strings"; "the enumeration has no end
condition".

Each renderer file is parsed once with `parseTsSource` (T3). A *module reference* exists only at
these syntax positions, each tagged with a kind:

| Position | Kind |
|---|---|
| `ImportDeclaration.source` (value, type-only, side-effect) | `static` |
| `ExportNamedDeclaration.source`, `ExportAllDeclaration.source` | `static` |
| `TSImportEqualsDeclaration` whose `moduleReference` is a `TSExternalModuleReference` (`import x = require("…")`, `import type x = require("…")`, `export import x = require("…")`) | `static` |
| dynamic `import(arg)` (`CallExpression` with `Import` callee, or `ImportExpression`) | `dynamic` |
| `require(arg)` — call whose callee is the `Identifier` `require` | `dynamic` |
| `TSImportType` argument (`typeof import("…")`, `import("…").T`) | `type-query` |
| `vi.<m>(arg, …)` where `<m>` ∈ {`mock`, `doMock`, `unmock`, `doUnmock`, `importActual`, `importMock`} — Vitest's module-path API; non-computed member or computed static string on the `Identifier` `vi` | `mock` |

**TypeScript value wrappers are transparent everywhere.** Babel keeps `as`, `satisfies`, `!`,
instantiation and angle-bracket assertions as nodes (probe: `(vi as any).mock(…)` has a
`TSAsExpression` object). Every callee, callee object, argument and constant-binding initializer is
unwrapped through the shared `VALUE_WRAPPERS` set of `scripts/parse-ts-source.mjs` before it is
classified or evaluated; parentheses and comments are already consumed by the parser.

**Vitest's module-promise overload.** `vi.mock(import("…"), factory)` (and the same overload of the
other listed methods, per `vitest/dist/index.d.ts:337`) names its module through the inner dynamic
import. When a `mock` position's first argument, unwrapped, is a dynamic `import(…)`, that import's
argument is the mock reference's specifier argument and the inner import is **not** a separate
`dynamic` reference, so `d-20260831-32`'s legal generated-bindings mock stays legal in both spellings.

The position set is closed by the language grammar and Vitest's documented module-path API, not by
observed spellings. Nothing outside these positions is a module reference: a specifier in a comment,
string, template, regex literal or JSX text is not seen.

**JSX-bearing files parse.** The runner scans `src/**/*.[jt]sx?`, but `parseTsSource` enables the
`jsx` plugin only for `.tsx` (probe: a `.jsx` file with JSX fails `Unterminated regular expression`).
`parseTsSource` enables `jsx` for `.jsx` as well; its other consumers parse only `.ts`/`.tsx`
(`check-ipc-command-consumers.mjs:386`, `check-untranslated-jsx.mjs`), so their behaviour is
unchanged. The tree has no `.js`/`.jsx` file under `src/` today.

### O2 — Specifiers are evaluated statically; an unresolvable one that could reach Tauri fails closed

**Rests on:** "cannot evaluate a specifier that is not a single literal token"; "Known limits to pin
as tests […] the point is that the gate states its limits rather than implying completeness".

* A `static` reference's specifier is its string literal.
* A `dynamic`, `type-query` or `mock` reference's specifier argument is evaluated statically,
  wrapper-transparently (O1): a string literal; a numeric literal (as its string form, inside a
  concatenation); a template literal whose every expression evaluates; a `+` concatenation whose
  operands evaluate; an identifier whose **constant** alias chain, followed through the shared
  `resolveChain` of `scripts/parse-ts-source.mjs` (the repository's one alias walk,
  `d-20260921-02`), ends at an evaluable initializer. Babel's `path.evaluate()` is not used: it
  stops at TS wrappers (probe: `const p = "@/platform/native" as const; import(p)` is non-confident
  under it) and would be a second alias walk beside `resolveChain`.
* Anything else is **unresolved**. Its *known prefix* is the leading static text: the evaluated
  leading quasi(s) of a template literal up to the first unevaluable expression, or the evaluated
  leftmost operands of a `+` concatenation up to the first unevaluable one; otherwise empty.
* An unresolved reference whose known prefix does **not** rule out an `@tauri-apps/` specifier
  (the prefix is empty, is a prefix of `@tauri-apps/`, or starts with `@tauri-apps/`) is a violation
  in **every** file, with the message `module specifier is not statically resolvable: <source text>`
  and the 1-based line. A prefix that rules it out (e.g. `../translation/`, T8) passes.
* For the `bindings/generated` rule (O4) an unresolved specifier is **not** flagged: it is a named,
  tested known limit (accidental runtime assembly of a relative path to the generated module is not
  in the threat model, and no prefix rule can tell a relative path apart from it).

### O3 — Tauri reach rule

**Rests on:** "this is the gate that keeps native capability behind `src/platform/`".

* A resolved specifier is a Tauri specifier iff it matches, anchored, `@tauri-apps/api` optionally
  followed by `/…`, or `@tauri-apps/plugin-…` — today's `TAURI_SPECIFIER` class, applied to the
  resolved string instead of to source text.
* Outside `platform/native.ts`: any module reference of any kind with a Tauri specifier is
  `direct @tauri-apps module access` (unchanged message), except that in `bindings/generated.ts`
  a `static` reference to a specifier in `GENERATED_BINDINGS_IMPORT_ALLOWLIST` (unchanged set) is
  allowed. `platform/tauri.ts` gets no exemption (unchanged).
* Type-only references (`import type`, `typeof import(…)`) remain violations, as today.

### O4 — Bindings, barrel and listener rules on the AST

**Rests on:** "cannot distinguish code from comments or strings" — these rules are regexes over raw
text today (T1) and carry the same defect.

Applies to every file except `platform/tauri.ts` and `bindings/generated.ts` (unchanged scope):

* `direct bindings/generated module access` — a `static`, `dynamic` or `type-query` reference whose
  resolved specifier matches today's `isGeneratedBindings`. A `mock` reference is legal
  (`d-20260831-32`).
* `runtime commands/events import from bindings barrel` — an `ImportDeclaration` from a specifier
  matching today's `isBindingsBarrel`, not `importKind: "type"`, holding a non-type `ImportSpecifier`
  whose imported name is `commands` or `events` (today's rule; `as` aliasing included).
* `raw .listen() call` — a call or optional call whose callee is a member access whose property is
  `listen` (identifier, or computed static string).
* `raw listen() call` — a call whose callee is the `Identifier` `listen`.
* `raw tauriEvents access` — a member access whose object is the `Identifier` `tauriEvents`.

Messages are unchanged. Behavioural change, intended: a declaration named `listen` (not a call) no
longer matches, and text in comments/strings never does.

### O5 — Native facade contract on the AST

**Rests on:** "one intermediate revision rejected a legitimate `from /* c */ "…"` re-export on the
real native facade".

For `platform/native.ts`:

* Re-export triples come from `ExportNamedDeclaration`s with a Tauri `source`: each `ExportSpecifier`
  yields `{ specifier, exported: <Babel local name>, local: <Babel exported name> }` (T7 mapping;
  `type`-kind specifiers included, kind not part of the key, as today).
* `NATIVE_EXPORT_ALLOWLIST` exact equality and the independent `NATIVE_EXPORT_DENYLIST` are unchanged
  in content and semantics (`d-20260831-28`), including their messages.
* An `ExportAllDeclaration` or `ExportNamespaceSpecifier` with a Tauri source is
  `native export star is forbidden: <specifier>`.
* Any other module reference with a Tauri specifier, and any unresolved reference under O2, is
  `native facade may only use named Tauri re-exports` (unchanged message; the O2 message is
  additionally reported for an unresolved one).

### O6 — A parse failure fails the gate

**Rests on:** the gate must not "imply completeness": a file it cannot read as code is not a
clean file.

A renderer file `parseTsSource` rejects makes `runTauriBoundaryCheck` throw
`Cannot parse <listed path>: <detail>` (the IPC consumer gate's shape, T10), so the CLI exits 1.
`inspectSource` propagates the parser error to its caller unwrapped; the runner adds the path.

### O7 — Regex scanner removed; exported surface preserved

**Rests on:** "`SPECIFIER_GAP` collapses back" / the performance annotation — a parser makes the
gap regexes, and the cost model they carried, obsolete.

* Deleted: `SPECIFIER_GAP`, `FROM_SPECIFIER`, `SIDE_EFFECT_SPECIFIER`, `TEMPLATE_TAURI_SPECIFIER`,
  `CALL_SPECIFIER`, `NATIVE_EXPORT`, `NATIVE_EXPORT_STAR`, `MODULE_CALL`, `MODULE_FROM`,
  `MODULE_SIDE_EFFECT`, `BINDINGS_IMPORT`, and the three listener regexes.
* Preserved exports and signatures: `NATIVE_EXPORT_ALLOWLIST`, `NATIVE_EXPORT_DENYLIST`,
  `inspectSource(path, source, { allowlist, denylist })`, `inspectCapability`, `inspectCsp`,
  `inspectAssetProtocol`, `runTauriBoundaryCheck({ workspaceRoot, listFiles, readFile })`.
  `inspectSource` still returns a de-duplicated array of message strings; `path` is the
  `src/`-relative path and selects the `jsx` plugin by its `.tsx` suffix.
* The capability, CSP and asset-protocol checks are not touched.
* The top-of-file comment states the gate's known limits (O2's unresolved-generated case and the
  threat model's out-of-scope list) so the gate states its limits in the source as well as in tests.

### Verification

**Rests on:** "Known limits to pin as tests".

`scripts/check-tauri-command-boundary.test.mjs` is migrated (existing cases keep their intent;

## Approach

### O1 — Module references come from syntax positions only

**Rests on:** "cannot distinguish code from comments or strings"; "the enumeration has no end
condition".

Each renderer file is parsed once with `parseTsSource` (T3). A *module reference* exists only at
these syntax positions, each tagged with a kind:

| Position | Kind |
|---|---|
| `ImportDeclaration.source` (value, type-only, side-effect) | `static` |
| `ExportNamedDeclaration.source`, `ExportAllDeclaration.source` | `static` |
| `TSImportEqualsDeclaration` whose `moduleReference` is a `TSExternalModuleReference` (`import x = require("…")`, `import type x = require("…")`, `export import x = require("…")`) | `static` |
| dynamic `import(arg)` (`CallExpression` with `Import` callee, or `ImportExpression`) | `dynamic` |
| `require(arg)` — call whose callee is the `Identifier` `require` | `dynamic` |
| `TSImportType` argument (`typeof import("…")`, `import("…").T`) | `type-query` |
| `vi.<m>(arg, …)` where `<m>` ∈ {`mock`, `doMock`, `unmock`, `doUnmock`, `importActual`, `importMock`} — Vitest's module-path API; non-computed member or computed static string on the `Identifier` `vi` | `mock` |

**TypeScript value wrappers are transparent everywhere.** Babel keeps `as`, `satisfies`, `!`,
instantiation and angle-bracket assertions as nodes (probe: `(vi as any).mock(…)` has a
`TSAsExpression` object). Every callee, callee object, argument and constant-binding initializer is
unwrapped through the shared `VALUE_WRAPPERS` set of `scripts/parse-ts-source.mjs` before it is
classified or evaluated; parentheses and comments are already consumed by the parser.

**Vitest's module-promise overload.** `vi.mock(import("…"), factory)` (and the same overload of the
other listed methods, per `vitest/dist/index.d.ts:337`) names its module through the inner dynamic
import. When a `mock` position's first argument, unwrapped, is a dynamic `import(…)`, that import's
argument is the mock reference's specifier argument and the inner import is **not** a separate
`dynamic` reference, so `d-20260831-32`'s legal generated-bindings mock stays legal in both spellings.

The position set is closed by the language grammar and Vitest's documented module-path API, not by
observed spellings. Nothing outside these positions is a module reference: a specifier in a comment,
string, template, regex literal or JSX text is not seen.

**JSX-bearing files parse.** The runner scans `src/**/*.[jt]sx?`, but `parseTsSource` enables the
`jsx` plugin only for `.tsx` (probe: a `.jsx` file with JSX fails `Unterminated regular expression`).
`parseTsSource` enables `jsx` for `.jsx` as well; its other consumers parse only `.ts`/`.tsx`
(`check-ipc-command-consumers.mjs:386`, `check-untranslated-jsx.mjs`), so their behaviour is
unchanged. The tree has no `.js`/`.jsx` file under `src/` today.

### O2 — Specifiers are evaluated statically; an unresolvable one that could reach Tauri fails closed

**Rests on:** "cannot evaluate a specifier that is not a single literal token"; "Known limits to pin
as tests […] the point is that the gate states its limits rather than implying completeness".

* A `static` reference's specifier is its string literal.
* A `dynamic`, `type-query` or `mock` reference's specifier argument is evaluated statically,
  wrapper-transparently (O1): a string literal; a numeric literal (as its string form, inside a
  concatenation); a template literal whose every expression evaluates; a `+` concatenation whose
  operands evaluate; an identifier whose **constant variable** alias chain, followed through the
  shared `resolveChain` of `scripts/parse-ts-source.mjs` (the repository's one alias walk,
  `d-20260921-02`), ends at an evaluable initializer. Babel's `path.evaluate()` is not used: it
  stops at TS wrappers (probe: `const p = "@/platform/native" as const; import(p)` is non-confident
  under it) and would be a second alias walk beside `resolveChain`.
* **A parameter is never a known value.** `resolveChain` follows a defaulted parameter's default
  (`followsAlias`'s `AssignmentPattern` branch, `parse-ts-source.mjs`), which is right for the IPC
  consumer gate's facade bindings but wrong for a specifier: the caller overrides the default
  (`function load(s = "./local") { return import(s); } load("@tauri-apps/…")`). The shared walk
  gains a per-caller option that stops at a parameter binding, with or without a default (rule 11:
  per-site difference through a parameter); its default keeps today's behaviour, so
  `check-ipc-command-consumers.mjs` is unchanged. This checker always passes the option, so any
  chain that reaches a parameter is unresolved.
* Anything else is **unresolved**. Its *known prefix* is the leading static text: the evaluated
  leading quasi(s) of a template literal up to the first unevaluable expression, or the evaluated
  leftmost operands of a `+` concatenation up to the first unevaluable one; otherwise empty.
* An unresolved reference whose known prefix does **not** rule out an `@tauri-apps/` specifier
  (the prefix is empty, is a prefix of `@tauri-apps/`, or starts with `@tauri-apps/`) is a violation
  in **every** file, with the message `module specifier is not statically resolvable: <source text>`
  and the 1-based line. A prefix that rules it out (e.g. `../translation/`, T8) passes.
* For the `bindings/generated` rule (O4) an unresolved specifier is **not** flagged: it is a named,
  tested known limit (accidental runtime assembly of a relative path to the generated module is not
  in the threat model, and no prefix rule can tell a relative path apart from it).

### O3 — Tauri reach rule

**Rests on:** "this is the gate that keeps native capability behind `src/platform/`".

* A resolved specifier is a Tauri specifier iff it matches, anchored, `@tauri-apps/api` optionally
  followed by `/…`, or `@tauri-apps/plugin-…` — today's `TAURI_SPECIFIER` class, applied to the
  resolved string instead of to source text.
* Outside `platform/native.ts`: any module reference of any kind with a Tauri specifier is
  `direct @tauri-apps module access` (unchanged message), except that in `bindings/generated.ts`
  a `static` reference to a specifier in `GENERATED_BINDINGS_IMPORT_ALLOWLIST` (unchanged set) is
  allowed. `platform/tauri.ts` gets no exemption (unchanged).
* Type-only references (`import type`, `typeof import(…)`) remain violations, as today.

### O4 — Bindings, barrel and listener rules on the AST

**Rests on:** "cannot distinguish code from comments or strings" — these rules are regexes over raw
text today (T1) and carry the same defect.

Applies to every file except `platform/tauri.ts` and `bindings/generated.ts` (unchanged scope):

* `direct bindings/generated module access` — a `static`, `dynamic` or `type-query` reference whose
  resolved specifier matches today's `isGeneratedBindings`. A `mock` reference is legal
  (`d-20260831-32`).
* `runtime commands/events import from bindings barrel` — an `ImportDeclaration` from a specifier
  matching today's `isBindingsBarrel`, not `importKind: "type"`, holding a non-type `ImportSpecifier`
  whose imported name is `commands` or `events` (today's rule; `as` aliasing included).
* `raw .listen() call` — a call or optional call whose callee is a member access whose property is
  `listen` (identifier, or computed static string).
* `raw listen() call` — a call whose callee is the `Identifier` `listen`.
* `raw tauriEvents access` — a member access whose object is the `Identifier` `tauriEvents`.

Messages are unchanged. Behavioural change, intended: a declaration named `listen` (not a call) no
longer matches, and text in comments/strings never does.

### O5 — Native facade contract on the AST

**Rests on:** "one intermediate revision rejected a legitimate `from /* c */ "…"` re-export on the
real native facade".

For `platform/native.ts`:

* Re-export triples come from `ExportNamedDeclaration`s with a Tauri `source`: each `ExportSpecifier`
  yields `{ specifier, exported: <Babel local name>, local: <Babel exported name> }` (T7 mapping;
  `type`-kind specifiers included, kind not part of the key, as today).
* `NATIVE_EXPORT_ALLOWLIST` exact equality and the independent `NATIVE_EXPORT_DENYLIST` are unchanged

  `native export star is forbidden: <specifier>`.
* Any other module reference with a Tauri specifier, and any unresolved reference under O2, is
  `native facade may only use named Tauri re-exports` (unchanged message; the O2 message is
  additionally reported for an unresolved one).

## Decisions and trade-offs

## Decided autonomously

* **Q:** Mask comments and keep the regexes, or replace the scanner with a Babel-backed check?
  **Chosen:** Babel AST through the existing `scripts/parse-ts-source.mjs`. **Rejected:** a JS
  comment-masking pre-pass. **Because:** masking JavaScript correctly needs regex-literal versus
  division context, which is parser knowledge; masking alone leaves concatenation, literal-template
  interpolation and constant bindings unevaluated (two of the finding's three known limits), so the
  syntax enumeration keeps its missing end condition; the "shared primitive" with `f-20260829-04`
  did not materialise — that run shipped a Rust-grammar masker (`scripts/rust-source-mask.mjs`), and
  the JavaScript primitive that does exist and is shared is the Babel parser (T3, T4). No new
  dependency. Cost measured: 2.0 s parse+traverse for 409 files versus ~0.2 s today, inside an
  unconditional contract gate whose IPC consumer member already parses the tree in 1.4 s.
  **Supersedes** `d-20260831-29` (regex over parser) on new evidence that decision did not have: two
  measured loading forms missed after nine hand-closed ones, a quadratic gap, a native-facade false
  positive, and the existence of a shared parse primitive.
* **Q:** What does the gate do with a dynamic specifier it cannot evaluate? **Chosen:** refuse it
  when its static prefix does not rule out `@tauri-apps/` (O2), pass it otherwise. **Rejected:**
  passing every unresolvable specifier as a tested residual (`d-20260831-29`'s choice), and refusing
  every unresolvable specifier (reddens the legitimate locale import in `src/utils/db.test.ts`, T8).
  **Because:** the finding requires the gate to state its limits; the IPC consumer gate's `C5` is the
  repository precedent for refusing unresolvable reach; the prefix rule is exact on today's tree.
* **Q:** Which `vi` calls are module references? **Chosen:** Vitest's module-path API
  (`mock`, `doMock`, `unmock`, `doUnmock`, `importActual`, `importMock`). **Rejected:** `vi.mock`
  only (today; `vi.importActual("@tauri-apps/…")` reaches around the facade identically); any `vi.*`
  call (`vi.fn(impl)` would make every mock factory an unresolvable specifier). `d-20260831-32`
  (generated mocks legal) stands.
* **Q:** Do listener rules match text or calls? **Chosen:** calls and member accesses (O4).
  **Rejected:** keeping raw-text regexes for these three rules beside an AST for the rest — two
  mechanisms for one question in one file (rule 11, `d-20260921-02`'s one-mechanism precedent).

## Threat model and non-goals

Frozen in round 1.

* **In scope — accidental reach.** A contributor or agent writing ordinary TypeScript/TSX in `src/`
  that loads, mocks, re-exports or type-references an `@tauri-apps/*` module outside
  `src/platform/native.ts`, imports `bindings/generated` outside the facade, imports runtime
  `commands`/`events` from the bindings barrel, or calls a raw event listener — including through
  every syntactic variation the language allows at those positions (comments anywhere, template
  literals, string concatenation, constant bindings, parenthesisation, TS wrappers).
* **In scope — false positives.** Text that merely mentions a specifier or `listen(` (comments,
  string/template contents, regex literals, JSX text) must never be a violation.
* **Out of scope — deliberate evasion.** `eval`, `new Function`, `globalThis["req" + "uire"]`,
  a destructured `const { mock } = vi`, reaching Tauri through `window.__TAURI_INTERNALS__`, and a
  relative path into `node_modules/@tauri-apps/…` are not module references this gate can classify.
  They are named as known limits in the checker's header comment, not closed. (Wrapping `import`
  in a helper whose parameter is the specifier is *not* evasion in this sense: O2 refuses it.)
* **Environment.** The renderer source tree as enumerated by `listWorkingTreeFiles` (tracked +
  untracked `src/**/*.[jt]sx?`), parsed with the repository's pinned `@babel/core`.

## Approach

### O1 — Module references come from syntax positions only

**Rests on:** "cannot distinguish code from comments or strings"; "the enumeration has no end
condition".

Each renderer file is parsed once with `parseTsSource` (T3). A *module reference* exists only at
these syntax positions, each tagged with a kind:

| Position | Kind |
|---|---|
| `ImportDeclaration.source` (value, type-only, side-effect) | `static` |
| `ExportNamedDeclaration.source`, `ExportAllDeclaration.source` | `static` |
| `TSImportEqualsDeclaration` whose `moduleReference` is a `TSExternalModuleReference` (`import x = require("…")`, `import type x = require("…")`, `export import x = require("…")`) | `static` |
| dynamic `import(arg)` (`CallExpression` with `Import` callee, or `ImportExpression`) | `dynamic` |
| `require(arg)` — call whose callee is the `Identifier` `require` | `dynamic` |
| `TSImportType` argument (`typeof import("…")`, `import("…").T`) | `type-query` |
| `vi.<m>(arg, …)` where `<m>` ∈ {`mock`, `doMock`, `unmock`, `doUnmock`, `importActual`, `importMock`} — Vitest's module-path API; non-computed member or computed static string on the `Identifier` `vi` | `mock` |

**TypeScript value wrappers are transparent everywhere.** Babel keeps `as`, `satisfies`, `!`,
instantiation and angle-bracket assertions as nodes (probe: `(vi as any).mock(…)` has a
`TSAsExpression` object). Every callee, callee object, argument and constant-binding initializer is
unwrapped through the shared `VALUE_WRAPPERS` set of `scripts/parse-ts-source.mjs` before it is
classified or evaluated; parentheses and comments are already consumed by the parser.

**Vitest's module-promise overload.** `vi.mock(import("…"), factory)` (and the same overload of the
other listed methods, per `vitest/dist/index.d.ts:337`) names its module through the inner dynamic
import. When a `mock` position's first argument, unwrapped, is a dynamic `import(…)`, that import's
argument is the mock reference's specifier argument and the inner import is **not** a separate
`dynamic` reference, so `d-20260831-32`'s legal generated-bindings mock stays legal in both spellings.

The position set is closed by the language grammar and Vitest's documented module-path API, not by
observed spellings. Nothing outside these positions is a module reference: a specifier in a comment,
string, template, regex literal or JSX text is not seen.

**JSX-bearing files parse.** The runner scans `src/**/*.[jt]sx?`, but `parseTsSource` enables the
`jsx` plugin only for `.tsx` (probe: a `.jsx` file with JSX fails `Unterminated regular expression`).
`parseTsSource` enables `jsx` for `.jsx` as well; its other consumers parse only `.ts`/`.tsx`
(`check-ipc-command-consumers.mjs:386`, `check-untranslated-jsx.mjs`), so their behaviour is
unchanged. The tree has no `.js`/`.jsx` file under `src/` today.

### O2 — Specifiers are evaluated statically; an unresolvable one that could reach Tauri fails closed

**Rests on:** "cannot evaluate a specifier that is not a single literal token"; "Known limits to pin
as tests […] the point is that the gate states its limits rather than implying completeness".

* A `static` reference's specifier is its string literal.
* A `dynamic`, `type-query` or `mock` reference's specifier argument is evaluated statically,
  wrapper-transparently (O1): a string literal; a numeric literal (as its string form, inside a
  concatenation); a template literal whose every expression evaluates; a `+` concatenation whose
  operands evaluate; an identifier whose **constant variable** alias chain, followed through the
  shared `resolveChain` of `scripts/parse-ts-source.mjs` (the repository's one alias walk,
  `d-20260921-02`), ends at an evaluable initializer. Babel's `path.evaluate()` is not used: it
  stops at TS wrappers (probe: `const p = "@/platform/native" as const; import(p)` is non-confident
  under it) and would be a second alias walk beside `resolveChain`.
* **A parameter is never a known value.** `resolveChain` follows a defaulted parameter's default
  (`followsAlias`'s `AssignmentPattern` branch, `parse-ts-source.mjs`), which is right for the IPC
  consumer gate's facade bindings but wrong for a specifier: the caller overrides the default
  (`function load(s = "./local") { return import(s); } load("@tauri-apps/…")`). The shared walk
  gains a per-caller option that stops at a parameter binding, with or without a default (rule 11:
  per-site difference through a parameter); its default keeps today's behaviour, so
  `check-ipc-command-consumers.mjs` is unchanged. This checker always passes the option, so any
  chain that reaches a parameter is unresolved.
* Anything else is **unresolved**. Its *known prefix* is the leading static text: the evaluated
  leading quasi(s) of a template literal up to the first unevaluable expression, or the evaluated
  leftmost operands of a `+` concatenation up to the first unevaluable one; otherwise empty.
* An unresolved reference whose known prefix does **not** rule out an `@tauri-apps/` specifier
  (the prefix is empty, is a prefix of `@tauri-apps/`, or starts with `@tauri-apps/`) is a violation
  in **every** file, with the message `module specifier is not statically resolvable: <source text>`
  and the 1-based line. A prefix that rules it out (e.g. `../translation/`, T8) passes.
* For the `bindings/generated` rule (O4) an unresolved specifier is **not** flagged: it is a named,
  tested known limit (accidental runtime assembly of a relative path to the generated module is not
  in the threat model, and no prefix rule can tell a relative path apart from it).

### O3 — Tauri reach rule

**Rests on:** "this is the gate that keeps native capability behind `src/platform/`".

* A resolved specifier is a Tauri specifier iff it matches, anchored, `@tauri-apps/api` optionally
  followed by `/…`, or `@tauri-apps/plugin-…` — today's `TAURI_SPECIFIER` class, applied to the
  resolved string instead of to source text.
* Outside `platform/native.ts`: any module reference of any kind with a Tauri specifier is
  `direct @tauri-apps module access` (unchanged message), except that in `bindings/generated.ts`
  a `static` reference to a specifier in `GENERATED_BINDINGS_IMPORT_ALLOWLIST` (unchanged set) is
  allowed. `platform/tauri.ts` gets no exemption (unchanged).
* Type-only references (`import type`, `typeof import(…)`) remain violations, as today.

### O4 — Bindings, barrel and listener rules on the AST

**Rests on:** "cannot distinguish code from comments or strings" — these rules are regexes over raw
text today (T1) and carry the same defect.

Applies to every file except `platform/tauri.ts` and `bindings/generated.ts` (unchanged scope):

* `direct bindings/generated module access` — a `static`, `dynamic` or `type-query` reference whose
  resolved specifier matches today's `isGeneratedBindings`. A `mock` reference is legal
  (`d-20260831-32`).
* `runtime commands/events import from bindings barrel` — an `ImportDeclaration` from a specifier
  matching today's `isBindingsBarrel`, not `importKind: "type"`, holding a non-type `ImportSpecifier`
  whose imported name is `commands` or `events` (today's rule; `as` aliasing included).
* `raw .listen() call` — a call or optional call whose callee is a member access whose property is
  `listen` (identifier, or computed static string).
* `raw listen() call` — a call whose callee is the `Identifier` `listen`.
* `raw tauriEvents access` — a member access whose object is the `Identifier` `tauriEvents`.

Messages are unchanged. Behavioural change, intended: a declaration named `listen` (not a call) no
longer matches, and text in comments/strings never does.

### O5 — Native facade contract on the AST

**Rests on:** "one intermediate revision rejected a legitimate `from /* c */ "…"` re-export on the
real native facade".

For `platform/native.ts`:

* Re-export triples come from `ExportNamedDeclaration`s with a Tauri `source`: each `ExportSpecifier`
  yields `{ specifier, exported: <Babel local name>, local: <Babel exported name> }` (T7 mapping;
  `type`-kind specifiers included, kind not part of the key, as today).
* `NATIVE_EXPORT_ALLOWLIST` exact equality and the independent `NATIVE_EXPORT_DENYLIST` are unchanged
  in content and semantics (`d-20260831-28`), including their messages.
* An `ExportAllDeclaration` or `ExportNamespaceSpecifier` with a Tauri source is
  `native export star is forbidden: <specifier>`.
* Any other module reference with a Tauri specifier, and any unresolved reference under O2, is
  `native facade may only use named Tauri re-exports` (unchanged message; the O2 message is
  additionally reported for an unresolved one).

### O6 — A parse failure fails the gate

**Rests on:** the gate must not "imply completeness": a file it cannot read as code is not a
clean file.

A renderer file `parseTsSource` rejects makes `runTauriBoundaryCheck` throw
`Cannot parse <listed path>: <detail>` (the IPC consumer gate's shape, T10), so the CLI exits 1.
`inspectSource` propagates the parser error to its caller unwrapped; the runner adds the path.

### O7 — Regex scanner removed; exported surface preserved

**Rests on:** "`SPECIFIER_GAP` collapses back" / the performance annotation — a parser makes the
gap regexes, and the cost model they carried, obsolete.

* Deleted: `SPECIFIER_GAP`, `FROM_SPECIFIER`, `SIDE_EFFECT_SPECIFIER`, `TEMPLATE_TAURI_SPECIFIER`,
  `CALL_SPECIFIER`, `NATIVE_EXPORT`, `NATIVE_EXPORT_STAR`, `MODULE_CALL`, `MODULE_FROM`,
  `MODULE_SIDE_EFFECT`, `BINDINGS_IMPORT`, and the three listener regexes.
* Preserved exports and signatures: `NATIVE_EXPORT_ALLOWLIST`, `NATIVE_EXPORT_DENYLIST`,
  `inspectSource(path, source, { allowlist, denylist })`, `inspectCapability`, `inspectCsp`,
  `inspectAssetProtocol`, `runTauriBoundaryCheck({ workspaceRoot, listFiles, readFile })`.
  `inspectSource` still returns a de-duplicated array of message strings; `path` is the
  `src/`-relative path and selects the `jsx` plugin by its `.tsx` suffix.
* The capability, CSP and asset-protocol checks are not touched.
* The top-of-file comment states the gate's known limits (O2's unresolved-generated case and the
  threat model's out-of-scope list) so the gate states its limits in the source as well as in tests.

## Decisions and trade-offs

The contested points are the four entries under `## Decided autonomously` below: parser versus
masking, the unresolvable-specifier policy, the `vi` position set, and one mechanism for the
listener rules. They were decided under `full auto` and are recorded by the adopting session
through `findings.py record-decision`.

## Decided autonomously

* **Q:** Mask comments and keep the regexes, or replace the scanner with a Babel-backed check?
  **Chosen:** Babel AST through the existing `scripts/parse-ts-source.mjs`. **Rejected:** a JS
  comment-masking pre-pass. **Because:** masking JavaScript correctly needs regex-literal versus
  division context, which is parser knowledge; masking alone leaves concatenation, literal-template
  interpolation and constant bindings unevaluated (two of the finding's three known limits), so the
  syntax enumeration keeps its missing end condition; the "shared primitive" with `f-20260829-04`
  did not materialise — that run shipped a Rust-grammar masker (`scripts/rust-source-mask.mjs`), and
  the JavaScript primitive that does exist and is shared is the Babel parser (T3, T4). No new
  dependency. Cost measured: 2.0 s parse+traverse for 409 files versus ~0.2 s today, inside an
  unconditional contract gate whose IPC consumer member already parses the tree in 1.4 s.
  **Supersedes** `d-20260831-29` (regex over parser) on new evidence that decision did not have: two
  measured loading forms missed after nine hand-closed ones, a quadratic gap, a native-facade false
  positive, and the existence of a shared parse primitive.
* **Q:** What does the gate do with a dynamic specifier it cannot evaluate? **Chosen:** refuse it
  when its static prefix does not rule out `@tauri-apps/` (O2), pass it otherwise. **Rejected:**
  passing every unresolvable specifier as a tested residual (`d-20260831-29`'s choice), and refusing
  every unresolvable specifier (reddens the legitimate locale import in `src/utils/db.test.ts`, T8).
  **Because:** the finding requires the gate to state its limits; the IPC consumer gate's `C5` is the
  repository precedent for refusing unresolvable reach; the prefix rule is exact on today's tree.
* **Q:** Which `vi` calls are module references? **Chosen:** Vitest's module-path API
  (`mock`, `doMock`, `unmock`, `doUnmock`, `importActual`, `importMock`). **Rejected:** `vi.mock`
  only (today; `vi.importActual("@tauri-apps/…")` reaches around the facade identically); any `vi.*`
  call (`vi.fn(impl)` would make every mock factory an unresolvable specifier). `d-20260831-32`
  (generated mocks legal) stands.
* **Q:** Do listener rules match text or calls? **Chosen:** calls and member accesses (O4).
  **Rejected:** keeping raw-text regexes for these three rules beside an AST for the rest — two
  mechanisms for one question in one file (rule 11, `d-20260921-02`'s one-mechanism precedent).

## Risks / open questions
