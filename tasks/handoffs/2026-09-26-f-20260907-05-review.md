### Failure Paths and Error Handling Analysis

1. **Database Row Query Failures (Fail-Closed):**
   - Under bounded batch assembly, any `QueryResult::Err` yielded by `load_iter` (e.g. SQLite disk I/O errors or database corruption) propagates as `Err(Error::from(e))` to `get_players_game_info_blocking` ([line 29–31](file:///home/felixb/Projekte/chessfable/tasks/plans/2026-09-26-player-statistics-streaming.md#L29-L31)).
   - The blocking call returns `Err` immediately, dropping in-flight batch data and accumulators.
   - The wrapper [`get_players_game_info`](file:///home/felixb/Projekte/chessfable/src-tauri/src/db/mod.rs#L2082-L2119) maps the error to `ProgressState::Failed` on the progress lease via `complete_preserving_result` and propagates the typed `Error` across IPC to the renderer, where both [`Databases.tsx:204`](file:///home/felixb/Projekte/chessfable/src/components/home/Databases.tsx#L204) and [`PlayerCard.tsx:38`](file:///home/felixb/Projekte/chessfable/src/components/databases/PlayerCard.tsx#L38) render localized error states (`Home.Databases.ErrorLoading`). No partial statistics are returned as success ([`d-20260905-21`](file:///home/felixb/Projekte/chessfable/tasks/decisions.md#L2074-L2081)).

2. **Cancellation and Connection Health:**
   - Pre-stream cancellation is checked before connection acquisition and query dispatch via `cancellation_check(cancellation)?`.
   - Real SQLite query execution runs under `sqlite_cancellation::with_sqlite_cancellation`. Interruption aborts the VM query with `SQLITE_INTERRUPT` and maps to `Error::Cancellation`. Because `COUNT(*)` and the streaming `SELECT` run sequentially without an enclosing transaction ([lines 85–88](file:///home/felixb/Projekte/chessfable/tasks/plans/2026-09-26-player-statistics-streaming.md#L85-L88)), no `ROLLBACK` is executed that could fail and poison the connection pool state.
   - Batch iteration checks cancellation between batches ([line 32](file:///home/felixb/Projekte/chessfable/tasks/plans/2026-09-26-player-statistics-streaming.md#L32)). Rayon worker evaluation preserves per-row `cancellation.is_cancelled() -> Err(Error::Cancellation)` checks.
   - Any cancellation returns `Err(Error::Cancellation)`, completing the progress lease as `ProgressState::Cancelled` and returning an error Result without publication.

3. **Data Eligibility and Corrupt Move Streams:**
   - In accordance with [`d-20260907-05`](file:///home/felixb/Projekte/chessfable/tasks/decisions.md#L2287-L2294), required values (metadata, date, outcome, rating) and valid mainline move byte decoding are enforced per row.
   - Corrupt move streams fail open per row (excluding only the invalid game from statistics), whereas cancellation errors inside move validation fail closed and propagate `Error::Cancellation`.

4. **Numeric and Arithmetic Boundaries:**
   - Game counts use `u32` and accumulating counts use saturating arithmetic (`saturating_add`), eliminating integer wrap-around or debug panics on large corpora.
   - Emitted progress percentages are clamped to `0.0..=100.0`, protecting against division edge cases (`total == 0` is never divided by) and numerator skew caused by concurrent insertions between `COUNT(*)` and the streaming `SELECT`.

No unhandled failure paths, swallowed exceptions, or regressions in error surfacing were identified in candidate revision r3.
