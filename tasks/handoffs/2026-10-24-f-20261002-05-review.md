## Approach

### The config directory is created by admission

On a successful first launch, `admit_instance` creates each missing per-user root, including `app_config_dir`, before credentials, before `PathAuthority::open_for_app`, and before the window. Unix creation mode is `0o700`. Windows creation is `FILE_CREATE` on the directory child. `d-20261008-01` is why this directory is in that list. The mode is the mode `acquire_canonical` already uses for any missing root. This plan does not choose a different mode.

### The registry save still requires the parent

`atomic_replace` does not create its parent on Unix or Windows. Putting parent creation there would change a shared primitive, including the bindings export, and would hide a missing locked root. The missing-file versus unreadable-file split in `open` stays: missing file, empty maps; existing file, `File::open`. Admission makes the first-run parent exist, so the missing-file branch is a missing file in an existing directory.

### Commands cannot be the first writer

The window is built last, and `create` is false, so `get_engine_workspace` cannot run before admission. The engines directory it creates is under `app_data_dir`.

### Other first writes under the config directory

The only in-repo production uses of `app_config_dir()` are the admission and the registry path. The window-state plugin also uses that directory. Its setup only reads, and its write is on exit, after admission, and that write creates the directory itself if needed. It is not a first-run failure path. The log sink configured in this repository is not `app_config_dir`.
