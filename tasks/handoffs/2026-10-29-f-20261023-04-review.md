### O1 — One budget for admitted Rust work

Treat the gate's usable memory as one shared resource. Admit at most one complete Rust lane at a time in declared lane order. After Rust finishes, preserve the existing frontend coverage, e2e and mutation budget rules, adjusted only to the actual set of concurrently active lanes. Frontend-only, bindings-only and contract-only routes retain their existing work and applicable ordering.

Within an admitted Rust lane, use the existing workerCount primitive to set Cargo's build-job allowance from the usable budget and available CPUs, with a source-adjacent measured cold compiler envelope and its fixed overhead. ## Approach

### O1 — One budget for admitted Rust work

Treat the gate's usable memory as one shared resource. Admit at most one complete Rust lane at a time in declared lane order. The named resource is the unpartitioned memory needed by cold native, cross-target and instrumented compiler/linker contexts. Keep contract and bundle work concurrent. While a Rust lane owns that resource, defer frontend coverage and mutation rather than assigning them a fictitious free half of the same memory. After Rust finishes, preserve the existing frontend coverage, e2e and mutation budget rules, adjusted only to the actual set of concurrently active lanes. Frontend-only, bindings-only and contract-only routes retain their existing work and applicable ordering.

Use the existing workerCount primitive to set Cargo's build-job allowance from the usable budget and available CPUs, with a source-adjacent measured cold compiler envelope and its fixed overhead. Apply the allocation before every scheduler-owned Rust compilation entry, including the P1 bindings exporter as well as each admitted P2 Rust lane. Measure the bindings exporter's native binary compilation, native all-target compilation, Windows GNU clippy and pinned nightly branch coverage before choosing those constants. Use a conservative envelope covering the largest observed context with explicit headroom, and retain a documented conservative one-job fallback for unavailable cgroup detection. A budget below the minimum required for one job refuses the affected work with an actionable nonzero error. Never force one worker into an insufficient known budget. Cargo build jobs govern compilation only, leaving libtest concurrency and all test selection unchanged. Bindings-only runs therefore also detect and apply the Rust allocation, while contract-only runs acquire no unnecessary compiler allocation.

Apply the same allocation and exclusion contract to the scheduler's pre-review Windows compilation and concurrent mutation lane. Share the Rust sizing implementation between push and pre-review. Do not introduce a second domain implementation, general resource scheduler, user setting or policy switch. Standalone receipt commands and hosted direct Cargo jobs keep their entry points and proof contracts, and scheduler-supplied resource environment reaches every nested Cargo invocation. A lower valid inherited Cargo build-job limit remains respected, and inherited configuration cannot raise the scheduler's computed bound.

### O2 — Completion, failure and proof ownership

Resource admission orders work, it does not make success a dependency. An ordinary failed Rust lane releases admission after terminal completion so later selected lanes still run. Existing prerequisite failures continue to skip only their consumers. Preserve table-order failure precedence, per-lane log/result identities and receipt contracts. Interruption prevents all queued starts, supervises already started children and remains nonzero. Cleanup failure never releases permission to start new compilation beside an unconfirmed surviving child.

Keep P0 mutation guard, setup and P1 frontend build/bindings before their existing consumers. E2e must still wait for bundle and every selected Rust lane, including failures. No dist writer overlaps a Rust consumer. Cache hits are allowed in ordinary use, but admission applies before a receipt miss can launch its compiler. A missing receipt cannot escape the resource contract. Receipt schema, command, tree/toolchain/platform checks, TTL and unchanged-tree refusal stay unchanged.
