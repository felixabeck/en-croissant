# Plan: one missing-entry predicate for every caller above the OS layer (f-20260916-09)

Plan path: `tasks/plans/2026-10-04-missing-entry-predicate.md`

## Goal

Every place in the Rust backend that decides "this filesystem entry does not exist" from an
error value (`crate::error::Error` or `std::io::Error`) does so through one predicate with one
documented meaning on every platform. The raw-number Windows predicates, the `ErrorKind`-based
resolver predicate and the inline `kind() == NotFound` copies stop disagreeing, because only one
of them is left.

## Approach

### O1 — One missing-entry predicate and its meaning

MANDATE: "so that every caller above it tests one predicate"; "which of the two predicates
survives"; "whether `Error::Io` keeps carrying a platform-specific number".

* `src-tauri/src/error.rs` owns exactly one predicate, exposed in two forms: a method on
  `crate::error::Error` (true only for `Error::Io(e)` where the io form is true) and a free function
  over `&std::io::Error` for the call sites that hold a bare std error. Working names:
  `Error::is_missing_entry` and `is_missing_entry_io`.
* **Meaning: the OS reported that the named entry does not exist.**
  * When the error carries a raw OS code, the predicate is true exactly for the platform's
    absence codes: unix `ENOENT`; Windows `ERROR_FILE_NOT_FOUND` and `ERROR_PATH_NOT_FOUND`
    (from `windows-sys`, named, never bare literals).
  * When the error carries no raw OS code (an `io::Error` constructed in-process with
    `ErrorKind::NotFound`, as `file_workspace.rs` and macOS `ensure_directory_not_removed` do),
    the predicate is `kind() == ErrorKind::NotFound`.
  * Every other error, and every non-`Io` `Error` variant, is false.
* Consequence on unix: identical to today's `kind() == NotFound` (P1), except that raw 3 (`ESRCH`)
  stops being absence in `classify_probe_error_kind` (P5).
  Consequence on Windows: raw 15/53/67 are no longer absence anywhere (P4, P5, P7, P8 sites);
  raw 2/3 remain absence everywhere.
* `Error::Io` keeps carrying the original `std::io::Error`, raw OS code included. The NT layer
  (`windows_open_status_error`) is not changed: it already emits raw 2/3 for the three not-found
  statuses (P2), and the predicate is the only place in the crate that interprets an absence code.
* A doc comment on the predicate states the meaning, why it is narrower than
  `ErrorKind::NotFound` on Windows (P1), and that the producer-layer tests of P9 use the same sets.

### O2 — The raw-number and kind-based predicates are replaced, not kept beside it

MANDATE: "which of the two predicates survives"; "every caller above it tests one predicate".

* Windows `missing` and `missing_leaf` in `infra/fs.rs` are deleted; their four callers

* `is_missing_leaf_error` in `resolved.rs` is deleted; `resolve_windows` calls the O1 predicate in

* `classify_probe_error_kind` decides `ProbeErrorClass::NotFound` through the O1 predicate only; its
  other arms (unix LOOP/NOTDIR, Windows 1920/4393/267/1224, `InvalidData`, the typed messages) are

* `conflict_if_replaced` tests absence through the O1 predicate in both arms and keeps its other

### Decided autonomously

* **D1 — What does "missing entry" mean?** Chosen: the exact OS absence codes (unix `ENOENT`;

  or share reads as "absent": optional reads (`read_leaf_bytes`, `open_private_registry`,

  rename report success, and the probe classifier swallows a network failure as "no index" —
  contrary to `d-20261002-08` ("other I/O errors propagate") and to unix, where an unreachable
  network filesystem reports `EIO`/`ESTALE`/`ETIMEDOUT`, not `ENOENT`. (b) Normalising the NT layer
  to synthetic `ErrorKind::NotFound` errors — drops the OS code from diagnostics, and does not
  constrain the other producers (`last_os_error`, std path APIs) whose 15/53/67 would still be
  `NotFound` by kind. Reason: absence must mean the OS said the entry does not exist; the narrow set
  is also exactly what the producer layer (P9) already uses.
* **D2 — Where does the predicate live?** Chosen: `src-tauri/src/error.rs`, beside `category` and
  `root_failure_reason`, which consume it. Rejected: `infra/path_authority` or `infra/fs.rs` —
  callers outside `infra` (credentials, practice, sound, puzzle, db) would import a path-authority
  internal for an error question.
* **D3 — Does `Error::Io` keep the platform number across the path-authority boundary?** Chosen:
  yes, unchanged; only the predicate interprets absence codes. Rejected: stripping it (see D1 (b)).
* **D4 — Do `category` / `root_failure_reason` follow the predicate?** Chosen: yes (O3), so one
  error cannot be "missing" for the renderer's category and "present" for control flow. Rejected:
  leaving them on `ErrorKind::NotFound`, which would re-create the divergence the MANDATE names.
  Effect is Windows-only and limited to raw 15/53/67.
* **D5 — Are producer-layer absence tests (P9) routed too?** Chosen: no; they compare native
  `Errno` / `u32` values before an `Error` exists and already use the O1 sets. Rejected: converting
  each to an `io::Error` only to call the predicate.

Frozen in round 1.

* **Inputs are accidental, not adversarial.** The errors in question are produced by the OS for

## Approach

### O1 — One missing-entry predicate and its meaning

MANDATE: "so that every caller above it tests one predicate"; "which of the two predicates
survives"; "whether `Error::Io` keeps carrying a platform-specific number".

* `src-tauri/src/error.rs` owns exactly one predicate, exposed in two forms: a method on
  `crate::error::Error` (true only for `Error::Io(e)` where the io form is true) and a free function
  over `&std::io::Error` for the call sites that hold a bare std error. Working names:
  `Error::is_missing_entry` and `is_missing_entry_io`.
* **Meaning: the OS reported that the named entry does not exist.**
  * When the error carries a raw OS code, the predicate is true exactly for the platform's
    absence codes: unix `ENOENT`; Windows `ERROR_FILE_NOT_FOUND` and `ERROR_PATH_NOT_FOUND`
    (from `windows-sys`, named, never bare literals).
  * When the error carries no raw OS code (an `io::Error` constructed in-process with
    `ErrorKind::NotFound`, as `file_workspace.rs` and macOS `ensure_directory_not_removed` do),
    the predicate is `kind() == ErrorKind::NotFound`.
  * Every other error, and every non-`Io` `Error` variant, is false.
* Consequence on unix: identical to today's `kind() == NotFound` (P1), except that raw 3 (`ESRCH`)
  stops being absence in `classify_probe_error_kind` (P5).
  Consequence on Windows: raw 15/53/67 are no longer absence anywhere (P4, P5, P7, P8 sites);
  raw 2/3 remain absence everywhere.
* `Error::Io` keeps carrying the original `std::io::Error`, raw OS code included. The NT layer
  (`windows_open_status_error`) is not changed: it already emits raw 2/3 for the three not-found
  statuses (P2), and the predicate is the only place in the crate that interprets an absence code.
* A doc comment on the predicate states the meaning, why it is narrower than
  `ErrorKind::NotFound` on Windows (P1), and that the producer-layer tests of P9 use the same sets.

### O2 — The raw-number and kind-based predicates are replaced, not kept beside it

MANDATE: "which of the two predicates survives"; "every caller above it tests one predicate".

* Windows `missing` and `missing_leaf` in `infra/fs.rs` are deleted; their four callers
  (`target_stat`, `rename_optional_regular_at`, `directory_entry_at`, `remove_optional_regular_at`)
  call the O1 predicate with unchanged match semantics (`Ok(None)` / `Ok(false)` / `Ok(None)` /
  `Ok(())`). The stale `RtlNtStatusToDosError` comment goes with `missing_leaf`.
* `is_missing_leaf_error` in `resolved.rs` is deleted; `resolve_windows` calls the O1 predicate in
  the same guard (final component, `allows_missing_leaf(operation)`).
* `classify_probe_error_kind` decides `ProbeErrorClass::NotFound` through the O1 predicate only; its
  other arms (unix LOOP/NOTDIR, Windows 1920/4393/267/1224, `InvalidData`, the typed messages) are
  unchanged. Its doc comment stops claiming that the NotFound decision is platform-number based.
* `conflict_if_replaced` tests absence through the O1 predicate in both arms and keeps its other
  members (unix `LOOP`, `NOTDIR`; Windows `ERROR_DIRECTORY`; the reparse-refusal message). The
  resulting set equals `d-20261003-05`'s chosen set exactly (P6), so that decision is unchanged.

### O3 — Every remaining caller routes through it

MANDATE: "every caller above it tests one predicate".

* The 19 inline production sites of P7 and the two classifications of P8 (`root_failure_reason`,
  `category`) use the O1 predicate (method form on `Error`, free form on bare `std::io::Error`) with
  their existing match semantics and arm order unchanged. After this, no production code above the
  producer layer tests absence by `ErrorKind::NotFound`, by raw 2/3, or by `ENOENT` on an
  `Error`/`io::Error` value.
* P8 effect, stated once: on Windows, an `Io` error with raw 15/53/67 is categorised by its other
  arms (generic I/O) instead of `MissingResource`, and root labelling no longer calls it `Missing`.
  `PermissionDenied` and every other arm are unchanged.
* **Sanitising wrappers preserve the classification** (P12). Every site that replaces an
  `io::Error`'s text by rebuilding it from the source's kind goes through one helper in
  `src-tauri/src/error.rs` whose result satisfies the O1 predicate exactly when the source did, and
  otherwise keeps the source's kind except that a raw-coded `NotFound` that is not an absence
  (Windows 15/53/67) is rebuilt with a kind that `category` and `root_failure_reason` treat as
  generic I/O. `PermissionDenied` and every other kind are kept, so the wrappers' existing
  MissingResource/Permission categories hold for real absence and permission failures. The
  sanitised text stays as it is (no native path reaches the renderer), and the wrappers' own doc
  comments name the helper's rule.
* Out of scope (P9): rustix `Errno::NOENT` comparisons and the SQLite VFS hooks, which operate on
  native error values before any `Error`/`io::Error` exists and already use exactly the O1 sets.

### Decided autonomously

  contrary to `d-20261002-08` ("other I/O errors propagate") and to unix, where an unreachable
  network filesystem reports `EIO`/`ESTALE`/`ETIMEDOUT`, not `ENOENT`. (b) Normalising the NT layer
  to synthetic `ErrorKind::NotFound` errors — drops the OS code from diagnostics, and does not
  constrain the other producers (`last_os_error`, std path APIs) whose 15/53/67 would still be
  `NotFound` by kind. Reason: absence must mean the OS said the entry does not exist; the narrow set
  is also exactly what the producer layer (P9) already uses.
* **D2 — Where does the predicate live?** Chosen: `src-tauri/src/error.rs`, beside `category` and
  `root_failure_reason`, which consume it. Rejected: `infra/path_authority` or `infra/fs.rs` —
  callers outside `infra` (credentials, practice, sound, puzzle, db) would import a path-authority
  internal for an error question.
* **D3 — Does `Error::Io` keep the platform number across the path-authority boundary?** Chosen:
  yes, unchanged; only the predicate interprets absence codes. Rejected: stripping it (see D1 (b)).
* **D4 — Do `category` / `root_failure_reason` follow the predicate?** Chosen: yes (O3), so one
  error cannot be "missing" for the renderer's category and "present" for control flow. Rejected:
  leaving them on `ErrorKind::NotFound`, which would re-create the divergence the MANDATE names.
  Effect is Windows-only and limited to raw 15/53/67.
* **D5 — Are producer-layer absence tests (P9) routed too?** Chosen: no; they compare native

## Approach

### O1 — One missing-entry predicate and its meaning

MANDATE: "so that every caller above it tests one predicate"; "which of the two predicates
survives"; "whether `Error::Io` keeps carrying a platform-specific number".

* `src-tauri/src/error.rs` owns exactly one predicate, exposed in two forms: a method on
  `crate::error::Error` (true only for `Error::Io(e)` where the io form is true) and a free function
  over `&std::io::Error` for the call sites that hold a bare std error. Working names:
  `Error::is_missing_entry` and `is_missing_entry_io`.
* **Meaning: the OS reported that the named entry does not exist.**
  * When the error carries a raw OS code, the predicate is true exactly for the platform's
    absence codes: unix `ENOENT`; Windows `ERROR_FILE_NOT_FOUND` and `ERROR_PATH_NOT_FOUND`
    (from `windows-sys`, named, never bare literals).
  * When the error carries no raw OS code (an `io::Error` constructed in-process with
    `ErrorKind::NotFound`, as `file_workspace.rs` and macOS `ensure_directory_not_removed` do),
    the predicate is `kind() == ErrorKind::NotFound`.
  * Every other error, and every non-`Io` `Error` variant, is false.
* Consequence on unix: identical to today's `kind() == NotFound` (P1), except that raw 3 (`ESRCH`)
  stops being absence in `classify_probe_error_kind` (P5).
  Consequence on Windows: raw 15/53/67 are no longer absence anywhere (P4, P5, P7, P8 sites);
  raw 2/3 remain absence everywhere.
* `Error::Io` keeps carrying the original `std::io::Error`, raw OS code included. The NT layer
  (`windows_open_status_error`) is not changed: it already emits raw 2/3 for the three not-found
  statuses (P2), and the predicate is the only place in the crate that interprets an absence code.
* A doc comment on the predicate states the meaning, why it is narrower than
  `ErrorKind::NotFound` on Windows (P1), and that the producer-layer tests of P9 use the same sets.

### O2 — The raw-number and kind-based predicates are replaced, not kept beside it

MANDATE: "which of the two predicates survives"; "every caller above it tests one predicate".

* Windows `missing` and `missing_leaf` in `infra/fs.rs` are deleted; their four callers
  (`target_stat`, `rename_optional_regular_at`, `directory_entry_at`, `remove_optional_regular_at`)
  call the O1 predicate with unchanged match semantics (`Ok(None)` / `Ok(false)` / `Ok(None)` /
  `Ok(())`). The stale `RtlNtStatusToDosError` comment goes with `missing_leaf`.
* `is_missing_leaf_error` in `resolved.rs` is deleted; `resolve_windows` calls the O1 predicate in
  the same guard (final component, `allows_missing_leaf(operation)`).
* `classify_probe_error_kind` decides `ProbeErrorClass::NotFound` through the O1 predicate only; its
  other arms (unix LOOP/NOTDIR, Windows 1920/4393/267/1224, `InvalidData`, the typed messages) are
  unchanged. Its doc comment stops claiming that the NotFound decision is platform-number based.
* `conflict_if_replaced` tests absence through the O1 predicate in both arms and keeps its other
  members (unix `LOOP`, `NOTDIR`; Windows `ERROR_DIRECTORY`; the reparse-refusal message). The
  resulting set equals `d-20261003-05`'s chosen set exactly (P6), so that decision is unchanged.

### O3 — Every remaining caller routes through it

MANDATE: "every caller above it tests one predicate".

* The 19 inline production sites of P7 and the two classifications of P8 (`root_failure_reason`,
  `category`) use the O1 predicate (method form on `Error`, free form on bare `std::io::Error`) with
  their existing match semantics and arm order unchanged. After this, no production code above the
  producer layer tests absence by `ErrorKind::NotFound`, by raw 2/3, or by `ENOENT` on an

* P8 effect, stated once: on Windows, an `Io` error with raw 15/53/67 is categorised by its other
  arms (generic I/O) instead of `MissingResource`, and root labelling no longer calls it `Missing`.
  `PermissionDenied` and every other arm are unchanged.
* **Sanitising wrappers preserve the classification** (P12). Every site that replaces an
  `io::Error`'s text by rebuilding it from the source's kind goes through one helper in

* Out of scope (P9): rustix `Errno::NOENT` comparisons and the SQLite VFS hooks, which operate on

## Decisions and trade-offs

### Decided autonomously

* **D1 — What does "missing entry" mean?** Chosen: the exact OS absence codes (unix `ENOENT`;
  Windows `ERROR_FILE_NOT_FOUND`, `ERROR_PATH_NOT_FOUND`), and `kind() == NotFound` only for errors
  without a raw code. Rejected: (a) std's `ErrorKind::NotFound` everywhere — by P1 it also accepts
  `ERROR_INVALID_DRIVE`, `ERROR_BAD_NETPATH`, `ERROR_BAD_NET_NAME`, so an unreachable drive, server
  or share reads as "absent": optional reads (`read_leaf_bytes`, `open_private_registry`,
  `read_stamp`) return `None` and their callers proceed as if no state existed, optional removal and
  rename report success, and the probe classifier swallows a network failure as "no index" —
  contrary to `d-20261002-08` ("other I/O errors propagate") and to unix, where an unreachable
  network filesystem reports `EIO`/`ESTALE`/`ETIMEDOUT`, not `ENOENT`. (b) Normalising the NT layer

  constrain the other producers (`last_os_error`, std path APIs) whose 15/53/67 would still be
  `NotFound` by kind. Reason: absence must mean the OS said the entry does not exist; the narrow set
  is also exactly what the producer layer (P9) already uses.
* **D2 — Where does the predicate live?** Chosen: `src-tauri/src/error.rs`, beside `category` and

  callers outside `infra` (credentials, practice, sound, puzzle, db) would import a path-authority
  internal for an error question.
* **D3 — Does `Error::Io` keep the platform number across the path-authority boundary?** Chosen:
  yes, unchanged; only the predicate interprets absence codes. Rejected: stripping it (see D1 (b)).
* **D4 — Do `category` / `root_failure_reason` follow the predicate?** Chosen: yes (O3), so one

## Approach

### O1 — One missing-entry predicate and its meaning

MANDATE: "so that every caller above it tests one predicate"; "which of the two predicates
survives"; "whether `Error::Io` keeps carrying a platform-specific number".

* `src-tauri/src/error.rs` owns exactly one predicate, exposed in two forms: a method on
  `crate::error::Error` (true only for `Error::Io(e)` where the io form is true) and a free function
  over `&std::io::Error` for the call sites that hold a bare std error. Working names:
  `Error::is_missing_entry` and `is_missing_entry_io`.
* **Meaning: the OS reported that the named entry does not exist.**
  * When the error carries a raw OS code, the predicate is true exactly for the platform's
    absence codes: unix `ENOENT`; Windows `ERROR_FILE_NOT_FOUND` and `ERROR_PATH_NOT_FOUND`
    (from `windows-sys`, named, never bare literals).
  * When the error carries no raw OS code (an `io::Error` constructed in-process with
    `ErrorKind::NotFound`, as `file_workspace.rs` and macOS `ensure_directory_not_removed` do),
    the predicate is `kind() == ErrorKind::NotFound`.
  * Every other error, and every non-`Io` `Error` variant, is false.
* Consequence on unix: identical to today's `kind() == NotFound` (P1), except that raw 3 (`ESRCH`)
  stops being absence in `classify_probe_error_kind` (P5).
  Consequence on Windows: raw 15/53/67 are no longer absence anywhere (P4, P5, P7, P8 sites);
  raw 2/3 remain absence everywhere.
* `Error::Io` keeps carrying the original `std::io::Error`, raw OS code included. The NT layer
  (`windows_open_status_error`) is not changed: it already emits raw 2/3 for the three not-found
  statuses (P2), and the predicate is the only place in the crate that interprets an absence code.
* A doc comment on the predicate states the meaning, why it is narrower than
  `ErrorKind::NotFound` on Windows (P1), and that the producer-layer tests of P9 use the same sets.

### O2 — The raw-number and kind-based predicates are replaced, not kept beside it

MANDATE: "which of the two predicates survives"; "every caller above it tests one predicate".

* Windows `missing` and `missing_leaf` in `infra/fs.rs` are deleted; their four callers
  (`target_stat`, `rename_optional_regular_at`, `directory_entry_at`, `remove_optional_regular_at`)
  call the O1 predicate with unchanged match semantics (`Ok(None)` / `Ok(false)` / `Ok(None)` /
  `Ok(())`). The stale `RtlNtStatusToDosError` comment goes with `missing_leaf`.
* `is_missing_leaf_error` in `resolved.rs` is deleted; `resolve_windows` calls the O1 predicate in
  the same guard (final component, `allows_missing_leaf(operation)`).
* `classify_probe_error_kind` decides `ProbeErrorClass::NotFound` through the O1 predicate only; its
  other arms (unix LOOP/NOTDIR, Windows 1920/4393/267/1224, `InvalidData`, the typed messages) are
  unchanged. Its doc comment stops claiming that the NotFound decision is platform-number based.
* `conflict_if_replaced` tests absence through the O1 predicate in both arms and keeps its other
  members (unix `LOOP`, `NOTDIR`; Windows `ERROR_DIRECTORY`; the reparse-refusal message). The
  resulting set equals `d-20261003-05`'s chosen set exactly (P6), so that decision is unchanged.

### O3 — Every remaining caller routes through it

MANDATE: "every caller above it tests one predicate".

* The 19 inline production sites of P7 and the two classifications of P8 (`root_failure_reason`,
  `category`) use the O1 predicate (method form on `Error`, free form on bare `std::io::Error`) with
  their existing match semantics and arm order unchanged. After this, no production code above the
  producer layer tests absence by `ErrorKind::NotFound`, by raw 2/3, or by `ENOENT` on an
  `Error`/`io::Error` value.
* P8 effect, stated once: on Windows, an `Io` error with raw 15/53/67 is categorised by its other
  arms (generic I/O) instead of `MissingResource`, and root labelling no longer calls it `Missing`.
  `PermissionDenied` and every other arm are unchanged.
* **Sanitising wrappers preserve the classification** (P12). Every site that replaces an
  `io::Error`'s text by rebuilding it from the source's kind goes through one helper in
  `src-tauri/src/error.rs` whose result satisfies the O1 predicate exactly when the source did, and
  otherwise keeps the source's kind except that a raw-coded `NotFound` that is not an absence
  (Windows 15/53/67) is rebuilt with a kind that `category` and `root_failure_reason` treat as
  generic I/O. `PermissionDenied` and every other kind are kept, so the wrappers' existing
  MissingResource/Permission categories hold for real absence and permission failures. The
  sanitised text stays as it is (no native path reaches the renderer), and the wrappers' own doc
  comments name the helper's rule.

## Decisions and trade-offs

### Decided autonomously

* **D1 — What does "missing entry" mean?** Chosen: the exact OS absence codes (unix `ENOENT`;
  Windows `ERROR_FILE_NOT_FOUND`, `ERROR_PATH_NOT_FOUND`), and `kind() == NotFound` only for errors
  without a raw code. Rejected: (a) std's `ErrorKind::NotFound` everywhere — by P1 it also accepts
  `ERROR_INVALID_DRIVE`, `ERROR_BAD_NETPATH`, `ERROR_BAD_NET_NAME`, so an unreachable drive, server
  or share reads as "absent": optional reads (`read_leaf_bytes`, `open_private_registry`,
  `read_stamp`) return `None` and their callers proceed as if no state existed, optional removal and
  rename report success, and the probe classifier swallows a network failure as "no index" —
  contrary to `d-20261002-08` ("other I/O errors propagate") and to unix, where an unreachable
  network filesystem reports `EIO`/`ESTALE`/`ETIMEDOUT`, not `ENOENT`. (b) Normalising the NT layer
  to synthetic `ErrorKind::NotFound` errors — drops the OS code from diagnostics, and does not
  constrain the other producers (`last_os_error`, std path APIs) whose 15/53/67 would still be
  `NotFound` by kind. Reason: absence must mean the OS said the entry does not exist; the narrow set
  is also exactly what the producer layer (P9) already uses.
* **D2 — Where does the predicate live?** Chosen: `src-tauri/src/error.rs`, beside `category` and
  `root_failure_reason`, which consume it. Rejected: `infra/path_authority` or `infra/fs.rs` —
  callers outside `infra` (credentials, practice, sound, puzzle, db) would import a path-authority
  internal for an error question.
* **D3 — Does `Error::Io` keep the platform number across the path-authority boundary?** Chosen:
  yes, unchanged; only the predicate interprets absence codes. Rejected: stripping it (see D1 (b)).
* **D4 — Do `category` / `root_failure_reason` follow the predicate?** Chosen: yes (O3), so one
  error cannot be "missing" for the renderer's category and "present" for control flow. Rejected:
  leaving them on `ErrorKind::NotFound`, which would re-create the divergence the MANDATE names.
  Effect is Windows-only and limited to raw 15/53/67.
* **D5 — Are producer-layer absence tests (P9) routed too?** Chosen: no; they compare native
  `Errno` / `u32` values before an `Error` exists and already use the O1 sets. Rejected: converting
  each to an `io::Error` only to call the predicate.
