## Approach

### O1. LF checkouts on every platform

Add a repository-root `.gitattributes` with `* text=auto eol=lf`. A Windows checkout of any text file is
byte-identical to the Linux one. No tracked file's content changes.

### O2. Portable fixture for the leaf-validation tests

`assert_atomic_entry_point_refuses_an_empty_or_multicomponent_leaf` stops opening a directory: its `parent` is a
regular file created inside the tempdir and opened read-only (valid on every platform, because `single_leaf`
rejects both inputs before `parent` is used), and the helper asserts for both inputs that the error is
`Error::InvalidInput`. The four callers are unchanged.

### O3. Unported tests are named on Windows, not hidden

Each of the 81 tests in `tasks/plans/2026-09-15-f-20260914-07-ignored-tests.tsv` gets
`#[cfg_attr(not(unix), ignore = "unported on this platform: <owner>")]` directly beside its `#[test]` /
`#[tokio::test]` attribute, `<owner>` being that row's finding id. Inert on unix; still compiled on Windows. A
test that still fails on the proof run is classified from its panic before it is touched.

### O4. Every Windows refusal site is exactly pinned by a source assertion that runs everywhere

No runtime Windows refusal test is added (focused review-plan judgment r3: "No runtime Windows test is inherently
required by the mandate; Windows-executed source assertions are valid if they pin the active cfg path,
helper/constant semantics, and all direct statements, with staged failures for those mutations").

* **O4a — effective non-unix path.** Table B is generalised: each row is `(file, signature, form, expected)`, where
  `form` is the row's pinned shape — `Counterpart` (a `#[cfg(not(unix))]` attribute directly precedes the signature,
  e.g. `create_dir_at`) or `Block` (the body contains a `#[cfg(not(unix))]` block, e.g. `atomic_replace_with_precommit`
  `infra/fs.rs:1508-1526`, `atomic_install_dir` `:2038-2049`, `create_database_child`
  `path_authority/mod.rs:4936-4947`) — and the row fails when the site's actual shape is not that form, so removing a `#[cfg(not(unix))]` attribute and its braces
  (even while making the unix arm `return`, which leaves the flattened text identical) fails by form mismatch. Every
  one of the 40 sites is `Counterpart` or `Block` today; the only unconditional non-unix tail in the tree is
  `opened_file_change_stamp`, which is the O4d exclusion entry and no row. If implementation finds a site of any other
  shape, it is named in the phase report and gets its own pinned form rather than being forced into these two; and
  `expected` is the site's **effective non-unix body** written out exactly. The effective non-unix body is
  computed on `normalise(source, Literals::Blank)` offsets and compacted from the raw source:
  * if a `#[cfg(not(unix))]` attribute directly precedes the signature (the existing whole-function form), it is
    that function's braced body;
  * otherwise it is the named function's braced body with every statement, item or block that carries
    `#[cfg(unix)]` removed together with that attribute, and every `#[cfg(not(unix))]` block's attribute and
    braces removed so its contents stand in place;
  * the row fails when the named function itself carries any `cfg` attribute other than a directly preceding
    `#[cfg(not(unix))]`, when its body contains any `cfg` attribute other than `#[cfg(unix)]` or
    `#[cfg(not(unix))]`, when it contains a `cfg!(` or `cfg_attr` outside the permitted guard text, or when the
    signature matches more than one function of the applicable form.
  **G rows get the same function-level strictness:** the named function carries no `cfg` attribute, its signature
  matches exactly one function in the file, and the guard statement's raw text — including `cfg!(unix)` — is exact.
  **Enclosing scopes (both G and B rows, and the O4b pins):** no enclosing `impl` block or inline `mod` block of the
  pinned item carries a `cfg` or `cfg_attr` attribute (a B row's own directly preceding `#[cfg(not(unix))]` is the only
  permitted one), and the `mod <file>;` declaration of the row's file in its parent module file, up to `main.rs`,
  carries none either; a violation fails that row with a message naming the scope.
  Statements after a G guard are not pinned: off unix the guard returns before them (`off_unix_refusal(…, false)` is
  `Err`, `?` returns), and the exact `cfg!(unix)` text plus the pinned helper body keep it that way.

  sites become B rows whose `expected` is their current effective body, byte-compacted — for example the unconditional
  `single_leaf(leaf)?;` before the fd-relative refusal is part of that row's `expected`. No production code changes
  unless a site's current shape cannot be expressed this way; then its non-unix path is rewritten into the
  whole-function form with a byte-identical message (the slice-1 counterpart rule, `d-20260914-05`).

## Decisions and trade-offs

* **Whole suite + `cfg_attr(not(unix), ignore = …)`, not `#[cfg(unix)]` and not a filtered run.** Rejected
  `#[cfg(unix)]`: removes the tests from the Windows build and log. Rejected a filtered or `--skip` run:
  `d-20260914-08` and `check-gate-routing.mjs`. Rejected leaving the job red until the port: a permanently red job is
  ignored; the named ignores plus 454 executing tests plus the O4 pins keep it from checking nothing (`d-20260830-20`).
* **This is `d-20260914-08`'s follow-up (a), not a reversal.**
* **Exact source pins of the effective non-unix path, not runtime Windows tests.** A runtime test cannot observe an
  arbitrary pathname operation (r2/r3 R2-07, R3-04); an exact pin of every statement on the path excludes all of
  them, extends `d-20260914-05`'s existing proof to the 11 unpinned sites, and executes on Windows through the new
  job. Settled by the focused review-plan judgment in r3 with the conditions O4a-O4c implement. Rejected: runtime
  tests for 9 reachable sites (arbitrary-path and overwrite effects unobservable; staged effect undefined for
  read-only sites); runtime tests for all 41; label-only coverage.
* **CRLF fixed at the checkout**, not per test.
* **The `"*"` branch-filter gap is filed, not fixed here** (R4-03): it affects every job, and pinning a new trigger
  policy is not required by this mandate.
* **The D-class `resolve_windows` defect is annotated onto `f-20260914-10`, not fixed here.**
* **The ignore set is not pinned by a committed source scan** (R1-10); the owner mapping is verified by the phase proof.
