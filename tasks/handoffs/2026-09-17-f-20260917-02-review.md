## What a successor should know

* There is no Windows runtime on this machine — only a `x86_64-pc-windows-gnu` cross-compiler,
  installed per `d-20260916-07`. It catches type errors and the `const` alignment assertions and
  nothing else. The runner is the only oracle, and the two-step fail-closed read in `d-20260917-10`
  is how a round is accepted.
* Every `infra::fs::tests::` test sorting after `fresh_…` had never executed on any platform before
  this run, because the access violation killed the harness there. Three real defects were hiding
  behind it. If another platform job crashes, assume the reported failure list is a truncation
  artefact until proven otherwise.
* Two assertions in this area used to discard what they saw. They now print it. Any new assertion
  on a platform-specific path should do the same — a bare `assert!(matches!(…))` costs a full CI
  round every time it fires.
