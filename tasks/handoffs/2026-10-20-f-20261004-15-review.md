## Approach

### O1 — collection identity and platform boundary
Add a narrowly scoped native collection service for linked PGNs. Keep standalone database ownership and the composed Library controllers. A versioned, bounded native registry in app data records collection UUID, authorized workspace root, native-only relative source locator, current authority binding, purpose, optional provider/account identity, migration state and derived-cache identity. Do not store raw paths or credential material in renderer state. Each cache is app-owned and keyed by collection UUID, outside the standalone database directory. The registry is the link authority, not the cache or filename. Validate records at load, refuse unsupported/corrupt records without overwriting them, and surface a recoverable unavailable state. Persist using existing identified atomic-file and durability primitives. Reconcile interrupted registration by verifying the source and rebuilding disposable cache state, never inventing an empty PGN.

Automatically index files explicitly categorized as game or tournament in the authorized library workspace. Repertoire, puzzle and other files remain plain. Do not infer purpose from titles or parse content to silently reclassify existing files. Changing purpose activates or retires only the derived index, never changes the PGN bytes. App moves/renames retain UUID and update the source locator, with uncertain outcomes reconciled from native state. External replacement at the recorded locator is acquired through a fresh verified workspace listing, with a new binding and source generation. Never retarget an already-open dirty tab by pathname. An external move/rename that cannot be proven by a unique retained object identity leaves the collection unavailable until explicit source re-selection. Deleted sources remain unavailable, without silently presenting the old index as current. No inode reuse, basename or digest-only relinking across ambiguous candidates. Root changes cannot move a collection into a different workspace by spelling.

Linux and macOS enable linking. Windows preserves existing standalone import, editing and account flows, and creates no automatic linked collection or migration. Keep d-20260918-13 command-entry refusals. Centralize the support predicate in the native service and expose only typed supported/unavailable results required by real consumers. This finding does not port PGN atomic replacement.

Proof level: native persistence/restart and authority tests must show stable UUID across app rename, fresh generation after external replace, missing/ambiguous source refusal, corrupt-record preservation, and no link activation on Windows. Revert the relevant production identity or platform guard while retaining the tests and observe the expected failure.

### O2 — current and consistent derived indexes
Use full streaming rebuilds after a source generation changes. Reuse the PGN scanner and importer/encoding primitives, without importing through the account timestamp cutoff. Link each indexed row to its original source ordinal and exact game-byte stamp in that source generation. Preserve ordinal gaps for skipped malformed games and preserve identical duplicates as distinct source occurrences. The PGN remains lossless truth even when a game is not indexable. Report omissions rather than silently claiming a complete index. Do not change mainline-only position/statistics semantics.

Build rows, locators, source fingerprint and DataRevision together under the existing cancellable database write lock and a single SQLite transaction. Recheck the bound source snapshot before committing. A changed source discards the build and uses the existing three-attempt stale-read bound. A failed/canceled build rolls back and leaves the cache stale, not ready. Do not replace a live WAL database as a plain file. Search-index and result-cache provenance includes collection generation as well as database revision. A query and its later normalization must observe one generation. Before returning, verify it is still the generation admitted for that request. Stale results are discarded and refreshed or return a typed stale result, never paired with newly reordered rows.

Automatic currency checks run at app startup/library entry, window focus, after every app PGN mutation, and before any linked query or statistics consumer. Extend the existing shared two-second freshness schedule to collections actively displayed or searched, rather than adding an independent timer per component. Poll only the authority-bound identity/revision metadata, including ctime, with one outstanding check per collection. Stream a digest while rebuilding. A changed identity/revision triggers rebuilding. Inactive collections refresh at the next startup, library entry or actual use. No index that failed the admitted source check is served as current. Bound jobs through the existing native operation capacity, deduplicate rebuilds by collection/generation, release transient entries on all terminal paths, retain only the current cache generation and clean owned abandoned artifacts on startup. Disk-full cleanup errors remain surfaced and retryable without deleting the source.

Proof level: real native PGN→SQLite→position/game/statistics consumers must distinguish old and new games after external same-size/mtime-preserving rewrite, app save, append and deletion. Race rebuild/search/normalization and source rewrite, plus cancellation, restart and index-write failure. Assert no mixed generation, no partial publication, correct duplicate ordinals and bounded streaming on a 300 MB fixture. Source-only faults removing source revalidation, transaction rollback or generation validation must make corresponding assertions fail.
