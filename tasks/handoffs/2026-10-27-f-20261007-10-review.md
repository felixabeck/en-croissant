## Approach

### Return failures from convertToNormalized

`convertToNormalized` returns `Promise<{ games: NormalizedGame[]; failures: SequentialFailure<PositionGames>[] }>` (the failure item type is the element type it already accepts). `games` is today's `values`. `failures` is the collector's `failures`, including an empty array when every game succeeded. Do not pass `describe`. Do not change the collector. Survivor `id` stays the original index. Cancellation still rejects the whole call: no log and no partial publication. The two abort tests keep that behavior.

### Publish gameFailures from the online fetcher

`fetchOnlineOpening` sets `games` from `normalized.games` and `gameFailures` from `normalized.failures`, including `[]` when nothing failed. Both `lch_all` and `lch_master` get that field because they share this function. The local branch does not set `gameFailures`. The field is therefore optional on the fetch result. Missing and empty mean the same thing to the panel: no notice. Opening rows stay the mapped explorer moves. The `topGames || recentGames` selection stays as it is.

### Games-tab notice

Only the Games tab renders the notice, as a yellow `Alert` and only when `gameFailures` is non-empty. An in-flight or absent result is not a failure list. The notice is a child of that tab's panel, so the existing auth, error, and missing-reference replacements still replace it. Stats and Options do not render it.

Partial list (`games` non-empty and `gameFailures` non-empty): the notice is above `GamesTable`. The table still lists the games that loaded. Copy key `Board.Database.GamesIncomplete`, English "Could not load these games: {{games}}".

Every returned game failed (`games` empty and `gameFailures` non-empty): do not render `GamesTable`, so the hardcoded "No games found" is absent. Copy key `Board.Database.GamesFailed`, English "Could not load games: {{games}}".

Explorer returned no games (`games` empty and `gameFailures` empty or missing): today's `GamesTable` and "No games found", with no notice.

Each key is one sentence and includes the joined labels. Use literal `t()` keys and `defaultValue` so extract keeps them. Do not use i18next plural suffixes. Do not render `failure.message` or any other raw diagnostic. `Alert` is already imported in the panel.

### Matches floor

Count explorer games whose PGN failed. Do not subtract them from the opening-move total, and do not add them on top of a larger opening total.

```
const reportedGameCount =
  (openingData?.games.length ?? 0) + (openingData?.gameFailures?.length ?? 0);
const matches = Math.max(grandTotal || 0, reportedGameCount);
```

Local results omit `gameFailures`, so their floor stays the loaded-game count. Use `??` for the two lengths so a real zero is kept. Keep `grandTotal || 0`.

### Labels

For each failure, in collector index order, the label is the non-empty trimmed `white.name` and `black.name` joined with `" - "` when both sides are non-empty. One non-empty side is that side alone. Both empty after trim: the explorer `id`. Join labels with `", "`. No ratings. The names come from the explorer object on the failure item, not from a PGN that failed to parse.

### Translations

Add both keys to all 16 catalogues. en-GB may match en-US. Every other locale needs its own wording and the same `{{games}}` placeholder. Run `pnpm i18n:extract` after the `t()` calls exist, then fill the new strings. If extract rewrites `src/i18next.d.ts` or `src/types/resources.d.ts`, keep those generated edits and do not hand-edit them. Run `pnpm i18n:types` only when extract left those bindings stale. Do not run extract again as part of the proof, and do not run it concurrently with a receipt-backed gate.

## Approach

### Return failures from convertToNormalized

`convertToNormalized` returns `Promise<{ games: NormalizedGame[]; failures: SequentialFailure<PositionGames[number]>[] }>`. `PositionGames` is already the array type, so the failure item is one game, matching the collector and the label's `white.name` / `black.name` reads. `games` is today's `values`. `failures` is the collector's `failures`, including an empty array when every game succeeded. Do not pass `describe`. Do not change the collector. Survivor `id` stays the original index. Cancellation still rejects the whole call: no log and no partial publication. The two abort tests keep that behavior.

### Publish gameFailures from the online fetcher

`fetchOnlineOpening` sets `games` from `normalized.games` and `gameFailures` from `normalized.failures`, including `[]` when nothing failed. Both `lch_all` and `lch_master` get that field because they share this function. The local branch does not set `gameFailures`. The field is therefore optional on the fetch result. Missing and empty mean the same thing to the panel: no notice. Opening rows stay the mapped explorer moves. The `topGames || recentGames` selection stays as it is.

### Games-tab notice

Only the Games tab renders the notice, as a yellow `Alert` and only when `gameFailures` is non-empty. An in-flight or absent result is not a failure list. The notice is a child of that tab's panel, so the existing auth, error, and missing-reference replacements still replace it. Stats and Options do not render it.

Partial list (`games` non-empty and `gameFailures` non-empty): the notice is above `GamesTable`. The table still lists the games that loaded. Copy key `Board.Database.GamesIncomplete`, English "Could not load these games: {{games}}".

Every returned game failed (`games` empty and `gameFailures` non-empty): do not render `GamesTable`, so the hardcoded "No games found" is absent. Copy key `Board.Database.GamesFailed`, English "Could not load games: {{games}}".

Explorer returned no games (`games` empty and `gameFailures` empty or missing): today's `GamesTable` and "No games found", with no notice.

Each key is one sentence and includes the joined labels. Use literal `t()` keys and `defaultValue` so extract keeps them. Do not use i18next plural suffixes. Do not render `failure.message` or any other raw diagnostic. `Alert` is already imported in the panel.

### Matches floor

Count explorer games whose PGN failed. Do not subtract them from the opening-move total, and do not add them on top of a larger opening total.

```
const reportedGameCount =
  (openingData?.games.length ?? 0) + (openingData?.gameFailures?.length ?? 0);
const matches = Math.max(grandTotal || 0, reportedGameCount);
```

Local results omit `gameFailures`, so their floor stays the loaded-game count. Use `??` for the two lengths so a real zero is kept. Keep `grandTotal || 0`.

### Labels

For each failure, in collector index order, the label is the non-empty trimmed `white.name` and `black.name` joined with `" - "` when both sides are non-empty. One non-empty side is that side alone. Both empty after trim: the explorer `id`. Join labels with `", "`. No ratings. The names come from the explorer object on the failure item, not from a PGN that failed to parse.

## Approach

### Return failures from convertToNormalized

`convertToNormalized` returns `Promise<{ games: NormalizedGame[]; failures: SequentialFailure<PositionGames[number]>[] }>`. `PositionGames` is already the array type, so the failure item is one game, matching the collector and the label's `white.name` / `black.name` reads. `games` is today's `values`. `failures` is the collector's `failures`, including an empty array when every game succeeded. Do not pass `describe`. Do not change the collector. Survivor `id` stays the original index. Cancellation still rejects the whole call: no log and no partial publication. The two abort tests keep that behavior.

### Publish gameFailures from the online fetcher

`fetchOnlineOpening` sets `games` from `normalized.games` and `gameFailures` from `normalized.failures`, including `[]` when nothing failed. Both `lch_all` and `lch_master` get that field because they share this function. The local branch does not set `gameFailures`. The field is therefore optional on the fetch result. Missing and empty mean the same thing to the panel: no notice. Opening rows stay the mapped explorer moves. The `topGames || recentGames` selection stays as it is.

### Games-tab notice

Only the Games tab renders the notice, as a yellow `Alert` and only when `gameFailures` is non-empty. An in-flight or absent result is not a failure list. The notice is a child of that tab's panel, so the existing auth, error, and missing-reference replacements still replace it. Stats and Options do not render it.

Partial list (`games` non-empty and `gameFailures` non-empty): the notice is above `GamesTable`. The table still lists the games that loaded. Copy key `Board.Database.GamesIncomplete`, English "Could not load these games: {{games}}".

Every returned game failed (`games` empty and `gameFailures` non-empty): do not render `GamesTable`, so the hardcoded "No games found" is absent. Copy key `Board.Database.GamesFailed`, English "Could not load games: {{games}}".

Explorer returned no games (`games` empty and `gameFailures` empty or missing): today's `GamesTable` and "No games found", with no notice.

Each key is one sentence and includes the joined labels. Use literal `t()` keys and `defaultValue` so extract keeps them. Do not use i18next plural suffixes. Do not render `failure.message` or any other raw diagnostic. `Alert` is already imported in the panel.

### Matches floor

Count explorer games whose PGN failed. Do not subtract them from the opening-move total, and do not add them on top of a larger opening total.

```
const reportedGameCount =
  (openingData?.games.length ?? 0) + (openingData?.gameFailures?.length ?? 0);
const matches = Math.max(grandTotal || 0, reportedGameCount);
```

Local results omit `gameFailures`, so their floor stays the loaded-game count. Use `??` for the two lengths so a real zero is kept. Keep `grandTotal || 0`.

Both empty after trim: the explorer `id`. Join labels with `", "`. No ratings. The names come from the explorer object on the failure item, not from a PGN that failed to parse.

## Approach

### Return failures from convertToNormalized

`convertToNormalized` returns `Promise<{ games: NormalizedGame[]; failures: SequentialFailure<PositionGames[number]>[] }>`. `PositionGames` is already the array type, so the failure item is one game, matching the collector and the label's `white.name` / `black.name` reads. `games` is today's `values`. `failures` is the collector's `failures`, including an empty array when every game succeeded. Do not pass `describe`. Do not change the collector. Survivor `id` stays the original index. Cancellation still rejects the whole call: no log and no partial publication. The two abort tests keep that behavior.

### Publish gameFailures from the online fetcher

`fetchOnlineOpening` sets `games` from `normalized.games` and `gameFailures` from `normalized.failures`, including `[]` when nothing failed. Both `lch_all` and `lch_master` get that field because they share this function. The local branch does not set `gameFailures`. The field is therefore optional on the fetch result. Missing and empty mean the same thing to the panel: no notice. Opening rows stay the mapped explorer moves. The `topGames || recentGames` selection stays as it is.

### Games-tab notice

Only the Games tab renders the notice, as a yellow `Alert` and only when `gameFailures` is non-empty. An in-flight or absent result is not a failure list. The notice is a child of that tab's panel, so the existing auth, error, and missing-reference replacements still replace it. Stats and Options do not render it.

Partial list (`games` non-empty and `gameFailures` non-empty): the notice is above `GamesTable`. The table still lists the games that loaded. Copy key `Board.Database.GamesIncomplete`, English "Could not load these games: {{games}}".

Every returned game failed (`games` empty and `gameFailures` non-empty): do not render `GamesTable`, so the hardcoded "No games found" is absent. Copy key `Board.Database.GamesFailed`, English "Could not load games: {{games}}".

Explorer returned no games (`games` empty and `gameFailures` empty or missing): today's `GamesTable` and "No games found", with no notice.

Each key is one sentence and includes the joined labels. Use literal `t()` keys and `defaultValue` so extract keeps them. Do not use i18next plural suffixes. Do not render `failure.message` or any other raw diagnostic. `Alert` is already imported in the panel.

### Matches floor

Count explorer games whose PGN failed. Do not subtract them from the opening-move total, and do not add them on top of a larger opening total.

```
const reportedGameCount =
  (openingData?.games.length ?? 0) + (openingData?.gameFailures?.length ?? 0);
const matches = Math.max(grandTotal || 0, reportedGameCount);
```

Local results omit `gameFailures`, so their floor stays the loaded-game count. Use `??` for the two lengths so a real zero is kept. Keep `grandTotal || 0`.

### Labels

For each failure, in collector index order, the label is the non-empty trimmed `white.name` and `black.name` joined with `" - "` when both sides are non-empty. One non-empty side is that side alone. Both empty after trim: the explorer `id`. Join labels with `", "`. No ratings. The names come from the explorer object on the failure item, not from a PGN that failed to parse.

### Decided autonomously — Games-tab notice

### Decided autonomously — Matches floor

* **Reason:** Matches is not a games-table count. The opening statistics are the number the header shows whenever moves were returned, and those statistics did not fail. * **Reversal:** Restore the floor to `openingData?.games.length` in `DatabasePanel.tsx`.

* **Reversal:** Stop setting `gameFailures` on the master branch of `fetchOpening`.
