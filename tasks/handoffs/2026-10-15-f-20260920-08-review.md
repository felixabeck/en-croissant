## Approach

### O1 — One bounded persisted owner

Store an optional, explicitly versioned puzzle-session field inside the existing compressed tab-tree state, under the tab's physical tree key. It contains ordered attempts with stable per-attempt identity and selected attempt identity or no selection. Database row IDs and array offsets are not attempt identities. Expose the view's current index as a derivation. Remove the independent Mantine history writer and currentPuzzleFamily production owner.

Use one shared schema/type for puzzle rows and session persistence. Bound count and variable-size fields, reject nonfinite numeric data, and validate legal puzzle sequences before admission. Limit retained history to 100 attempts and 32 KiB of compressed history payload, measured as UTF-16 code units times two. Retain the selected attempt while evicting oldest other attempts until both bounds hold. Refuse an individually oversized incoming attempt with a handled error rather than dropping the current selection. Determine a legacy selected owner before retention. Repeated attempts of the same puzzle stay distinct. The tree retains its existing schema limits and shared-origin quota handling, so these history limits do not promise that every possible combination of 100 open trees will fit.

Readers, writers, queued flushes, clones, ID repair and hydration must preserve this optional field. Ordinary non-puzzle trees remain compatible. A present invalid new-format session makes the combined record unreadable through the existing tree recovery contract, preserving original bytes until successful retry or explicit discard. Absence remains a supported legacy state.

### O2 — Durable session transitions and live ownership

Build a complete immutable candidate from the current live tree and session for admission, history selection, completion, elapsed-time/theme updates and clear/reset. Validate and synchronously save that one compressed record before publishing the candidate into the cached tree store or publishing derived controls/timer changes. Use the existing admitted-state installation boundary rather than a second independent store. A successful save supersedes every older queued write for that physical key. Refusal preserves prior stored bytes, session selection/history and the transition's prior live state, reports through the existing persistence notification route, and permits retry. A failed completion save preserves the already accepted human move and reply, consistent with d-20261014-20, but cannot report saved completion or advance to a successor.

Ordinary moves, notation edits and navigation continue through the existing tree debounce, carrying the same session metadata in every frame. Their existing failed-write retention and unload flush remain intact. Session transitions include the latest live tree, so they cannot save metadata against a stale played tree. No pending old frame may overwrite a newly committed session.

Capture logical tab, physical tree generation, stable attempt and operation ownership for continuations. Refresh an operation's own ownership snapshot after its successful immutable update before awaiting metadata or admitting a successor. Retirement, selection, reset, replacement and unmount invalidate stale work. Timer cleanup cannot write after close or recreate removed storage. Resume an incomplete selected attempt from saved elapsed duration, excluding time while the app is not running. Keep first incorrect result/time stable. Hints, playback, notation and immediate advance retain the legal/path contracts of d-20261014-20 through d-20261014-23.

### O3 — Restore and migrate without guessing or losing a tree

Restore valid new-format history and selected identity with the same saved tree before interactive puzzle consumers mount. A saved selected owner is checked against the restored tree rather than replacing that tree with its opening. A missing, invalid or incompatible selected identity leaves the tree intact and selection unresolved until explicit existing history selection or Clear Session. No default-index-zero admission runs during hydration.

For legacy raw `${logicalTabId}-puzzles` arrays, validate entries independently so one invalid row does not erase valid neighbors. Infer an owner only when the saved tree's root and resolved ordered played path establish exactly one compatible valid attempt. Shared roots/prefixes or duplicate compatible attempts remain unresolved. Absence of an owner or invalid legacy history never authorizes resetting a present valid tree. The unresolved state has no playable selected puzzle, while explicit history selection can restart an attempt and Clear Session can reset it. Brand-new empty sessions remain usable.

Commit a validated bounded combined record before retiring legacy bytes. On read/save refusal retain the source and prior live state for retry. Workspace ID repair must transfer puzzle ownership from the original logical ID alongside the tree clone before publishing replacement metadata, including background puzzle tabs. Migration failure must not publish a repaired ID whose puzzle source becomes unreachable. Duplicating a migrated puzzle tab copies history, selection and its active played tree independently through the same tree clone route.

### O4 — Reclaim through workspace ownership

New sessions need no additional key or cleanup registry because existing physical-tree removal intents reclaim the complete envelope. Apply cleanup to explicit close and every existing reclaimTabLocalState caller after durable metadata removal. Refused workspace close leaves its session, tree and live atoms intact. Existing pending-removal replay keeps retrying failed combined-tree deletion under d-20261008-09.

After successful migration, retire known legacy history keys. At startup and later workspace commits, retry orphan legacy histories only when workspace ownership is authoritative. Match the exact app puzzle suffix and a UUID logical ID, plus specifically proven legacy source IDs from workspace migration. Preserve retained puzzle owners and protected/uncertain repair sources. Never use a broad suffix wipe or delete unrelated session values. Catch removal refusal, retain the key for the next ownership reconciliation, and report the failure. The identifiable legacy key itself is the retry target, so no new durable cleanup queue is required.

## Approach

### O1 — One bounded persisted owner

Store an optional, explicitly versioned puzzle-session field inside the existing compressed tab-tree state, under the tab's physical tree key. It contains ordered attempts with stable per-attempt identity and selected attempt identity or no selection. Database row IDs and array offsets are not attempt identities. Expose the view's current index as a derivation. Remove the independent Mantine history writer and currentPuzzleFamily production owner.

Use one shared schema/type for puzzle rows and session persistence. Bound count and variable-size fields, reject nonfinite numeric data, and validate legal puzzle sequences before admission. Limit retained history to 100 attempts and 32 KiB of compressed history payload, measured as UTF-16 code units times two. Retain the selected attempt while evicting oldest other attempts until both bounds hold. Refuse an individually oversized incoming attempt with a handled error rather than dropping the current selection. Determine a legacy selected owner before retention. Repeated attempts of the same puzzle stay distinct. The tree retains its existing schema limits and shared-origin quota handling, so these history limits do not promise that every possible combination of 100 open trees will fit.

Readers, writers, queued flushes, clones, ID repair and hydration must preserve this optional field. Ordinary non-puzzle trees remain compatible. A present invalid new-format session makes the combined record unreadable through the existing tree recovery contract, preserving original bytes until successful retry or explicit discard. Absence remains a supported legacy state.

### O2 — Durable session transitions and live ownership

Build a complete immutable candidate from the current live tree and session for admission, history selection, completion, elapsed-time/theme updates and clear/reset. Validate and synchronously save that one compressed record before publishing the candidate into the cached tree store or publishing derived controls/timer changes. Use the existing admitted-state installation boundary rather than a second independent store. A successful save supersedes every older queued write for that physical key. Refusal preserves prior stored bytes, session selection/history and the transition's prior live state, reports through the existing persistence notification route, and permits retry. A failed completion save preserves the already accepted human move and reply, consistent with d-20261014-20, but cannot report saved completion or advance to a successor.

Ordinary moves, notation edits and navigation continue through the existing tree debounce, carrying the same session metadata in every frame. Their existing failed-write retention and unload flush remain intact. Session transitions include the latest live tree, so they cannot save metadata against a stale played tree. No pending old frame may overwrite a newly committed session.

Capture logical tab, physical tree generation, stable attempt and operation ownership for continuations. Refresh an operation's own ownership snapshot after its successful immutable update before awaiting metadata or admitting a successor. Retirement, selection, reset, replacement and unmount invalidate stale work. Timer cleanup cannot write after close or recreate removed storage. Resume an incomplete selected attempt from saved elapsed duration, excluding time while the app is not running. Keep first incorrect result/time stable. Hints, playback, notation and immediate advance retain the legal/path contracts of d-20261014-20 through d-20261014-23.

### O3 — Restore and migrate without guessing or losing a tree

Restore valid new-format history and selected identity with the same saved tree before interactive puzzle consumers mount. A saved selected owner is checked against the restored tree rather than replacing that tree with its opening. A missing, invalid or incompatible selected identity leaves the tree intact and selection unresolved until explicit existing history selection or Clear Session. No default-index-zero admission runs during hydration.

For legacy raw `${logicalTabId}-puzzles` arrays, validate entries independently so one invalid row does not erase valid neighbors. Infer an owner only when the saved tree's root and resolved ordered played path establish exactly one compatible valid attempt. Shared roots/prefixes or duplicate compatible attempts remain unresolved. Absence of an owner or invalid legacy history never authorizes resetting a present valid tree. The unresolved state has no playable selected puzzle, while explicit history selection can restart an attempt and Clear Session can reset it. Brand-new empty sessions remain usable.

Commit a validated bounded combined record before retiring legacy bytes. On read/save refusal retain the source and prior live state for retry. Workspace ID repair must transfer puzzle ownership from the original logical ID alongside the tree clone before publishing replacement metadata, including background puzzle tabs. Migration failure must not publish a repaired ID whose puzzle source becomes unreachable. Duplicating a migrated puzzle tab copies history, selection and its active played tree independently through the same tree clone route.

### O4 — Reclaim through workspace ownership

New sessions need no additional key or cleanup registry because existing physical-tree removal intents reclaim the complete envelope. Apply cleanup to explicit close and every existing reclaimTabLocalState caller after durable metadata removal. Refused workspace close leaves its session, tree and live atoms intact. Existing pending-removal replay keeps retrying failed combined-tree deletion under d-20261008-09.

After successful migration, retire known legacy history keys. At startup and later workspace commits, retry orphan legacy histories only when workspace ownership is authoritative. Match the exact app puzzle suffix and a UUID logical ID, plus specifically proven legacy source IDs from workspace migration. Preserve retained puzzle owners and protected/uncertain repair sources. Never use a broad suffix wipe or delete unrelated session values. Catch removal refusal and report the failure.

For proven legacy keys that cannot be rediscovered from the UUID namespace, retain their exact logical history keys in an optional bounded workspace cleanup-intent field. Derive those keys from the original logical tab ID, never its possibly different physical tree key. Publish that authority with replacement/close metadata before retiring a source owner or deleting a source tree. Retain and replay it across fresh documents until the exact history key is confirmed absent, independently of whether its tree still exists. A refused read or removal preserves the intent. Bound it to 100 unique keys and refuse a migration/close whose required evidence would overflow, preserving the prior owner. Reuse the existing workspace save/reconciliation and bounded-intent concepts rather than introducing a separate registry or service. An absent field is compatible with current workspace records. Successful cleanup removes the matching intent on a subsequent successful workspace save, stale already-absent targets are harmless. Ordinary UUID orphan keys remain discoverable without an intent. This legacy-only field and its replay can be removed when legacy history migration is retired and no supported workspace contains such intents.

## Decisions and trade-offs

Decided autonomously for the adopter to record before implementation:

- **Persistence boundary:** embed the session in the existing compressed tree envelope. Rejected coordinating two keys or adding a journal because one-key atomic replacement directly establishes ownership and reuses tree lifetime/removal. Reversal requires an equally coherent proven owner with legacy/refusal/close coverage.
- **Retention:** 100 attempts and 32 KiB compressed history, protecting the selected attempt and refusing an oversized candidate. Rejected count-only retention and dropping the selected attempt. These are technical storage bounds required by the finding, not a promise of unlimited history. Reversal is a schema/budget change with boundary, realistic-size and quota proof, preserving selected progress.
- **Legacy ambiguity:** preserve the played tree with no selected owner when evidence is ambiguous, use existing selection/clear actions to resolve it. Rejected guessing index zero or resetting a valid tree. Reversal requires new ownership evidence and actual consumer proof.
- **Legacy cleanup authority:** retain bounded exact-key cleanup intents inside existing workspace metadata for non-UUID source histories. Rejected relying on an expiring tree-removal intent or treating every suffix-matching key as app-owned. Source tracing proves the old logical owner disappears while removal can fail independently. Reversal requires equivalent cold-reload retry authority, or retirement of the legacy migration and its outstanding intents.
- **Timing and history revisits:** resume saved elapsed duration without application downtime, preserve the existing restart behavior when explicitly selecting another attempt. Rejected persisting wall-clock timer starts or introducing one tree per history row. These follow the existing transient timer and single active-tree behavior. Reversal requires a separate evidenced product requirement.

## Approach

### O1 — One bounded persisted owner

Store an optional, explicitly versioned puzzle-session field inside the existing compressed tab-tree state, under the tab's physical tree key. It contains ordered attempts with stable per-attempt identity and selected attempt identity or no selection. Database row IDs and array offsets are not attempt identities. Expose the view's current index as a derivation. Remove the independent Mantine history writer and currentPuzzleFamily production owner.

Use one shared schema/type for puzzle rows and session persistence. Bound count and variable-size fields, reject nonfinite numeric data, and validate legal puzzle sequences before admission. Limit retained history to 100 attempts and 32 KiB of compressed history payload, measured as UTF-16 code units times two. Retain the selected attempt while evicting oldest other attempts until both bounds hold. Refuse an individually oversized incoming attempt with a handled error rather than dropping the current selection. Determine a legacy selected owner before retention. Repeated attempts of the same puzzle stay distinct. The tree retains its existing schema limits and shared-origin quota handling, so these history limits do not promise that every possible combination of 100 open trees will fit.

Readers, writers, queued flushes, clones, ID repair and hydration must preserve this optional field. Ordinary non-puzzle trees remain compatible. A present invalid new-format session makes the combined record unreadable through the existing tree recovery contract, preserving original bytes until successful retry or explicit discard. Absence remains a supported legacy state.

### O2 — Durable session transitions and live ownership

Build a complete immutable candidate from the current live tree and session for admission, history selection, completion, elapsed-time/theme updates and clear/reset. Validate and synchronously save that one compressed record before publishing the candidate into the cached tree store or publishing derived controls/timer changes. Use the existing admitted-state installation boundary rather than a second independent store. A successful save supersedes every older queued write for that physical key. Refusal preserves prior stored bytes, session selection/history and the transition's prior live state, reports through the existing persistence notification route, and permits retry. A failed completion save preserves the already accepted human move and reply, consistent with d-20261014-20, but cannot report saved completion or advance to a successor.

Ordinary moves, notation edits and navigation continue through the existing tree debounce, carrying the same session metadata in every frame. Their existing failed-write retention and unload flush remain intact. Session transitions include the latest live tree, so they cannot save metadata against a stale played tree. No pending old frame may overwrite a newly committed session.

Capture logical tab, physical tree generation, stable attempt and operation ownership for continuations. Refresh an operation's own ownership snapshot after its successful immutable update before awaiting metadata or admitting a successor. Retirement, selection, reset, replacement and unmount invalidate stale work. Timer cleanup cannot write after close or recreate removed storage. Resume an incomplete selected attempt from saved elapsed duration, excluding time while the app is not running. Keep first incorrect result/time stable. Hints, playback, notation and immediate advance retain the legal/path contracts of d-20261014-20 through d-20261014-23.

### O3 — Restore and migrate without guessing or losing a tree

Restore valid new-format history and selected identity with the same saved tree before interactive puzzle consumers mount. A saved selected owner is checked against the restored tree rather than replacing that tree with its opening. A missing, invalid or incompatible selected identity leaves the tree intact and selection unresolved until explicit existing history selection or Clear Session. No default-index-zero admission runs during hydration.

For legacy raw `${logicalTabId}-puzzles` arrays, validate entries independently so one invalid row does not erase valid neighbors. Infer an owner only when the saved tree's root and resolved ordered played path establish exactly one compatible valid attempt. Shared roots/prefixes or duplicate compatible attempts remain unresolved. Absence of an owner or invalid legacy history never authorizes resetting a present valid tree. The unresolved state has no playable selected puzzle, while explicit history selection can restart an attempt and Clear Session can reset it. Brand-new empty sessions remain usable.

Commit a validated bounded combined record before retiring legacy bytes. On read/save refusal retain the source and prior live state for retry. Workspace ID repair must transfer puzzle ownership from the original logical ID alongside the tree clone before publishing replacement metadata, including background puzzle tabs. Migration failure must not publish a repaired ID whose puzzle source becomes unreachable. Duplicating a migrated puzzle tab copies history, selection and its active played tree independently through the same tree clone route.
