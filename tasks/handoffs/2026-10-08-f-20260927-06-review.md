# Plan: termination preempts an in-flight engine exchange and reports the reap that ended the actor

## Goal

A termination request (`EngineActor::terminate`, `EngineSupervisor::terminate_exact`, and through
them `terminate_all`, `terminate_tab`, retirement and Kill) no longer waits for the one UCI exchange
an engine actor or a warm interactive transition is currently servicing. Shutdown of a silent engine
then costs one teardown (≤ 5.2 s), not an exchange deadline plus a teardown (15.2 s against
`SHUTDOWN_BUDGET` 15 s). Every termination caller reports the outcome of the child reap that
actually ended the actor, so `terminate_all` can no longer report success over an unconfirmed reap.

## Approach

### O1 — Termination preempts every in-flight actor exchange

*Rests on MANDATE:* "Every other exchange the actor loop services — the `isready`/`readyok` wait,
the `stop`/`bestmove` drain, and every command write — ignores it"; "should termination preempt an
in-flight exchange".

* **Behaviour.** Once the actor's existing `interrupt` token is cancelled, every command write and
  every terminal-line or configuration read the runtime performs for a command — `Init` (both
  writes, both reads), `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition`,
  `EnsureReady`, `StartSearch` (its implicit `stop_current`, its resynchronising `ensure_ready` and
  its `go` write), `Stop` and `StopRequest` in the loop and in `service_search_read`'s Stop arms —
  stops waiting at once instead of at its own deadline. An exchange that begins after the token is
  cancelled fails without writing.
* **Error.** The interrupted exchange returns `Error::EngineDisconnected`, the error the existing
  cancellable reads already return (P3), so `cancelled_search_error` keeps mapping it to
  `Cancellation` for a cancelled search (P10).
* **Failure path per handler: unchanged.** `EnsureReady`, `StartSearch`, `Stop`, `StopRequest` and
  the search-read Stop arms keep going through `recover_failed_protocol` (runtime terminated, actor
  exits); `Init`, `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition` keep replying the
  error and the loop then services the queued `Terminate` (biased control channel).
* **Boundary.** One token: the actor's existing `interrupt`. No second cancellation mechanism, and
  the runtime's own termination (`quit` write, force kill, reap, stderr join) keeps its existing
  bounds and is never interrupted. `service_search_read`'s search-output read stays preempted by
  the biased control channel as today. `interrupt` remains cancelled only by termination requests
  (`EngineActor::terminate` and O3).
* **Verification level:** deterministic actor tests (O4, A1).

### O2 — `EngineActor::terminate` reports the reap that ended the actor

*Rests on MANDATE:* "`EngineActor::terminate` returns `Ok` when its control request gets
`EngineDisconnected` and the actor task joined — even if the actor's own `recover_failed_protocol`
termination failed and was only logged — so `terminate_all` can report success for an unconfirmed
reap"; "Resolve it with the preemption/termination outcome design and test the queued-shutdown
case."

* **Behaviour.** The actor records the outcome of the runtime termination that ended it, whichever
  path ran it (`Terminate` command, `recover_failed_protocol`, channel closed), in state every
  `EngineActor` clone can read. `EngineActor::terminate` returns:
  * the `Terminate` reply's result when the actor serviced that request (as today);
  * otherwise — the request got `EngineDisconnected` because the actor already exited or exits
    before servicing it — the recorded outcome of the actor's own final termination, after the task
    is joined; this holds equally for a caller that finds the task already joined by another caller.
  * A task join failure is still reported, combined as today.
* `Ok` therefore means the reap that ended this actor succeeded. A recorded failure reaches every
  later caller losslessly (same `category()`, message, `diagnostic()` and `root_failure()`, as
  `Error::Shared` provides — P10). The command whose exchange failed keeps receiving
  `with_cleanup(primary, termination)`, and the failure is still logged exactly once where it is
  logged today.
* **Verification level:** deterministic actor tests (O4, A2).

### O3 — Exact termination preempts an interactive transition and reports that generation's reap

*Rests on MANDATE:* "a fix here must also cover the exchanges inside
`start_interactive_search`/`WarmEngine::{new,start}`"; "so `terminate_all` can report success for
an unconfirmed reap".

* **Behaviour.** `terminate_exact(key, generation)` cancels the matching published actor's
  `interrupt` before it awaits the per-key lifecycle lease, in the same barrier section where it
  already marks that actor cancelled, and after marking it cancelled — so the lease holder's
  in-flight exchange (O1) fails at once and the transition maps it to `Cancellation` (P10). The
  lease holder then reaps the generation itself (P6).
* **Result.** When, after obtaining the lease, the generation it observed is neither published nor
  pending any more because another owner (the lease holder) completed its reap, `terminate_exact`
  returns that actor's recorded termination outcome (O2) instead of `Ok(())`. It never starts a
  second termination of a still-running actor outside the shared pending-entry task
  (`d-20261006-19`); a generation it never observed keeps today's `Ok(())`.
* `terminate_all`, `terminate_tab` and retirement inherit both through `terminate_exact` (P8);
  `kill_engine` already reaches `EngineActor::terminate` without the lease and needs nothing beyond
  O1/O2.
* **Verification level:** supervisor tests, real-child unix fixture for the warm transition (O4,
  A3).

### O4 — Verification

*Rests on MANDATE:* "Tests must observe the exchange's write or read *before* calling
`terminate()` … and cover the indirect paths (`start_search`'s implicit stop/readiness,
`service_search_read`'s Stop arms, init writes, `ConfigureStart`)"; R9-03; "test the
queued-shutdown case".

* **A1 — preemption per exchange path** (actor level, fake I/O, runs on every platform). One case

  `terminate()`; uses exchange deadlines far longer than the case's bound; asserts that
  `terminate()` returns `Ok` within a bound far below the exchange deadline, that the in-flight
  requester received an error that is not `EngineTimeout`, and that `UciIo::terminate` ran exactly

* **A2 — termination outcome.** (a) Queued shutdown: an actor whose exchange is preempted (and one

  protocol recovery, with no termination requested — a later `terminate()` returns `Err`; with a

* **A3 — warm transition and exact result.** Unix real-child fixture: a warm transition whose

## Decisions and trade-offs

## Decided autonomously

* **D1 — Preempt, do not re-size budgets.** Question: termination preempts an in-flight exchange,
  or the budgets are re-sized so the longest exchange plus teardown fits `SHUTDOWN_BUDGET`?
  Chosen: preempt (O1, O3). Rejected: raising `SHUTDOWN_BUDGET` above 15.2 s (the app then hangs on
  exit for over 15 s with a silent engine, and any later exchange or transition re-breaks the
  arithmetic) and cutting `readyok`/`uciok` below 9.8 s (fails slow but healthy engines, e.g. a
  large-hash initialisation, to save shutdown time). Reason: `async-resource-invariants.md`
  "cancellation before use"; the bound becomes one teardown (≤ 5.2 s) independent of every exchange
  deadline. Reversal path: drop the token from the runtime's writes/reads and size the budget.
* **D2 — Interrupted exchange error is `EngineDisconnected`.** Rejected: a new error variant (a
  renderer-visible category and bindings change with no consumer that distinguishes it). Reason: it
  is what the existing cancellable reads return, and `cancelled_search_error` already maps it.
* **D3 — The actor's own final termination outcome is the answer for every later terminator.**
  Rejected: keeping `EngineDisconnected → Ok` (the defect); routing every registered-actor
  termination through the pending-entry sharing of `d-20261006-19` (that decision explicitly kept
  registered actors out, and registry retention of failed actors is `f-20261001-14`).
* **D4 — Release and stop paths do not preempt.** `release_generation` / `stop_search` keep their
  graceful `stop` before the reap. Rejected: cancelling `interrupt` inside
  `SupervisedEngine::mark_cancelled` (every release would abort its own `stop`, turning a clean
  release into an `EngineDisconnected` failure). Reason: they are not on the shutdown path; exact,
  all, tab, retirement and Kill are.
* **D5 — No deadline or budget constant changes.** The shutdown bound follows from D1.

* A release racing a Kill or shutdown on the same actor can now see its `stop` fail with

  already ended in `EngineDisconnected` once `Terminate` closed the channel. Known limit, not

# Plan: termination preempts an in-flight engine exchange and reports the reap that ended the actor

## Goal

A termination request (`EngineActor::terminate`, `EngineSupervisor::terminate_exact`, and through
them `terminate_all`, `terminate_tab`, retirement and Kill) no longer waits for the one UCI exchange
an engine actor or a warm interactive transition is currently servicing. Shutdown of a silent engine
then costs one teardown (≤ 5.2 s), not an exchange deadline plus a teardown (15.2 s against
`SHUTDOWN_BUDGET` 15 s). Every termination caller reports the outcome of the child reap that
actually ended the actor, so `terminate_all` can no longer report success over an unconfirmed reap.

## Threat model and non-goals

* **Accidental input only:** an engine that is silent (never answers `isready`, `uci` or `stop`),
  slow, or whose stdin pipe is full so a write blocks; an OS-level reap that fails (kill or wait
  error, reap timeout). No adversary deliberately evading the interrupt is in scope.
* **Environments:** the desktop app on Linux, macOS and Windows. Actor-level behaviour is
  platform-independent (`tokio` futures over `UciIo`); the real-child warm-path fixture is unix-only
  as all existing ones are.
* **Non-goals:** see `## Not part of this task`.

## Approach

### O1 — Termination preempts every in-flight actor exchange

*Rests on MANDATE:* "Every other exchange the actor loop services — the `isready`/`readyok` wait,
the `stop`/`bestmove` drain, and every command write — ignores it"; "should termination preempt an
in-flight exchange".

* **Behaviour.** Once the actor's existing `interrupt` token is cancelled, every command write and
  every terminal-line or configuration read the runtime performs for a command — `Init` (both
  writes, both reads), `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition`,
  `EnsureReady`, `StartSearch` (its implicit `stop_current`, its resynchronising `ensure_ready` and
  its `go` write), `Stop` and `StopRequest` in the loop and in `service_search_read`'s Stop arms —
  stops waiting at once instead of at its own deadline. An exchange that begins after the token is
  cancelled fails without writing.
* **Error.** The interrupted exchange returns `Error::EngineDisconnected`, the error the existing
  cancellable reads already return (P3), so `cancelled_search_error` keeps mapping it to
  `Cancellation` for a cancelled search (P10).
* **Failure path per handler: unchanged.** `EnsureReady`, `StartSearch`, `Stop`, `StopRequest` and
  the search-read Stop arms keep going through `recover_failed_protocol` (runtime terminated, actor
  exits); `Init`, `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition` keep replying the
  error and the loop then services the queued `Terminate` (biased control channel).
* **Boundary.** One token: the actor's existing `interrupt`. No second cancellation mechanism, and
  the runtime's own termination (`quit` write, force kill, reap, stderr join) keeps its existing
  bounds and is never interrupted. `service_search_read`'s search-output read stays preempted by
  the biased control channel as today. `interrupt` remains cancelled only by termination requests
  (`EngineActor::terminate` and O3).
* **Verification level:** deterministic actor tests (O4, A1).

### O2 — `EngineActor::terminate` reports the reap that ended the actor

*Rests on MANDATE:* "`EngineActor::terminate` returns `Ok` when its control request gets
`EngineDisconnected` and the actor task joined — even if the actor's own `recover_failed_protocol`
termination failed and was only logged — so `terminate_all` can report success for an unconfirmed
reap"; "Resolve it with the preemption/termination outcome design and test the queued-shutdown
case."

* **Behaviour.** The actor records the outcome of the runtime termination that ended it, whichever
  path ran it (`Terminate` command, `recover_failed_protocol`, channel closed), in state every
  `EngineActor` clone can read. `EngineActor::terminate` returns:
  * the `Terminate` reply's result when the actor serviced that request (as today);
  * otherwise — the request got `EngineDisconnected` because the actor already exited or exits
    before servicing it — the recorded outcome of the actor's own final termination, after the task
    is joined; this holds equally for a caller that finds the task already joined by another caller.
  * A task join failure is still reported, combined as today.
* `Ok` therefore means the reap that ended this actor succeeded. A recorded failure reaches every
  later caller losslessly (same `category()`, message, `diagnostic()` and `root_failure()`, as
  `Error::Shared` provides — P10). The command whose exchange failed keeps receiving
  `with_cleanup(primary, termination)`. Existing log sites are unchanged; a terminator that now
  receives the recorded failure (for example the shared pending-entry task, P7) logs it through
  its own existing logging.
* **Verification level:** deterministic actor tests (O4, A2).

### O3 — Exact termination preempts an interactive transition and reports that generation's reap

*Rests on MANDATE:* "a fix here must also cover the exchanges inside
`start_interactive_search`/`WarmEngine::{new,start}`"; "so `terminate_all` can report success for
an unconfirmed reap".

* **Behaviour.** `terminate_exact(key, generation)` cancels the matching published actor's
  `interrupt` before it awaits the per-key lifecycle lease, in the same barrier section where it
  already marks that actor cancelled, and after marking it cancelled — so the lease holder's
  in-flight exchange (O1) fails at once and the transition maps it to `Cancellation` (P10). The
  lease holder then reaps the generation itself (P6).
* **Result.** When, after obtaining the lease, the generation it observed is neither published nor
  pending any more because another owner (the lease holder) completed its reap, `terminate_exact`
  returns that actor's recorded termination outcome (O2) instead of `Ok(())`. It never starts a
  second termination of a still-running actor outside the shared pending-entry task
  (`d-20261006-19`); a generation it never observed keeps today's `Ok(())`.
* **Observation starts at the drain's snapshot.** `drain_matching` (P8) snapshots each published
  target together with the actor it observed, and that target's result is the observed actor's
  recorded outcome whenever another owner reaped it between the snapshot and the exact
  termination — so a failed reap of an actor `terminate_all`, `terminate_tab` or retirement
  targeted is never reported as success. A direct `terminate_exact` call observes in its own
  barrier section as above.
* `terminate_all`, `terminate_tab` and retirement inherit both through the drain and
  `terminate_exact` (P8); `kill_engine` already reaches `EngineActor::terminate` without the lease
  and needs nothing beyond O1/O2.
* **Verification level:** supervisor tests, real-child unix fixture for the warm transition (O4,
  A3).

### O4 — Verification

*Rests on MANDATE:* "Tests must observe the exchange's write or read *before* calling
`terminate()` … and cover the indirect paths (`start_search`'s implicit stop/readiness,
`service_search_read`'s Stop arms, init writes, `ConfigureStart`)"; R9-03; "test the
queued-shutdown case".

* **A1 — preemption per exchange path** (actor level, fake I/O, runs on every platform). One case
  per call site: `Init`'s `uci` write and its `isready` write, `ConfigureStart`'s `uci` write,
  `SetOption`'s write, `SetPosition`'s write, direct `EnsureReady` (blocked `isready` write and
  silent `readyok` read), `StartSearch`'s implicit stop (blocked `stop` write and silent `bestmove`
  drain), `StartSearch`'s resynchronising readiness (silent `readyok`), `StartSearch`'s blocked
  `go` write, loop `Stop`, and `service_search_read`'s Stop arms on the control and the normal
  queue. Each case proves by a handshake — never a sleep — that the exchange's write or read has
  started before it calls `terminate()`; uses exchange deadlines far longer than the case's bound;
  asserts that `terminate()` returns `Ok` within a bound far below the exchange deadline, that the
  in-flight requester received exactly `Error::EngineDisconnected` (O1), and that
  `UciIo::terminate` ran exactly once. Each case goes red if the token is missing at its call
  site. Cases share one table-driven harness rather than copies (global rule 11).
* **A2 — termination outcome.** (a) Queued shutdown: an actor whose exchange is preempted (and one
  whose exchange times out on its own) with a failing runtime termination and a `Terminate`
  queued — `terminate()` returns `Err` carrying the termination failure; a second `terminate()` on
  a clone returns the same failure. (b) An actor that already exited through its own failed
  protocol recovery, with no termination requested — a later `terminate()` returns `Err`; with a
  successful recovery it returns `Ok`. Each goes red with today's `EngineDisconnected → Ok` mapping.
* **A3 — warm transition and exact result.** Unix real-child fixture: a warm transition whose
  engine never answers `isready`, on the fresh and the reuse path, terminated through
  `terminate_exact` and through `terminate_all`. Every case first observes the transition's
  `isready` on the child's wire (the handshake the existing warm-transition test uses) and only
  then requests termination; it asserts the termination completes far below the 10 s `readyok`
  deadline, the search resolves to `Cancellation`, `quit` reaches the child and the registry entry
  is gone. Supervisor level, with orderings reached deterministically (a test hook or barrier,
  never timing): when the lease holder's reap of the observed generation fails, `terminate_exact`
  returns `Err` with that failure; when another owner's failed reap of a drain target completes
  between the drain's snapshot and its exact termination, `terminate_all` returns `Err` with that
  failure.
* **A4 — unchanged behaviour stays green**, notably
  `warm_transition_termination_stops_after_one_slow_exchange_on_fresh_and_reuse_paths` (including
  its `release` case), `termination_preempts_a_silent_search_read`,
  `chatty_ensure_ready_timeout_reaps_actor_and_rejects_search`, the `init_uci_cancellable_*` tests
  and `recover_failed_protocol_preserves_operation_and_termination_roles`.
* **A5 — one expectation inverts by design.**
  `recover_failed_protocol_logs_termination_failure_for_bound_actor` currently expects the
  `terminate_exact` that follows a failed recovery reap to succeed ("reaped idempotently"). Under
  O2 it must return `Err` carrying the injected termination failure; the test is changed to assert
  that, keeping its single-log assertion for the recovery site.

## Decided autonomously

* **D1 — Preempt, do not re-size budgets.** Question: termination preempts an in-flight exchange,
  or the budgets are re-sized so the longest exchange plus teardown fits `SHUTDOWN_BUDGET`?
  Chosen: preempt (O1, O3). Rejected: raising `SHUTDOWN_BUDGET` above 15.2 s (the app then hangs on
  exit for over 15 s with a silent engine, and any later exchange or transition re-breaks the
  arithmetic) and cutting `readyok`/`uciok` below 9.8 s (fails slow but healthy engines, e.g. a
  large-hash initialisation, to save shutdown time). Reason: `async-resource-invariants.md`
  "cancellation before use"; the bound becomes one teardown (≤ 5.2 s) independent of every exchange
  deadline. Reversal path: drop the token from the runtime's writes/reads and size the budget.
* **D2 — Interrupted exchange error is `EngineDisconnected`.** Rejected: a new error variant (a
  renderer-visible category and bindings change with no consumer that distinguishes it). Reason: it
  is what the existing cancellable reads return, and `cancelled_search_error` already maps it.
* **D3 — The actor's own final termination outcome is the answer for every later terminator.**
  Rejected: keeping `EngineDisconnected → Ok` (the defect); routing every registered-actor
  termination through the pending-entry sharing of `d-20261006-19` (that decision explicitly kept
  registered actors out, and registry retention of failed actors is `f-20261001-14`).
* **D4 — Release and stop paths do not preempt.** `release_generation` / `stop_search` keep their
  graceful `stop` before the reap. Rejected: cancelling `interrupt` inside
  `SupervisedEngine::mark_cancelled` (every release would abort its own `stop`, turning a clean
  release into an `EngineDisconnected` failure). Reason: they are not on the shutdown path; exact,
  all, tab, retirement and Kill are.
* **D5 — No deadline or budget constant changes.** The shutdown bound follows from D1.

## Risks / open questions

* A write cancelled mid-line can leave a partial command on the engine's stdin before `quit`; the
  engine may then ignore `quit` and is force-killed after the 3 s `quit` bound — still inside the
  5.2 s teardown.
* A release racing a Kill or shutdown on the same actor can now see its `stop` fail with
  `EngineDisconnected` promptly instead of after the exchange; before this change the same race
  already ended in `EngineDisconnected` once `Terminate` closed the channel. Known limit, not
  worsened.

## Not part of this task

* `f-20260927-01` (channel-closed terminations discard or label-log a failed termination) — its own
  inline finding; O2 records that path's outcome but does not change its logging.
* `f-20261001-14` (a failed termination removes the actor from the registry) — retention/retry of
  failed actors.
* `f-20261006-04` (a launch that spawns after the final drain).
* An actor another owner already reaped before a drain's snapshot: the drain never targeted it and
  the failure goes to that owner's caller; keeping it findable afterwards is `f-20261001-14`.
* Preempting release/stop paths (D4); renderer changes; any change to deadlines or
  `SHUTDOWN_BUDGET` (D5).

### plan-r3.md

# Plan: termination preempts an in-flight engine exchange and reports the reap that ended the actor

## Goal

A termination request (`EngineActor::terminate`, `EngineSupervisor::terminate_exact`, and through
them `terminate_all`, `terminate_tab`, retirement and Kill) no longer waits for the one UCI exchange
an engine actor or a warm interactive transition is currently servicing. Shutdown of a silent engine
then costs one teardown (≤ 5.2 s), not an exchange deadline plus a teardown (15.2 s against
`SHUTDOWN_BUDGET` 15 s). Every termination caller reports the outcome of the child reap that
actually ended the actor, so `terminate_all` can no longer report success over an unconfirmed reap.

## Approach

### O1 — Termination preempts every in-flight actor exchange

*Rests on MANDATE:* "Every other exchange the actor loop services — the `isready`/`readyok` wait,
the `stop`/`bestmove` drain, and every command write — ignores it"; "should termination preempt an
in-flight exchange".

* **Behaviour.** Once the actor's existing `interrupt` token is cancelled, every command write and
  every terminal-line or configuration read the runtime performs for a command — `Init` (both
  writes, both reads), `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition`,
  `EnsureReady`, `StartSearch` (its implicit `stop_current`, its resynchronising `ensure_ready` and
  its `go` write), `Stop` and `StopRequest` in the loop and in `service_search_read`'s Stop arms —
  stops waiting at once instead of at its own deadline. An exchange that begins after the token is
  cancelled fails without writing.
* **Error.** The interrupted exchange returns `Error::EngineDisconnected`, the error the existing
  cancellable reads already return (P3), so `cancelled_search_error` keeps mapping it to
  `Cancellation` for a cancelled search (P10).
* **Failure path per handler: unchanged.** `EnsureReady`, `StartSearch`, `Stop`, `StopRequest` and
  the search-read Stop arms keep going through `recover_failed_protocol` (runtime terminated, actor
  exits); `Init`, `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition` keep replying the
  error and the loop then services the queued `Terminate` (biased control channel).
* **Boundary.** One token: the actor's existing `interrupt`. No second cancellation mechanism, and
  the runtime's own termination (`quit` write, force kill, reap, stderr join) keeps its existing
  bounds and is never interrupted. `service_search_read`'s search-output read stays preempted by
  the biased control channel as today. `interrupt` remains cancelled only by termination requests
  (`EngineActor::terminate` and O3).
* **Verification level:** deterministic actor tests (O4, A1).

### O2 — `EngineActor::terminate` reports the reap that ended the actor

*Rests on MANDATE:* "`EngineActor::terminate` returns `Ok` when its control request gets
`EngineDisconnected` and the actor task joined — even if the actor's own `recover_failed_protocol`
termination failed and was only logged — so `terminate_all` can report success for an unconfirmed
reap"; "Resolve it with the preemption/termination outcome design and test the queued-shutdown
case."

* **Behaviour.** The actor records the outcome of the runtime termination that ended it, whichever
  path ran it (`Terminate` command, `recover_failed_protocol`, channel closed), in state every
  `EngineActor` clone can read. `EngineActor::terminate` returns:
  * the `Terminate` reply's result when the actor serviced that request (as today);
  * otherwise — the request got `EngineDisconnected` because the actor already exited or exits
    before servicing it — the recorded outcome of the actor's own final termination, after the task
    is joined; this holds equally for a caller that finds the task already joined by another caller.
  * A task join failure is still reported, combined as today.
* `Ok` therefore means the reap that ended this actor succeeded. A recorded failure reaches every
  later caller losslessly (same `category()`, message, `diagnostic()` and `root_failure()`, as
  `Error::Shared` provides — P10). The command whose exchange failed keeps receiving
  `with_cleanup(primary, termination)`. Existing log sites are unchanged; a terminator that now
  receives the recorded failure (for example the shared pending-entry task, P7) logs it through
  its own existing logging.
* **Verification level:** deterministic actor tests (O4, A2).

### O3 — Exact termination preempts an interactive transition and reports that generation's reap

*Rests on MANDATE:* "a fix here must also cover the exchanges inside
`start_interactive_search`/`WarmEngine::{new,start}`"; "so `terminate_all` can report success for
an unconfirmed reap".

* **Behaviour.** `terminate_exact(key, generation)` cancels the matching published actor's
  `interrupt` before it awaits the per-key lifecycle lease, in the same barrier section where it
  already marks that actor cancelled, and after marking it cancelled — so the lease holder's
  in-flight exchange (O1) fails at once and the transition maps it to `Cancellation` (P10). The
  lease holder then reaps the generation itself (P6).
* **Result.** When, after obtaining the lease, the generation it observed is neither published nor
  pending any more because another owner (the lease holder) completed its reap, `terminate_exact`
  returns that actor's recorded termination outcome (O2) instead of `Ok(())`. It never starts a
  second termination of a still-running actor outside the shared pending-entry task
  (`d-20261006-19`); a generation it never observed keeps today's `Ok(())`.
* **Observation starts at the drain's snapshot.** `drain_matching` (P8) snapshots each published
  target together with the actor it observed, and that target's result is the observed actor's
  recorded outcome whenever another owner reaped it between the snapshot and the exact
  termination — so a failed reap of an actor `terminate_all`, `terminate_tab` or retirement
  targeted is never reported as success. A direct `terminate_exact` call observes in its own
  barrier section as above.
* `terminate_all`, `terminate_tab` and retirement inherit both through the drain and
  `terminate_exact` (P8); `kill_engine` already reaches `EngineActor::terminate` without the lease
  and needs nothing beyond O1/O2.
* **Verification level:** supervisor tests, real-child unix fixture for the warm transition (O4,
  A3).

### O4 — Verification

*Rests on MANDATE:* "Tests must observe the exchange's write or read *before* calling
`terminate()` … and cover the indirect paths (`start_search`'s implicit stop/readiness,
`service_search_read`'s Stop arms, init writes, `ConfigureStart`)"; R9-03; "test the
queued-shutdown case".

* **A1 — preemption per exchange path** (actor level, fake I/O, runs on every platform). One case
  per call site: `Init`'s `uci` write and its `isready` write, `ConfigureStart`'s `uci` write,
  `SetOption`'s write, `SetPosition`'s write, direct `EnsureReady` (blocked `isready` write and
  silent `readyok` read), `StartSearch`'s implicit stop (blocked `stop` write and silent `bestmove`
  drain), `StartSearch`'s resynchronising readiness (silent `readyok`), `StartSearch`'s blocked
  `go` write, loop `Stop`, and `service_search_read`'s Stop arms on the control and the normal
  queue. Each case proves by a handshake — never a sleep — that the exchange's write or read has
  started before it calls `terminate()`; uses exchange deadlines far longer than the case's bound;
  asserts that `terminate()` returns `Ok` within a bound far below the exchange deadline, that the
  in-flight requester received exactly `Error::EngineDisconnected` (O1), and that
  `UciIo::terminate` ran exactly once. Each case goes red if the token is missing at its call
  site. Cases share one table-driven harness rather than copies (global rule 11).
* **A2 — termination outcome.** (a) Queued shutdown: an actor whose exchange is preempted (and one
  whose exchange times out on its own) with a failing runtime termination and a `Terminate`
  queued — `terminate()` returns `Err` carrying the termination failure; a second `terminate()` on
  a clone returns the same failure. (b) An actor that already exited through its own failed
  protocol recovery, with no termination requested — a later `terminate()` returns `Err`; with a
  successful recovery it returns `Ok`. Each goes red with today's `EngineDisconnected → Ok` mapping.
* **A3 — warm transition and exact result.** Unix real-child fixture: a warm transition whose
  engine never answers `isready`, on the fresh and the reuse path, terminated through
  `terminate_exact` and through `terminate_all`. Every case first observes the transition's
  `isready` on the child's wire (the handshake the existing warm-transition test uses) and only
  then requests termination; it asserts the termination completes far below the 10 s `readyok`
  deadline, the search resolves to `Cancellation`, `quit` reaches the child and the registry entry
  is gone. Supervisor level, with orderings reached deterministically (a test hook or barrier,
  never timing): when the lease holder's reap of the observed generation fails, `terminate_exact`
  returns `Err` with that failure; when another owner's failed reap of a drain target completes
  between the drain's snapshot and its exact termination, `terminate_all` returns `Err` with that
  failure.
* **A4 — unchanged behaviour stays green**, notably
  `warm_transition_termination_stops_after_one_slow_exchange_on_fresh_and_reuse_paths` (including
  its `release` case), `termination_preempts_a_silent_search_read`,
  `chatty_ensure_ready_timeout_reaps_actor_and_rejects_search`, the `init_uci_cancellable_*` tests
  and `recover_failed_protocol_preserves_operation_and_termination_roles`.
* **A5 — one class of existing expectation inverts by design.** Any existing test that injects a
  failed final termination of an actor and then expects a *later* terminator of that same actor
  (`terminate_exact`, `terminate_all`, retirement, `EngineActor::terminate`) to succeed encodes the
  defect O2 removes; each such assertion changes to expect `Err` carrying the injected failure,

## Decided autonomously

* **D1 — Preempt, do not re-size budgets.** Question: termination preempts an in-flight exchange,
  or the budgets are re-sized so the longest exchange plus teardown fits `SHUTDOWN_BUDGET`?
  Chosen: preempt (O1, O3). Rejected: raising `SHUTDOWN_BUDGET` above 15.2 s (the app then hangs on
  exit for over 15 s with a silent engine, and any later exchange or transition re-breaks the
  arithmetic) and cutting `readyok`/`uciok` below 9.8 s (fails slow but healthy engines, e.g. a
  large-hash initialisation, to save shutdown time). Reason: `async-resource-invariants.md`
  "cancellation before use"; the bound becomes one teardown (≤ 5.2 s) independent of every exchange
  deadline. Reversal path: drop the token from the runtime's writes/reads and size the budget.
* **D2 — Interrupted exchange error is `EngineDisconnected`.** Rejected: a new error variant (a
  renderer-visible category and bindings change with no consumer that distinguishes it). Reason: it
  is what the existing cancellable reads return, and `cancelled_search_error` already maps it.
* **D3 — The actor's own final termination outcome is the answer for every later terminator.**
  Rejected: keeping `EngineDisconnected → Ok` (the defect); routing every registered-actor
  termination through the pending-entry sharing of `d-20261006-19` (that decision explicitly kept
  registered actors out, and registry retention of failed actors is `f-20261001-14`).
* **D4 — Release and stop paths do not preempt.** `release_generation` / `stop_search` keep their
  graceful `stop` before the reap. Rejected: cancelling `interrupt` inside
  `SupervisedEngine::mark_cancelled` (every release would abort its own `stop`, turning a clean
  release into an `EngineDisconnected` failure). Reason: they are not on the shutdown path; exact,
  all, tab, retirement and Kill are.
* **D5 — No deadline or budget constant changes.** The shutdown bound follows from D1.

### plan-r4.md

# Plan: termination preempts an in-flight engine exchange and reports the reap that ended the actor

## Goal

A termination request (`EngineActor::terminate`, `EngineSupervisor::terminate_exact`, and through
them `terminate_all`, `terminate_tab`, retirement and Kill) no longer waits for the one UCI exchange
an engine actor or a warm interactive transition is currently servicing. Shutdown of a silent engine
then costs one teardown (≤ 5.2 s), not an exchange deadline plus a teardown (15.2 s against
`SHUTDOWN_BUDGET` 15 s). Every termination caller reports the outcome of the child reap that
actually ended the actor, so `terminate_all` can no longer report success over an unconfirmed reap.

## MANDATE

## Approach

### O1 — Termination preempts every in-flight actor exchange

*Rests on MANDATE:* "Every other exchange the actor loop services — the `isready`/`readyok` wait,
the `stop`/`bestmove` drain, and every command write — ignores it"; "should termination preempt an
in-flight exchange".

* **Behaviour.** Once the actor's existing `interrupt` token is cancelled, every command write and
  every terminal-line or configuration read the runtime performs for a command — `Init` (both
  writes, both reads), `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition`,
  `EnsureReady`, `StartSearch` (its implicit `stop_current`, its resynchronising `ensure_ready` and
  its `go` write), `Stop` and `StopRequest` in the loop and in `service_search_read`'s Stop arms —
  stops waiting at once instead of at its own deadline. An exchange that begins after the token is
  cancelled fails without writing.
* **Error.** The interrupted exchange returns `Error::EngineDisconnected`, the error the existing
  cancellable reads already return (P3), so `cancelled_search_error` keeps mapping it to
  `Cancellation` for a cancelled search (P10).
* **Failure path per handler: unchanged.** `EnsureReady`, `StartSearch`, `Stop`, `StopRequest` and
  the search-read Stop arms keep going through `recover_failed_protocol` (runtime terminated, actor
  exits); `Init`, `ConfigureStart`, `ConfigureNext`, `SetOption`, `SetPosition` keep replying the
  error and the loop then services the queued `Terminate` (biased control channel).
* **Boundary.** One token: the actor's existing `interrupt`. No second cancellation mechanism, and
  the runtime's own termination (`quit` write, force kill, reap, stderr join) keeps its existing
  bounds and is never interrupted. `service_search_read`'s search-output read stays preempted by
  the biased control channel as today. `interrupt` remains cancelled only by termination requests
  (`EngineActor::terminate` and O3).
* **Verification level:** deterministic actor tests (O4, A1).

### O2 — `EngineActor::terminate` reports the reap that ended the actor

*Rests on MANDATE:* "`EngineActor::terminate` returns `Ok` when its control request gets
`EngineDisconnected` and the actor task joined — even if the actor's own `recover_failed_protocol`
termination failed and was only logged — so `terminate_all` can report success for an unconfirmed
reap"; "Resolve it with the preemption/termination outcome design and test the queued-shutdown
case."

* **Behaviour.** The actor records the outcome of the runtime termination that ended it, whichever
  path ran it (`Terminate` command, `recover_failed_protocol`, channel closed), in state every
  `EngineActor` clone can read. `EngineActor::terminate` returns:
  * the `Terminate` reply's result when the actor serviced that request (as today);
  * otherwise — the request got `EngineDisconnected` because the actor already exited or exits
    before servicing it — the recorded outcome of the actor's own final termination, after the task
    is joined; this holds equally for a caller that finds the task already joined by another caller.
  * A task join failure is still reported, combined as today.
* `Ok` therefore means the reap that ended this actor succeeded. A recorded failure reaches every
  later caller losslessly (same `category()`, message, `diagnostic()` and `root_failure()`, as
  `Error::Shared` provides — P10). The command whose exchange failed keeps receiving
  `with_cleanup(primary, termination)`. Existing log sites are unchanged; a terminator that now
  receives the recorded failure (for example the shared pending-entry task, P7) logs it through
  its own existing logging.
* **Verification level:** deterministic actor tests (O4, A2).

### O3 — Exact termination preempts an interactive transition and reports that generation's reap

*Rests on MANDATE:* "a fix here must also cover the exchanges inside
`start_interactive_search`/`WarmEngine::{new,start}`"; "so `terminate_all` can report success for
an unconfirmed reap".

* **Behaviour.** `terminate_exact(key, generation)` cancels the matching published actor's
  `interrupt` before it awaits the per-key lifecycle lease, in the same barrier section where it
  already marks that actor cancelled, and after marking it cancelled — so the lease holder's
  in-flight exchange (O1) fails at once and the transition maps it to `Cancellation` (P10). The
  lease holder then reaps the generation itself (P6).
* **Result.** When, after obtaining the lease, the generation it observed is neither published nor
  pending any more because another owner (the lease holder) completed its reap, `terminate_exact`
  returns that actor's recorded termination outcome (O2) instead of `Ok(())`. It never starts a
  second termination of a still-running actor outside the shared pending-entry task
  (`d-20261006-19`); a generation it never observed keeps today's `Ok(())`.
* **Observation starts at the drain's snapshot.** `drain_matching` (P8) snapshots each published
  target together with the actor it observed, and that target's result is the observed actor's
  recorded outcome whenever another owner reaped it between the snapshot and the exact
  termination — so a failed reap of an actor `terminate_all`, `terminate_tab` or retirement
  targeted is never reported as success. A direct `terminate_exact` call observes in its own
  barrier section as above.
* `terminate_all`, `terminate_tab` and retirement inherit both through the drain and
  `terminate_exact` (P8); `kill_engine` already reaches `EngineActor::terminate` without the lease
  and needs nothing beyond O1/O2.
* **Verification level:** supervisor tests, real-child unix fixture for the warm transition (O4,
  A3).

### O4 — Verification

*Rests on MANDATE:* "Tests must observe the exchange's write or read *before* calling
`terminate()` … and cover the indirect paths (`start_search`'s implicit stop/readiness,
`service_search_read`'s Stop arms, init writes, `ConfigureStart`)"; R9-03; "test the
queued-shutdown case".

* **A1 — preemption per exchange path** (actor level, fake I/O, runs on every platform). One case
  per call site: `Init`'s `uci` write and its `isready` write, `ConfigureStart`'s `uci` write,
  `SetOption`'s write, `SetPosition`'s write, direct `EnsureReady` (blocked `isready` write and
  silent `readyok` read), `StartSearch`'s implicit stop (blocked `stop` write and silent `bestmove`
  drain), `StartSearch`'s resynchronising readiness (silent `readyok`), `StartSearch`'s blocked
  `go` write, loop `Stop`, and `service_search_read`'s Stop arms on the control and the normal
  queue. Each case proves by a handshake — never a sleep — that the exchange's write or read has
  started before it calls `terminate()`; uses exchange deadlines far longer than the case's bound;
  asserts that `terminate()` returns `Ok` within a bound far below the exchange deadline, that the
  in-flight requester received exactly `Error::EngineDisconnected` (O1), and that
  `UciIo::terminate` ran exactly once. Each case goes red if the token is missing at its call
  site. Cases share one table-driven harness rather than copies (global rule 11).
* **A2 — termination outcome.** (a) Queued shutdown: an actor whose exchange is preempted (and one
  whose exchange times out on its own) with a failing runtime termination and a `Terminate`
  queued — `terminate()` returns `Err` carrying the termination failure; a second `terminate()` on
  a clone returns the same failure. (b) An actor that already exited through its own failed
  protocol recovery, with no termination requested — a later `terminate()` returns `Err`; with a
  successful recovery it returns `Ok`. Each goes red with today's `EngineDisconnected → Ok` mapping.
* **A3 — warm transition and exact result.** Unix real-child fixture: a warm transition whose
  engine never answers `isready`, on the fresh and the reuse path, terminated through
  `terminate_exact` and through `terminate_all`. Every case first observes the transition's
  `isready` on the child's wire (the handshake the existing warm-transition test uses) and only
  then requests termination; it asserts the termination completes far below the 10 s `readyok`
  deadline, the search resolves to `Cancellation`, `quit` reaches the child and the registry entry
  is gone. Supervisor level, with orderings reached deterministically (a test hook or barrier,
  never timing): when the lease holder's reap of the observed generation fails, `terminate_exact`
  returns `Err` with that failure; when another owner's failed reap of a drain target completes
  between the drain's snapshot and its exact termination, `terminate_all` returns `Err` with that
  failure.
* **A4 — unchanged behaviour stays green**, notably
  `warm_transition_termination_stops_after_one_slow_exchange_on_fresh_and_reuse_paths` (including
  its `release` case), `termination_preempts_a_silent_search_read`,
  `chatty_ensure_ready_timeout_reaps_actor_and_rejects_search`, the `init_uci_cancellable_*` tests
  and `recover_failed_protocol_preserves_operation_and_termination_roles`.
* **A5 — one class of existing expectation inverts by design.** Any existing test that injects a
  failed final termination of an actor and then expects a *later* terminator of that same actor
  (`terminate_exact`, `terminate_all`, retirement, `EngineActor::terminate`) to succeed encodes the
  defect O2 removes; each such assertion changes to expect `Err` carrying the injected failure,
  keeping its other assertions (log lines, registry removal). Known instances at BASE:
  `recover_failed_protocol_logs_termination_failure_for_bound_actor` (`process.rs:6936-6939`,
  failed recovery reap) and `terminate_now_logs_command_failure_during_active_search`
  (`process.rs:6779-6793`, normal-channel `Terminate` whose reply was dropped). The complete set
  is whatever the phase proof turns red in this class; a red test outside this class is not
  rewritten to pass but reported as a deviation. Tests that terminate a *different* actor after a
  failure (for example the `unrelated` key in the `game.rs` retirement tests) are unaffected.

### O5 — Rule text follows the code

*Rests on MANDATE:* "`.claude/rules/engine-lifecycle.md` (every spawn has a kill on every exit
path)". The DO bullet in `.claude/rules/engine-lifecycle.md` that says the stop drain does not
observe the termination interrupt (P12) becomes false; restate it as the invariant this plan
establishes: a termination request preempts the in-flight exchange, and every terminator reports

## Decided autonomously

* **D1 — Preempt, do not re-size budgets.** Question: termination preempts an in-flight exchange,
  or the budgets are re-sized so the longest exchange plus teardown fits `SHUTDOWN_BUDGET`?
  Chosen: preempt (O1, O3). Rejected: raising `SHUTDOWN_BUDGET` above 15.2 s (the app then hangs on
  exit for over 15 s with a silent engine, and any later exchange or transition re-breaks the
  arithmetic) and cutting `readyok`/`uciok` below 9.8 s (fails slow but healthy engines, e.g. a
  large-hash initialisation, to save shutdown time). Reason: `async-resource-invariants.md`
  "cancellation before use"; the bound becomes one teardown (≤ 5.2 s) independent of every exchange
  deadline. Reversal path: drop the token from the runtime's writes/reads and size the budget.
* **D2 — Interrupted exchange error is `EngineDisconnected`.** Rejected: a new error variant (a
  renderer-visible category and bindings change with no consumer that distinguishes it). Reason: it
  is what the existing cancellable reads return, and `cancelled_search_error` already maps it.
* **D3 — The actor's own final termination outcome is the answer for every later terminator.**
  Rejected: keeping `EngineDisconnected → Ok` (the defect); routing every registered-actor
  termination through the pending-entry sharing of `d-20261006-19` (that decision explicitly kept
  registered actors out, and registry retention of failed actors is `f-20261001-14`).
* **D4 — Release and stop paths do not preempt.** `release_generation` / `stop_search` keep their
  graceful `stop` before the reap. Rejected: cancelling `interrupt` inside
  `SupervisedEngine::mark_cancelled` (every release would abort its own `stop`, turning a clean
  release into an `EngineDisconnected` failure). Reason: they are not on the shutdown path; exact,
  all, tab, retirement and Kill are.
* **D5 — No deadline or budget constant changes.** The shutdown bound follows from D1.

## Risks / open questions

* A write cancelled mid-line can leave a partial command on the engine's stdin before `quit`; the
  engine may then ignore `quit` and is force-killed after the 3 s `quit` bound — still inside the
  5.2 s teardown.
* A release racing a Kill or shutdown on the same actor can now see its `stop` fail with
  `EngineDisconnected` promptly instead of after the exchange; before this change the same race
  already ended in `EngineDisconnected` once `Terminate` closed the channel. Known limit, not
  worsened.

## Not part of this task

* `f-20260927-01` (channel-closed terminations discard or label-log a failed termination) — its own
  inline finding; O2 records that path's outcome but does not change its logging.
* `f-20261001-14` (a failed termination removes the actor from the registry) — retention/retry of
  failed actors.
* `f-20261006-04` (a launch that spawns after the final drain).
* An actor another owner already reaped before a drain's snapshot: the drain never targeted it and
  the failure goes to that owner's caller; keeping it findable afterwards is `f-20261001-14`.
* Preempting release/stop paths (D4); renderer changes; any change to deadlines or
  `SHUTDOWN_BUDGET` (D5).
