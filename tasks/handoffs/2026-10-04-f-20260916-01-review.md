# Plan: closed-world assertion over the Windows refusals (f-20260916-01)

## Goal

Every Windows refusal that exists in production Rust source is either a pinned row or makes the
Linux test run red, for the spellings named in the MANDATE; the shared refusal helpers are pinned

## MANDATE

Verbatim from `tasks/findings.md`, `f-20260916-01` (entry and its 2026-09-16 annotation):

> **Defect:** after `f-20260914-07` every one of the 40 Windows refusal sites is pinned exactly and those pins run on Windows, but three gaps remain, each of which lets a Windows refusal change or disappear with every gate green: (1) the shared helpers and the refusal constant have no pinned declaration — an effect added inside `refusal`, or a changed format, body or visibility, leaves every row's text unchanged; (2) nothing ties the row tables to the set of refusals that actually exist, so a **newly added** refusal site (or one spelled through an alias, a bare `Error::Conflict` literal or the constant) is simply unlisted and unpinned; (3) the callees on an effective non-unix path (`single_leaf`, `validate_components`) are unpinned, so an effect added inside one of them precedes a refusal without changing its row. Frozen in round 1.

* **Adversary: none — accidental drift only.** The input is this repository's own production Rust
  source under `src-tauri/src/`, written by Felix's agents. The threat is a future change that adds,
  moves or re-spells a Windows refusal without adding or updating its pin, in a spelling an agent
  would naturally write. The MANDATE names the spellings that must be caught: a new
  `#[cfg(not(unix))]` site, `use … as`, a bare `Error::Conflict` literal, a `concat!`-split
  message; plus every helper-level change (new helper, changed body/format/visibility).
* **What "a refusal" is.** `d-20260914-05`: an unported Windows operation ends in
  `Error::Conflict("<operation> is|are unsupported on this platform")` built by
  `infra/platform_support.rs`. A refusal occurrence is therefore (a) any production reach of the
  helpers in that module, or (b) the refusal wording in a production string literal. An
  arbitrary Windows-gated error with *different* wording is not a refusal under that decision and
  is not detected (named limit L1 below).
* **Environments.** The assertions are platform-independent source checks; they execute in every
  `cargo test` run, Linux, macOS and the `rust-windows-test` job alike (`d-20260916-01` as
  reaffirmed by `d-20260916-06`).

    allowlist of Windows-gated conflicts would record entries with no refusal semantics and could
    not tell a refusal from a legitimate identity conflict.
  * L2 — refusal wording assembled at run time from non-literal parts, or split so that neither
    stem (D below) survives inside one literal; escape-encoded wording (`\x70latform`); wording
    generated by a procedural macro or read from a data file.
  * L3 — a string literal that spans a physical line break: the shared lexer
    (`infra/blocking.rs` `quoted_end`) stops a plain string at `\n` by design, so such a literal
    is not lexed as a literal. Changing the shared lexer is out of scope (it changes every scan
    that uses it).
  * These continue R6-06 as stated limitations; the MANDATE's named spellings are all inside the
    detected set.

## Approach

### A. Verifier and subject live in different files

*MANDATE words:* "how is a closed-world assertion over the refusals staged at all, given that its
own assertions live in `infra/platform_support.rs`"; "pin the helpers from a *different*
module's test".

* The whole test module of `infra/platform_support.rs` moves, unchanged in behaviour, to
  `src-tauri/src/infra/platform_support/tests.rs`, declared in the subject as
  `#[cfg(test)] mod tests;`. Test paths stay `infra::platform_support::tests::<name>`, so every
  external comment naming a test by path stays valid. Only the text changes that the move forces:
  one indentation level, and every `include_str!` path gains one `../`.
* The subject file afterwards holds only: a short `//!` pointer to the verifier, `use
  crate::error::Error;`, the four helpers, and `#[cfg(test)] mod tests;`. Its production text is
  unchanged.
* The module-doc staged-matrix record (`:1-309`) moves to the head of the verifier file: the
  record lives with the artefact it describes (push-review-policy §2).
* Comments elsewhere that say a pin lives "in `platform_support.rs`" are repointed to
  `infra/platform_support/tests.rs` (`infra/fs.rs:9281`, `:9526`; `infra/blocking.rs:25`;
  `infra/path_authority/resolved.rs:1141` if its wording names the file).
* **Why this answers the open question:** after the split, `infra/platform_support.rs` is an input
  the verifier reads through `include_str!`, not the verifier's logic, so the helper, visibility
  and own-file cases stage by editing it in a disposable worktree — the route P8 permits. R15-01's
  forbidden route disappears rather than being argued around.
* Verification level: behaviour-preserving move; the set of test names under
  `infra::platform_support::tests::` is identical before and after, and every test passes.

### B. The subject file is pinned whole

*MANDATE words:* "(1) the shared helpers … have no pinned declaration — an effect added inside
`refusal`, or a changed format, body or visibility"; R11-01.

* One assertion compares the whole of `infra/platform_support.rs` — comments blanked by
  `normalise(…, Literals::Keep)`, then `compact`ed — against one expected string. Any added,
  removed or changed item (a fifth helper, a re-export, a macro, a changed body, format string or
  visibility, a removed `#[cfg(test)]` on the `mod tests;` declaration) fails it; comment edits
  do not.
* Failure message (unique): `refusal subject changed: <compacted actual>`.
* It replaces `refusal_format_has_one_body` (P6), whose four `check_helper` pins and phrase count
  it subsumes; `check_helper` stays for its other callers.
* The `#[cfg(test)] mod tests;` declaration being part of the pinned text is what makes the
  verifier file test-only by construction; C and D rely on that to exclude it.

### C. Every production reach of the refusal helpers is a listed site

*MANDATE words:* "tying the G/B row tables to every refusal occurrence in the tree so that a
future unlisted, aliased … refusal (a new `#[cfg(not(unix))]` site, `use … as` …) cannot exist
unpinned"; R4-02; R14-03.

* Scope: the production region (E) of every `.rs` file under `src-tauri/src` except exactly the
  two keys `infra/platform_support.rs` (pinned whole by B) and `infra/platform_support/tests.rs`
  (test-only by B's pinned declaration). Exclusion is by `src`-relative key, never by file name.
* Every occurrence of the identifier token `platform_support` (found in `Literals::Blank` text, so
  comments and literals cannot fake or hide one) must be either the declaration
  `pub(crate) mod platform_support;` in `infra/mod.rs`, or a call of the exact form
  `crate::infra::platform_support::<helper>("<label>"` (whitespace-insensitive, trailing comma
  allowed) with `<helper>` one of `off_unix_refusal`, `unsupported`, `unsupported_plural` and
  `<label>` a single string literal read from the `Literals::Keep` text at the same offset (P11).
  Because every route to the helpers from another file must name the module, this one rule covers
  `use … as`, `use …::platform_support;`, globs, re-exports, `super::`-relative paths and a helper
  passed as a function value.
* Each valid call yields a tuple `(file key, enclosing named fn, helper, label)`. The multiset of
  tuples must equal the expected multiset built from `guard_rows()` (helper
  `off_unix_refusal`, label = the row's operation, fn = the name in the row's signature) plus one
  routed-row table holding today's single routed site (P2). No separate count or uniqueness
  assertion exists: a duplicated production call, a removed one, a moved one and a new one all
  surface as a multiset difference, so R14-03's "argued" count paths dissolve into staged ones.
* Failure messages, one per path, each naming file and line where one exists:
  * `refusal inventory: <file>:<line>: platform_support reference is not a qualified refusal call`
  * `refusal inventory: <file>:<line>: refusal label is not one string literal`
  * `refusal inventory: <file>:<line>: refusal call outside a named function`
  * `refusal inventory: unexpected refusal sites: [<tuples>]`
  * `refusal inventory: missing refusal sites: [<tuples>]`
  All failures of one run are collected and reported together.
* It replaces `production_off_unix_refusal_calls_match_guard_rows` and
  `routed_refusal_labels_are_unchanged` (P4), whose assertions it subsumes. The per-row guard
  checks (`refusal_guards_are_first_statements_and_precede_their_effects`) stay as they are; C
  decides *which* sites exist, the guard rows decide *how* each is placed.

### D. The refusal wording appears in no other production literal

*MANDATE words:* "a bare `Error::Conflict` literal, a `concat!`-split message"; R6-06.

* Scope: the production region (E) of the same file set as C (same two exact-key exclusions).
* On `normalise(…, Literals::Keep)` text (comments blanked, literals kept), lower-cased with all
  whitespace removed, neither stem `unsupportedonthis` nor `onthisplatform` may occur. Because a
  natural split keeps one stem whole inside one literal, this catches the contiguous phrase, any
  case or spacing variant, `concat!("… unsupported on this ", "platform")`, the same split for
  `format!`/`[..].concat()`, and a bare `Error::Conflict("… unsupported on this platform")`.
  Code tokens cannot form a stem (identifiers carry no spaces; the stems need three words).
* Failure message: `refusal text outside platform_support: <file>:<line>: <stem>`, all
  occurrences collected.
* It replaces `refusal_text_has_one_source` (P5), closing its file-name exemption.

### E. The production region is exact

*MANDATE words:* "every refusal occurrence in the tree".

* `production_region` (shared by C, D and the existing PGN call-graph pins through
  `for_each_production_region`) stops truncating at the first test module (P7). Instead it blanks
  exactly the braced body of every inline module whose attribute lines include one that is,
  whitespace-insensitively, `#[cfg(test)]` or begins `#[cfg(all(test,`; everything else in the
  file, before and after such a module, is production. `#[cfg(not(test))]` therefore no longer
  hides code.
* The returned text keeps byte offsets (blanked, not removed), so line numbers in C and D
  messages stay exact.
* The verifier file key is skipped by `for_each_production_region` (B pins it test-only).
* Verification level: the existing PGN pins stay green on the new region; staged S-after-tests and
  S-cfg-not-test (matrix) show what the old definition missed.

### F. Same-area cleanup in the guard-row verifier (rule 4b, not MANDATE)

* Remove `GuardRow.nested`, the nested-directory branch and the `"engine directory resources"`
  special case from `refusal_guards_are_first_statements_and_precede_their_effects` (dead since

## Proof selection (push-review-policy §2, "Proof selection before custom source verification")

* Behavioural/runtime route: the refusals only fire on non-unix targets; Windows tests run only on
  the CI runner, and a runtime test can observe an *existing* refusal but never the *absence of an
  unlisted* one. Completeness is a property of the source set, not of any one execution.
* Compiler route: considered and rejected as a substitute (Decisions, D-2) — a type-level
  registry cannot see an alias, a bare literal or the wording, and cannot tie a call site to a
  row.
* Existing source checks: P4-P7 show exactly which spellings they miss; this plan extends them
  rather than adding a parallel checker, and reuses the one shared lexer (`source_scan`).

## Decisions and trade-offs

* **D-1 (the open question): split verifier and subject (A).** Rejected: a separate `scripts/`
  checker with fixtures (a second lexer beside `infra/blocking.rs::source_scan`, whose header
  forbids a second copy, and a check that no longer runs in the Windows `cargo test` job);
  pinning the helpers from another module's test while the rest of the verifier stays in the
  subject file (B would then need a carve-out for a 2,900-line test module — the region heuristic
  E is repairing — and the subject file would still contain verifier logic for other
  assertions); argued assertions (the split makes them stageable at zero production change).
* **D-2: no compile-time registry.** An enum of refused operations passed to the helpers would
  change `d-20260914-05`'s helper API across all sites, still allow one variant at several call
  sites, and still miss a bare literal or an alias-free re-spelling of the wording; the source
  inventory (C) is still needed.
* **D-3: one multiset equality instead of counts plus uniqueness.** Derived from `guard_rows()`
  and the routed table, so adding a row automatically expects its call; every count path becomes
  stageable from production (closes R14-03).
* **D-4: two stems, not a literal-joining stream.** A per-file stream of joined literals invites
  cross-literal false matches and needs a second literal extractor; the stems catch every
  MANDATE-named split with the existing `Literals::Keep` normalisation.
* **D-5: whole-file subject pin replaces four helper pins.** One equality covers the four helpers
  and anything added beside them (the case P6 misses).
* **D-6: `BodyRow` machinery stays.** It is the documented home of a future body-form refusal pin
  (`ExpectedBody::Refusal` comment); C makes such a refusal visible, the row form pins its body.

## Threat model and non-goals

Frozen in round 1.

* **Adversary: none — accidental drift only.** The input is this repository's own production Rust
  source under `src-tauri/src/`, written by Felix's agents. The threat is a future change that adds,
  moves or re-spells a Windows refusal without adding or updating its pin, in a spelling an agent
  would naturally write. The MANDATE names the spellings that must be caught: a new
  `#[cfg(not(unix))]` site, `use … as`, a bare `Error::Conflict` literal, a `concat!`-split
  message; plus every helper-level change (new helper, changed body/format/visibility).
* **What "a refusal" is.** `d-20260914-05`: an unported Windows operation ends in
  `Error::Conflict("<operation> is|are unsupported on this platform")` built by
  `infra/platform_support.rs`. A refusal occurrence is therefore (a) any production reach of the
  helpers in that module, or (b) the refusal wording in a production string literal. An
  arbitrary Windows-gated error with *different* wording is not a refusal under that decision and
  is not detected (named limit L1 below).
* **Environments.** The assertions are platform-independent source checks; they execute in every
  `cargo test` run, Linux, macOS and the `rust-windows-test` job alike (`d-20260916-01` as
  reaffirmed by `d-20260916-06`).
* **Named limits (non-goals, recorded in the verifier header, not detected):**
  * L1 — an unported Windows path that returns an error with wording other than the refusal
    phrase. Rationale: `Error::Conflict(` occurs about 470 times in production regions; an
    allowlist of Windows-gated conflicts would record entries with no refusal semantics and could
    not tell a refusal from a legitimate identity conflict.
  * L2 — refusal wording assembled at run time from parts that are not string literals in source
    order (a variable holding text defined earlier in the file, text read from a data file);
    character-escape-encoded wording (`\x70latform`, `\u{70}`); wording generated by a
    procedural macro.
  * L3 — a string literal that spans a physical line break: the shared lexer
    (`infra/blocking.rs` `quoted_end`) stops a plain string at `\n` by design, so such a literal
    is not lexed as a literal. Changing the shared lexer is out of scope (it changes every scan
    that uses it).
  * L4 — the verifier's own compile gate. A `cfg` edit on the `mod tests;` declaration that
    compiles the verifier out on every platform removes all its assertions, B included. This is
    the same hazard the inline `#[cfg(test)] mod tests {` has at BASE (`platform_support.rs:332`);
    the existing observation is the post-push comparison of `infra::platform_support::tests::`
    line counts between the Linux run and `rust-windows-test` (`d-20260916-01`). Not worse than
    BASE, so no new mechanism here (round-1 issue F1-04).
  * These continue R6-06 as stated limitations; the MANDATE's named spellings are all inside the
    detected set.

## Approach

### A. Verifier and subject live in different files

*MANDATE words:* "how is a closed-world assertion over the refusals staged at all, given that its
own assertions live in `infra/platform_support.rs`"; "pin the helpers from a *different*
module's test".

* The whole test module of `infra/platform_support.rs` moves, unchanged in behaviour, to
  `src-tauri/src/infra/platform_support/tests.rs`, declared in the subject as
  `#[cfg(test)] mod tests;`. Test paths stay `infra::platform_support::tests::<name>`, so every
  external comment naming a test by path stays valid. Only the text changes that the move forces:
  one indentation level, every `include_str!` path gains one `../`, and the move-forced scan
  exclusion below.
* **Move-forced scan exclusion.** Three tree walkers in the moved module would read the verifier
  file itself once it is a separate file and report its own needle strings as production text:
  `refusal_text_has_one_source` (exempts by file *name* `platform_support.rs`; the moved
  `refusal_format_has_one_body` expected-body literal carries the phrase, BASE `:2950`),
  `routed_refusal_labels_are_unchanged`'s tree-wide count (whole files, `Literals::Keep`; the
  verifier's needle literals, BASE `:2244`, `:3107-3116`) and `for_each_production_region` (no
  `mod tests` inside the new file, so the whole file would count as production). In Phase 1 each
  of the three skips exactly the key `infra/platform_support/tests.rs`; Phase 2 replaces the first
  two outright (B, C, D) and keeps the skip in the third (E).
* The subject file afterwards holds only: a short `//!` pointer to the verifier, `use
  crate::error::Error;`, the four helpers, and `#[cfg(test)] mod tests;`. Its production text is
  unchanged.
* The module-doc staged-matrix record (`:1-309`) moves to the head of the verifier file: the
  record lives with the artefact it describes (push-review-policy §2).
* Comments elsewhere that say a pin lives "in `platform_support.rs`" are repointed to
  `infra/platform_support/tests.rs` (`infra/fs.rs:9281`, `:9526`; `infra/blocking.rs:25`;
  `infra/path_authority/resolved.rs:1141` if its wording names the file).
* **Why this answers the open question:** after the split, `infra/platform_support.rs` is an input
  the verifier reads through `include_str!`, not the verifier's logic, so the helper, visibility
  and own-file cases stage by editing it in a disposable worktree — the route P8 permits. R15-01's
  forbidden route disappears rather than being argued around.
* Verification level: behaviour-preserving move; the set of test names under
  `infra::platform_support::tests::` is identical before and after, and every test passes.

### B. The subject file is pinned whole

*MANDATE words:* "(1) the shared helpers … have no pinned declaration — an effect added inside
`refusal`, or a changed format, body or visibility"; R11-01.

* One assertion compares the whole of `infra/platform_support.rs` — comments blanked by
  `normalise(…, Literals::Keep)`, then `compact`ed — against one expected string. Any added,
  removed or changed item (a fifth helper, a re-export, a macro, a changed body, format string or
  visibility, a removed `#[cfg(test)]` on the `mod tests;` declaration) fails it; comment edits
  do not.
* Failure message (unique): `refusal subject changed: <compacted actual>`.
* It replaces `refusal_format_has_one_body` (P6), whose four `check_helper` pins and phrase count
  it subsumes; `check_helper` stays for its other callers.
* The `#[cfg(test)] mod tests;` declaration being part of the pinned text is what makes the
  verifier file test-only by construction; C and D rely on that to exclude it.

### C. Every production reach of the refusal helpers is a listed site

*MANDATE words:* "tying the G/B row tables to every refusal occurrence in the tree so that a
future unlisted, aliased … refusal (a new `#[cfg(not(unix))]` site, `use … as` …) cannot exist
unpinned"; R4-02; R14-03.

* Scope: the production region (E) of every `.rs` file under `src-tauri/src` except exactly the
  two keys `infra/platform_support.rs` (pinned whole by B) and `infra/platform_support/tests.rs`
  (test-only by B's pinned declaration). Exclusion is by `src`-relative key, never by file name.
* Every occurrence of the identifier token `platform_support` (found in `Literals::Blank` text, so
  comments and literals cannot fake or hide one) must be either the declaration
  `pub(crate) mod platform_support;` in `infra/mod.rs`, or a call of the exact form
  `crate::infra::platform_support::<helper>("<label>"` (whitespace-insensitive, trailing comma
  allowed) with `<helper>` one of `off_unix_refusal`, `unsupported`, `unsupported_plural` and
  `<label>` a single string literal read from the `Literals::Keep` text at the same offset (P11).
  Because every route to the helpers from another file must name the module, this one rule covers
  `use … as`, `use …::platform_support;`, globs, re-exports, `super::`-relative paths and a helper
  passed as a function value.
* Each valid call yields a tuple `(file key, enclosing named fn, helper, label)`. The multiset of
  tuples must equal the expected multiset built from `guard_rows()` (helper
  `off_unix_refusal`, label = the row's operation, fn = the name in the row's signature) plus one
  routed-row table holding today's single routed site (P2). No separate count or uniqueness
  assertion exists: a duplicated production call, a removed one, a moved one and a new one all
  surface as a multiset difference, so R14-03's "argued" count paths dissolve into staged ones.
* Failure messages, one per path, each naming file and line where one exists:
  * `refusal inventory: <file>:<line>: platform_support reference is not a qualified refusal call`
  * `refusal inventory: <file>:<line>: refusal label is not one string literal`
  * `refusal inventory: <file>:<line>: refusal call outside a named function`
  * `refusal inventory: unexpected refusal sites: [<tuples>]`
  * `refusal inventory: missing refusal sites: [<tuples>]`
  All failures of one run are collected and reported together.
* It replaces `production_off_unix_refusal_calls_match_guard_rows` and
  `routed_refusal_labels_are_unchanged` (P4), whose assertions it subsumes. The per-row guard
  checks (`refusal_guards_are_first_statements_and_precede_their_effects`) stay as they are; C
  decides *which* sites exist, the guard rows decide *how* each is placed.

### D. The refusal wording appears in no other production literal

*MANDATE words:* "a bare `Error::Conflict` literal, a `concat!`-split message"; R6-06.

* Scope: the production region (E) of the same file set as C (same two exact-key exclusions).
* **Literal stream.** The shared lexer module `infra/blocking.rs::source_scan` gains one function
  that returns the contents of every string literal (plain, raw, byte; comments skipped) with its
  byte offset, produced by the same lexing pass and delimiter functions `normalise` uses — no
  second copy of the delimiter logic (that module's header forbids one). `normalise`'s output
  does not change. For each file, the contents of all string literals in its production region
  are joined in source order into one stream, then: string-continuation escapes (`\` followed by
  a newline) and the escapes `\n`, `\r`, `\t` are dropped, every remaining whitespace character
  is dropped, every brace group without inner braces (a format placeholder such as `{}` or
  `{op}`) is dropped, and the result is lower-cased.
* The stream must not contain `unsupportedonthisplatform`. Because adjacent literals are joined
  without their delimiters, this catches the contiguous phrase, any case or spacing variant, a
  `concat!` split at **any** point (including `concat!("… unsupported on ", "this platform")`,
  round-1 issue F1-02), the same split through `format!` placeholders or `[..].concat()`, a raw or
  byte literal, a continuation-escaped long literal, and a bare
  `Error::Conflict("… unsupported on this platform")`.
* Failure message: `refusal text outside platform_support: <file>:<line>` with the line of the
  literal in which the matched phrase begins, all occurrences collected.
* The new lexer function gets its own unit tests beside the existing `source_scan` tests in
  `infra/blocking.rs`: plain, raw (`r#"…"#`), byte, escaped quote, a quote inside a comment, a
  `'"'` character literal, and offsets.
* It replaces `refusal_text_has_one_source` (P5), closing its file-name exemption.

### E. The production region is exact

*MANDATE words:* "every refusal occurrence in the tree".

* `production_region` (shared by C, D and the existing PGN call-graph pins through
  `for_each_production_region`) stops truncating at the first test module (P7). Instead it blanks
  exactly the braced body of every inline module whose attribute lines include one that is,
  whitespace-insensitively, `#[cfg(test)]` or begins `#[cfg(all(test,`; everything else in the
  file, before and after such a module, is production. `#[cfg(not(test))]` therefore no longer
  hides code.
* The returned text keeps byte offsets (blanked, not removed), so line numbers in C and D
  messages stay exact.
* The verifier file key is skipped by `for_each_production_region` (B pins it test-only).
* Verification level: the existing PGN pins stay green on the new region; staged S-after-tests and
  S-cfg-not-test (matrix) show what the old definition missed.

### F. Same-area cleanup in the guard-row verifier (rule 4b, not MANDATE)

* Remove `GuardRow.nested`, the nested-directory branch and the `"engine directory resources"`
  special case from `refusal_guards_are_first_statements_and_precede_their_effects` (dead since
  P3). No guard-row assertion reachable by a current row changes.

### G. Records

* The verifier header (moved record, A) gains this slice's paragraph: what C, D, B and E assert,
  the named limits L1-L4, the staged matrix below with every observed message and exit status, and
  the statement that **no assertion of B, C or D is argued** (or, if a path proves unstageable
  during implementation, it is named there as argued with its reason — never counted).
* The header sentence "Future closed-world completeness is not claimed here; that work is split to
  `f-20260916-01` (R15-01)" and the "four shared-helper pins … ARGUED, not staged" paragraph are
  replaced by the closed-world statement with its limits.

## Proof selection (push-review-policy §2, "Proof selection before custom source verification")

* Behavioural/runtime route: the refusals only fire on non-unix targets; Windows tests run only on
  the CI runner, and a runtime test can observe an *existing* refusal but never the *absence of an
  unlisted* one. Completeness is a property of the source set, not of any one execution.
* Compiler route: considered and rejected as a substitute (Decisions, D-2) — a type-level
  registry cannot see an alias, a bare literal or the wording, and cannot tie a call site to a
  row.
* Existing source checks: P4-P7 show exactly which spellings they miss; this plan extends them
  rather than adding a parallel checker, and reuses the one shared lexer (`source_scan`), adding
  one function to it rather than a second lexer.

## Decisions and trade-offs

* **D-1 (the open question): split verifier and subject (A).** Rejected: a separate `scripts/`
  checker with fixtures (a second lexer beside `infra/blocking.rs::source_scan`, whose header
  forbids a second copy, and a check that no longer runs in the Windows `cargo test` job);
  pinning the helpers from another module's test while the rest of the verifier stays in the
  subject file (B would then need a carve-out for a 2,900-line test module — the region heuristic
  E is repairing — and the subject file would still contain verifier logic for other
  assertions); argued assertions (the split makes them stageable at zero production change).
* **D-2: no compile-time registry.** An enum of refused operations passed to the helpers would
  change `d-20260914-05`'s helper API across all sites, still allow one variant at several call
  sites, and still miss a bare literal or an alias-free re-spelling of the wording; the source
  inventory (C) is still needed.
* **D-3: one multiset equality instead of counts plus uniqueness.** Derived from `guard_rows()`
  and the routed table, so adding a row automatically expects its call; every count path becomes
  stageable from production (closes R14-03).
* **D-4: a joined literal stream from the shared lexer, not stems over normalised text.** Round 1
  showed (F1-02) that whitespace-stripped `Literals::Keep` text keeps the `"`, `,` delimiters
  between `concat!` arguments, so a split at "unsupported on " / "this platform" kept neither
  stem whole; the MANDATE names `concat!` splits. Joining literal *contents* closes every split
  point. The cost is one additive function in `source_scan`, reusing its delimiter functions
  rather than adding a second lexer. A cross-literal false match needs consecutive literals that
  spell the phrase, which fails loud, never silent.
* **D-5: whole-file subject pin replaces four helper pins.** One equality covers the four helpers
  and anything added beside them (the case P6 misses).
* **D-6: `BodyRow` machinery stays.** It is the documented home of a future body-form refusal pin
  (`ExpectedBody::Refusal` comment); C makes such a refusal visible, the row form pins its body.

## Threat model and non-goals

Frozen in round 1.

* **Adversary: none — accidental drift only.** The input is this repository's own production Rust
  source under `src-tauri/src/`, written by Felix's agents. The threat is a future change that adds,
  moves or re-spells a Windows refusal without adding or updating its pin, in a spelling an agent
  would naturally write. The MANDATE names the spellings that must be caught: a new
  `#[cfg(not(unix))]` site, `use … as`, a bare `Error::Conflict` literal, a `concat!`-split
  message; plus every helper-level change (new helper, changed body/format/visibility).
* **What "a refusal" is.** `d-20260914-05`: an unported Windows operation ends in
  `Error::Conflict("<operation> is|are unsupported on this platform")` built by
  `infra/platform_support.rs`. A refusal occurrence is therefore (a) any production reach of the
  helpers in that module, or (b) the refusal wording in a production string literal. An
  arbitrary Windows-gated error with *different* wording is not a refusal under that decision and
  is not detected (named limit L1 below).
* **Environments.** The assertions are platform-independent source checks; they execute in every
  `cargo test` run, Linux, macOS and the `rust-windows-test` job alike (`d-20260916-01` as
  reaffirmed by `d-20260916-06`).
* **Named limits (non-goals, recorded in the verifier header, not detected):**
  * L1 — an unported Windows path that returns an error with wording other than the refusal
    phrase. Rationale: `Error::Conflict(` occurs about 470 times in production regions; an
    allowlist of Windows-gated conflicts would record entries with no refusal semantics and could
    not tell a refusal from a legitimate identity conflict.
  * L2 — refusal wording assembled at run time from parts that are not string literals in source
    order (a variable holding text defined earlier in the file, text read from a data file);
    character-escape-encoded wording (`\x70latform`, `\u{70}`); wording generated by a
    procedural macro; a `format!` whose wording is split so that neither stem stays inside one
    literal **and** another literal sits between the parts in source order (for example
    `format!("{} is unsupported on {}", "x", "this platform")`) — catching that would need a
    `format!` evaluator.
  * L3 — a string literal that spans a physical line break: the shared lexer
    (`infra/blocking.rs` `quoted_end`) stops a plain string at `\n` by design, so such a literal
    is not lexed as a literal. Changing the shared lexer is out of scope (it changes every scan
    that uses it).
  * L4 — the verifier's own compile gate. A `cfg` edit on the `mod tests;` declaration that
    compiles the verifier out on every platform removes all its assertions, B included. This is
    the same hazard the inline `#[cfg(test)] mod tests {` has at BASE (`platform_support.rs:332`);
    the existing observation is the post-push comparison of `infra::platform_support::tests::`
    line counts between the Linux run and `rust-windows-test` (`d-20260916-01`). Not worse than
    BASE, so no new mechanism here (round-1 issue F1-04).
  * These continue R6-06 as stated limitations; the MANDATE's named spellings are all inside the
    detected set.

## Approach

### A. Verifier and subject live in different files

*MANDATE words:* "how is a closed-world assertion over the refusals staged at all, given that its
own assertions live in `infra/platform_support.rs`"; "pin the helpers from a *different*
module's test".

* The whole test module of `infra/platform_support.rs` moves, unchanged in behaviour, to
  `src-tauri/src/infra/platform_support/tests.rs`, declared in the subject as
  `#[cfg(test)] mod tests;`. Test paths stay `infra::platform_support::tests::<name>`, so every
  external comment naming a test by path stays valid. Only the text changes that the move forces:
  one indentation level, every `include_str!` path gains one `../`, and the move-forced scan
  exclusion below.
* **Move-forced scan exclusion.** Three tree walkers in the moved module would read the verifier
  file itself once it is a separate file and report its own needle strings as production text:
  `refusal_text_has_one_source` (exempts by file *name* `platform_support.rs`; the moved
  `refusal_format_has_one_body` expected-body literal carries the phrase, BASE `:2950`),
  `routed_refusal_labels_are_unchanged`'s tree-wide count (whole files, `Literals::Keep`; the
  verifier's needle literals, BASE `:2244`, `:3107-3116`) and `for_each_production_region` (no
  `mod tests` inside the new file, so the whole file would count as production). In Phase 1 each
  of the three skips exactly the key `infra/platform_support/tests.rs`; Phase 2 replaces the first
  two outright (B, C, D) and keeps the skip in the third (E).
* The subject file afterwards holds only: a short `//!` pointer to the verifier, `use
  crate::error::Error;`, the four helpers, and `#[cfg(test)] mod tests;`. Its production text is
  unchanged.
* The module-doc staged-matrix record (`:1-309`) moves to the head of the verifier file: the
  record lives with the artefact it describes (push-review-policy §2).
* Comments elsewhere that say a pin lives "in `platform_support.rs`" are repointed to
  `infra/platform_support/tests.rs` (`infra/fs.rs:9281`, `:9526`; `infra/blocking.rs:25`;
  `infra/path_authority/resolved.rs:1141` if its wording names the file).
* **Why this answers the open question:** after the split, `infra/platform_support.rs` is an input
  the verifier reads through `include_str!`, not the verifier's logic, so the helper, visibility
  and own-file cases stage by editing it in a disposable worktree — the route P8 permits. R15-01's
  forbidden route disappears rather than being argued around.
* Verification level: behaviour-preserving move; the set of test names under
  `infra::platform_support::tests::` is identical before and after, and every test passes.

### B. The subject file is pinned whole

*MANDATE words:* "(1) the shared helpers … have no pinned declaration — an effect added inside
`refusal`, or a changed format, body or visibility"; R11-01.

* One assertion compares the whole of `infra/platform_support.rs` — comments blanked by
  `normalise(…, Literals::Keep)`, then `compact`ed — against one expected string. Any added,
  removed or changed item (a fifth helper, a re-export, a macro, a changed body, format string or
  visibility, a removed `#[cfg(test)]` on the `mod tests;` declaration) fails it; comment edits
  do not.
* Failure message (unique): `refusal subject changed: <compacted actual>`.
* It replaces `refusal_format_has_one_body` (P6), whose four `check_helper` pins and phrase count
  it subsumes; `check_helper` stays for its other callers.
* The `#[cfg(test)] mod tests;` declaration being part of the pinned text is what makes the
  verifier file test-only by construction; C and D rely on that to exclude it.

### C. Every production reach of the refusal helpers is a listed site

*MANDATE words:* "tying the G/B row tables to every refusal occurrence in the tree so that a
future unlisted, aliased … refusal (a new `#[cfg(not(unix))]` site, `use … as` …) cannot exist
unpinned"; R4-02; R14-03.

* Scope: the production region (E) of every `.rs` file under `src-tauri/src` except exactly the
  two keys `infra/platform_support.rs` (pinned whole by B) and `infra/platform_support/tests.rs`
  (test-only by B's pinned declaration). Exclusion is by `src`-relative key, never by file name.
* Every occurrence of the identifier token `platform_support` (found in `Literals::Blank` text, so
  comments and literals cannot fake or hide one) must be either the declaration
  `pub(crate) mod platform_support;` in `infra/mod.rs`, or a call of the exact form
  `crate::infra::platform_support::<helper>("<label>"` (whitespace-insensitive, trailing comma
  allowed) with `<helper>` one of `off_unix_refusal`, `unsupported`, `unsupported_plural` and
  `<label>` a single string literal read from the `Literals::Keep` text at the same offset (P11).
  Because every route to the helpers from another file must name the module, this one rule covers
  `use … as`, `use …::platform_support;`, globs, re-exports, `super::`-relative paths and a helper
  passed as a function value.
* Each valid call yields a tuple `(file key, enclosing named fn, helper, label)`. The multiset of
  tuples must equal the expected multiset built from `guard_rows()` (helper
  `off_unix_refusal`, label = the row's operation, fn = the name in the row's signature) plus one
  routed-row table holding today's single routed site (P2). No separate count or uniqueness
  assertion exists: a duplicated production call, a removed one, a moved one and a new one all
  surface as a multiset difference, so R14-03's "argued" count paths dissolve into staged ones.
* Failure messages, one per path, each naming file and line where one exists:
  * `refusal inventory: <file>:<line>: platform_support reference is not a qualified refusal call`
  * `refusal inventory: <file>:<line>: refusal label is not one string literal`
  * `refusal inventory: <file>:<line>: refusal call outside a named function`
  * `refusal inventory: unexpected refusal sites: [<tuples>]`
  * `refusal inventory: missing refusal sites: [<tuples>]`
  All failures of one run are collected and reported together.
* It replaces `production_off_unix_refusal_calls_match_guard_rows` and
  `routed_refusal_labels_are_unchanged` (P4), whose assertions it subsumes. The per-row guard
  checks (`refusal_guards_are_first_statements_and_precede_their_effects`) stay as they are; C
  decides *which* sites exist, the guard rows decide *how* each is placed.

### D. The refusal wording appears in no other production literal

*MANDATE words:* "a bare `Error::Conflict` literal, a `concat!`-split message"; R6-06.

* Scope: the production region (E) of the same file set as C (same two exact-key exclusions).
* **Literal contents.** The shared lexer module `infra/blocking.rs::source_scan` gains one
  function that returns the contents of every string literal (plain, raw, byte; comments
  skipped) with its byte offset, produced by the same lexing pass and delimiter functions
  `normalise` uses — no second copy of the delimiter logic (that module's header forbids one).
  `normalise`'s output does not change. Each content is *folded*: string-continuation escapes
  (`\` followed by a newline) and the escapes `\n`, `\r`, `\t` are dropped, every remaining
  whitespace character is dropped, and the result is lower-cased.
* **Two checks over the production region of each file, both required** (each closes cases the
  other misses — F1-02 and F2-01):
  * D-stem: no single folded literal contains `unsupportedonthis` or `onthisplatform`. Catches
    the contiguous phrase, any case or spacing variant, a bare
    `Error::Conflict("… unsupported on this platform")`, a raw, byte or continuation-escaped
    literal, and every split that keeps one stem inside one literal — including a `format!` that
    moves a word into an argument (`format!("{} is unsupported on this {}", "staged",
    "platform")`, F2-01).
  * D-joined: the folded contents of all literals of the file, joined in source order with
    nothing between them, do not contain `unsupportedonthisplatform`. Catches a split at any
    point between literals that are adjacent in source order, such as
    `concat!("… unsupported on ", "this platform")` (F1-02), which keeps neither stem whole.
* Failure messages, all occurrences collected:
  `refusal text outside platform_support: <file>:<line>: stem <stem>` (line of that literal) and
  `refusal text outside platform_support: <file>:<line>: joined phrase` (line of the literal in
  which the joined phrase begins).
* The new lexer function gets its own unit tests beside the existing `source_scan` tests in
  `infra/blocking.rs`: plain, raw (`r#"…"#`), byte, escaped quote, a quote inside a comment, a
  `'"'` character literal, and offsets.
* It replaces `refusal_text_has_one_source` (P5), closing its file-name exemption.

### E. The production region is exact

*MANDATE words:* "every refusal occurrence in the tree".

* `production_region` (shared by C, D and the existing PGN call-graph pins through
  `for_each_production_region`) stops truncating at the first test module (P7). Instead it blanks
  exactly the braced body of every inline module whose attribute lines include one that is,
  whitespace-insensitively, `#[cfg(test)]` or begins `#[cfg(all(test,`; everything else in the
  file, before and after such a module, is production. `#[cfg(not(test))]` therefore no longer
  hides code.
* The returned text keeps byte offsets (blanked, not removed), so line numbers in C and D
  messages stay exact.
* The verifier file key is skipped by `for_each_production_region` (B pins it test-only).
* Verification level: the existing PGN pins stay green on the new region; staged S-after-tests and
  S-cfg-not-test (matrix) show what the old definition missed.

## Proof selection (push-review-policy §2, "Proof selection before custom source verification")

* Behavioural/runtime route: the refusals only fire on non-unix targets; Windows tests run only on
  the CI runner, and a runtime test can observe an *existing* refusal but never the *absence of an
  unlisted* one. Completeness is a property of the source set, not of any one execution.
* Compiler route: considered and rejected as a substitute (Decisions, D-2) — a type-level
  registry cannot see an alias, a bare literal or the wording, and cannot tie a call site to a
  row.
* Existing source checks: P4-P7 show exactly which spellings they miss; this plan extends them
  rather than adding a parallel checker, and reuses the one shared lexer (`source_scan`), adding
  one function to it rather than a second lexer.

## Decisions and trade-offs

* **D-1 (the open question): split verifier and subject (A).** Rejected: a separate `scripts/`
  checker with fixtures (a second lexer beside `infra/blocking.rs::source_scan`, whose header
  forbids a second copy, and a check that no longer runs in the Windows `cargo test` job);
  pinning the helpers from another module's test while the rest of the verifier stays in the
  subject file (B would then need a carve-out for a 2,900-line test module — the region heuristic
  E is repairing — and the subject file would still contain verifier logic for other
  assertions); argued assertions (the split makes them stageable at zero production change).
* **D-2: no compile-time registry.** An enum of refused operations passed to the helpers would
  change `d-20260914-05`'s helper API across all sites, still allow one variant at several call
  sites, and still miss a bare literal or an alias-free re-spelling of the wording; the source
  inventory (C) is still needed.
* **D-3: one multiset equality instead of counts plus uniqueness.** Derived from `guard_rows()`
  and the routed table, so adding a row automatically expects its call; every count path becomes
  stageable from production (closes R14-03).
* **D-4: per-literal stems plus a joined literal stream, both over literal contents from the
  shared lexer.** Round 1 showed (F1-02) that stems over whitespace-stripped `Literals::Keep`
  text miss a `concat!` split at "unsupported on " / "this platform", because the `"`, `,`
  delimiters stay between the parts; the MANDATE names `concat!` splits. Round 2 showed (F2-01)
  that a joined stream alone misses a `format!` that moves "platform" into an argument after
  another argument, which the stems catch. Neither check subsumes the other, so both stay; no
  format-placeholder stripping is needed once the stems carry the `format!` cases. The cost is
  one additive function in `source_scan`, reusing its delimiter functions rather than adding a
  second lexer. A cross-literal false match needs consecutive literals that spell the phrase,
  which fails loud, never silent.
* **D-5: whole-file subject pin replaces four helper pins.** One equality covers the four helpers
  and anything added beside them (the case P6 misses).
* **D-6: `BodyRow` machinery stays.** It is the documented home of a future body-form refusal pin
  (`ExpectedBody::Refusal` comment); C makes such a refusal visible, the row form pins its body.

## Threat model and non-goals

Frozen in round 1.

* **Adversary: none — accidental drift only.** The input is this repository's own production Rust
  source under `src-tauri/src/`, written by Felix's agents. The threat is a future change that adds,
  moves or re-spells a Windows refusal without adding or updating its pin, in a spelling an agent
  would naturally write. The MANDATE names the spellings that must be caught: a new
  `#[cfg(not(unix))]` site, `use … as`, a bare `Error::Conflict` literal, a `concat!`-split
  message; plus every helper-level change (new helper, changed body/format/visibility).
* **What "a refusal" is.** `d-20260914-05`: an unported Windows operation ends in
  `Error::Conflict("<operation> is|are unsupported on this platform")` built by
  `infra/platform_support.rs`. A refusal occurrence is therefore (a) any production reach of the
  helpers in that module, or (b) the refusal wording in a production string literal. An
  arbitrary Windows-gated error with *different* wording is not a refusal under that decision and
  is not detected (named limit L1 below).
* **Environments.** The assertions are platform-independent source checks; they execute in every
  `cargo test` run, Linux, macOS and the `rust-windows-test` job alike (`d-20260916-01` as
  reaffirmed by `d-20260916-06`).
* **Named limits (non-goals, recorded in the verifier header, not detected):**
  * L1 — an unported Windows path that returns an error with wording other than the refusal
    phrase. Rationale: `Error::Conflict(` occurs about 470 times in production regions; an
    allowlist of Windows-gated conflicts would record entries with no refusal semantics and could
    not tell a refusal from a legitimate identity conflict.
  * L2 — refusal wording assembled at run time from parts that are not string literals in source
    order (a variable holding text defined earlier in the file, text read from a data file);
    character-escape-encoded wording (`\x70latform`, `\u{70}`); wording generated by a
    procedural macro; a `format!` whose wording is split so that neither stem stays inside one
    literal **and** another literal sits between the parts in source order (for example
    `format!("{} is unsupported on {}", "x", "this platform")`) — catching that would need a
    `format!` evaluator.
  * L3 — a string literal that spans a physical line break: the shared lexer
    (`infra/blocking.rs` `quoted_end`) stops a plain string at `\n` by design, so such a literal
    is not lexed as a literal. Changing the shared lexer is out of scope (it changes every scan
    that uses it).
  * L4 — the verifier's own compile gate. A `cfg` edit on the `mod tests;` declaration that
    compiles the verifier out on every platform removes all its assertions, B included. This is
    the same hazard the inline `#[cfg(test)] mod tests {` has at BASE (`platform_support.rs:332`);
    the existing observation is the post-push comparison of `infra::platform_support::tests::`
    line counts between the Linux run and `rust-windows-test` (`d-20260916-01`). Not worse than
    BASE, so no new mechanism here (round-1 issue F1-04).

    detected set.

### D. The refusal wording appears in no other production literal

*MANDATE words:* "a bare `Error::Conflict` literal, a `concat!`-split message"; R6-06.

* **Literal contents.** The shared lexer module `infra/blocking.rs::source_scan` gains one

  skipped) with its byte offset, produced by the same lexing pass and delimiter functions
  `normalise` uses — no second copy of the delimiter logic (that module's header forbids one).
  `normalise`'s output does not change. Each content is *folded*: string-continuation escapes
  (`\` followed by a newline) and the escapes `\n`, `\r`, `\t` are dropped, every remaining
  whitespace character is dropped, and the result is lower-cased.

  other misses — F1-02 and F2-01):

    moves a word into an argument (`format!("{} is unsupported on this {}", "staged",

## Proof selection (push-review-policy §2, "Proof selection before custom source verification")

* Behavioural/runtime route: the refusals only fire on non-unix targets; Windows tests run only on
  the CI runner, and a runtime test can observe an *existing* refusal but never the *absence of an
  unlisted* one. Completeness is a property of the source set, not of any one execution.
* Compiler route: considered and rejected as a substitute (Decisions, D-2) — a type-level
  registry cannot see an alias, a bare literal or the wording, and cannot tie a call site to a
  row.
* Existing source checks: P4-P7 show exactly which spellings they miss; this plan extends them
  rather than adding a parallel checker, and reuses the one shared lexer (`source_scan`), adding
  one function to it rather than a second lexer.

## Decisions and trade-offs

* **D-1 (the open question): split verifier and subject (A).** Rejected: a separate `scripts/`
  checker with fixtures (a second lexer beside `infra/blocking.rs::source_scan`, whose header
  forbids a second copy, and a check that no longer runs in the Windows `cargo test` job);
  pinning the helpers from another module's test while the rest of the verifier stays in the
  subject file (B would then need a carve-out for a 2,900-line test module — the region heuristic
  E is repairing — and the subject file would still contain verifier logic for other
  assertions); argued assertions (the split makes them stageable at zero production change).
* **D-2: no compile-time registry.** An enum of refused operations passed to the helpers would
  change `d-20260914-05`'s helper API across all sites, still allow one variant at several call
  sites, and still miss a bare literal or an alias-free re-spelling of the wording; the source
  inventory (C) is still needed.
* **D-3: one multiset equality instead of counts plus uniqueness.** Derived from `guard_rows()`
  and the routed table, so adding a row automatically expects its call; every count path becomes
  stageable from production (closes R14-03).
* **D-4: per-literal stems plus a joined literal stream, both over literal contents from the
  shared lexer.** Round 1 showed (F1-02) that stems over whitespace-stripped `Literals::Keep`
  text miss a `concat!` split at "unsupported on " / "this platform", because the `"`, `,`
  delimiters stay between the parts; the MANDATE names `concat!` splits. Round 2 showed (F2-01)
  that a joined stream alone misses a `format!` that moves "platform" into an argument after
  another argument, which the stems catch. Neither check subsumes the other, so both stay; no
  format-placeholder stripping is needed once the stems carry the `format!` cases. The cost is
  one additive function in `source_scan`, reusing its delimiter functions rather than adding a
  second lexer. A cross-literal false match needs consecutive literals that spell the phrase,
  which fails loud, never silent.
* **D-5: whole-file subject pin replaces four helper pins.** One equality covers the four helpers
  and anything added beside them (the case P6 misses).
* **D-6: `BodyRow` machinery stays.** It is the documented home of a future body-form refusal pin
  (`ExpectedBody::Refusal` comment); C makes such a refusal visible, the row form pins its body.
