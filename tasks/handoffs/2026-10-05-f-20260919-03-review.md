# Plan: f-20260919-03 — download commits and archive installs through a pinned parent

## Goal

The download core in `src-tauri/src/fs.rs` stops creating destination parents and stops
replacing the destination file by pathname. Every commit it makes (plain file, plain gzip,
zip/tar/tar-in-gzip tree install) happens relative to one parent directory descriptor pinned
once per call. `fs.rs`'s counted filesystem surface shrinks from 7 to 1; the one reach left is
the download payload reader that `f-20260919-02` owns.

## MANDATE

## Threat model and non-goals

Frozen in round 1.

* **In scope (accidental and hostile namespace races):** another process renames, removes or
  replaces the parent directory of the core's target between the moment the core starts
  committing and the moment the commit lands. The guarantee is: every byte and every directory
  the core commits lands under the one parent it pinned, or the call fails closed
  (`Error::Conflict` or an I/O error) with nothing installed at the target leaf. A removed
  parent is never recreated.
* **Environments:** Linux, macOS, Windows. The pin uses the same parent-open primitive the
  pathname commit already uses on each platform (traced premise P6), so no platform gains or
  loses a refusal.
* **Out of scope:** an adversary that can already write inside the pinned 0700 staging
  directory; the pathname readers of the committed payload after the core returns
  (`f-20260919-02`); publication of the engine tree onto its authority-resolved target
  (`ResolvedPath`, `infra/path_authority`); the outer staging directories themselves
  (`tempfile::tempdir()` for downloads, `private_tempdir_in(".archive", …)` for engine
  archives, `d-20260918-11`).

## Approach

### O1 — One shared pinned-leaf type in `infra/fs.rs`

MANDATE words: "go through an existing dest descriptor (… `open_parent_no_follow` + … /
descriptor-relative replace)".

`NativeExportDest` becomes the shared type `PinnedLeaf` (rule 11: the download target is its
second instance, P5). Contract:

* Holds only a no-follow-opened parent `File` and a single-component leaf; it never stores a
  pathname.
* `PinnedLeaf::pin(path)` is the general constructor: refuses a path without a single-component
  leaf (`single_leaf`), then opens the parent with `open_parent_no_follow`. It creates nothing.
* `PinnedLeaf::from_save_path(path, expected_extension)` keeps `d-20260919-06`'s export
  constructor unchanged in behaviour: extension check first, before anything is opened, then
  the same pin.
* `replace(write_fn)` commits with `atomic_replace_at` on the held parent.
* The parent's identity and the leaf are readable for the archive install (O3).
* `save_native_export_blocking` keeps its behaviour; only the type name at its call site and
  the strings of its existing source pin (`main.rs` test) change.

### O2 — The core commits plain and plain-gzip payloads through the pin, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core pins `path` once, at the start of its blocking commit closure, before format
  detection. Every commit in that call uses that one pin. The pin is dropped when the closure
  returns; the network download itself holds no directory handle (D1).
* Plain payload: `PinnedLeaf::replace`, same write loop, same cancellation checks, same
  `require_durable(…, ArchiveFileReplacement)`.
* Plain gzip (`extract_gz_cancellable`, non-tar): `PinnedLeaf::replace`, same bounded copy and
  ratio check, same `require_durable(…, GzipFileReplacement)`.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a parent rename after the pin no longer yields the pathname precommit's
  `Conflict`; the commit lands in the pinned directory (P7, same as `d-20260919-06`). A missing
  or symlinked parent fails at the pin, before any byte is written. Errors keep their existing
  types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned leaf, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* `create_private_dir_all` and its three calls are deleted (D2).
* `extract_zip_cancellable`, `extract_tar_cancellable` and the tar-in-gzip branch of
  `extract_gz_cancellable` receive the pin from O2 as their install destination.
* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created
  by the tempfile crate in the parent's pathname (P8, D4). The binding to the pin is the existing
  identity check, moved from a pathname reopen to the pin: before
  `install_owned_staging_dir`, the inner tree's held parent identity must equal the pin's parent
  identity, otherwise `Error::Conflict("archive staging parent changed concurrently")` and nothing
  is installed. `install_extracted_tree` therefore no longer opens any pathname.
* `archive_install_names` keeps its refusal of archive payloads outside process-owned staging
  (`"archive extract needs process-owned staging"`, `"archive target does not match its
  staging"`); its derived names are no longer needed as the install target, because the pin is.
* Cancellation, limits, member validation and cleanup-on-error behaviour are unchanged
  (`OwnedStagingDir` drop removes the inner leaf by identity under its own held parent).

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the callers.** The callers keep
  their signatures; the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle; and `f-20260919-02`'s open question (what the download caller holds for its
  readers) is not decided here.
* **D2 — delete the mkdirs instead of converting them.** Every production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — rename `NativeExportDest` to `PinnedLeaf` and add `pin`**, keeping `from_save_path` and
  every property `d-20260919-06` chose. The new evidence is the second instance (rule 11).
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The checker count is the structural guard; behaviour is
  pinned by V2–V4.

Frozen in round 1.

* **In scope (accidental and hostile namespace races):** another process renames, removes or

## Approach

### O1 — One shared pinned-leaf type in `infra/fs.rs`

MANDATE words: "go through an existing dest descriptor (… `open_parent_no_follow` + … /
descriptor-relative replace)".

`NativeExportDest` becomes the shared type `PinnedLeaf` (rule 11: the download target is its
second instance, P5). Contract:

* Holds only a no-follow-opened parent `File` and a single-component leaf; it never stores a
  pathname.
* `PinnedLeaf::pin(path)` is the general constructor: refuses a path without a single-component
  leaf (`single_leaf`), then opens the parent with `open_parent_no_follow`. It creates nothing.
* `PinnedLeaf::from_save_path(path, expected_extension)` keeps `d-20260919-06`'s export
  constructor unchanged in behaviour: extension check first, before anything is opened, then
  the same pin.
* `replace(write_fn)` commits with `atomic_replace_at` on the held parent.
* The parent's identity and the leaf are readable for the archive install (O3).
* `save_native_export_blocking` keeps its behaviour; only the type name at its call site and
  the strings of its existing source pin (`main.rs` test) change.

### O2 — The core commits plain and plain-gzip payloads through the pin, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core pins `path` once, at the start of its blocking commit closure, before format
  detection. Every commit in that call uses that one pin. The pin is dropped when the closure
  returns; the network download itself holds no directory handle (D1).
* Plain payload: `PinnedLeaf::replace`, same write loop, same cancellation checks, same
  `require_durable(…, ArchiveFileReplacement)`.
* Plain gzip (`extract_gz_cancellable`, non-tar): `PinnedLeaf::replace`, same bounded copy and
  ratio check, same `require_durable(…, GzipFileReplacement)`.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a parent rename after the pin no longer yields the pathname precommit's
  `Conflict`; the commit lands in the pinned directory (P7, same as `d-20260919-06`). A missing
  or symlinked parent fails at the pin, before any byte is written. Errors keep their existing
  types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned leaf, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* `create_private_dir_all` and its three calls are deleted (D2).
* `extract_zip_cancellable`, `extract_tar_cancellable` and the tar-in-gzip branch of
  `extract_gz_cancellable` receive the pin from O2 as their install destination.
* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created
  by the tempfile crate in the parent's pathname (P8, D4). The binding to the pin is the existing
  identity check, moved from a pathname reopen to the pin: before
  `install_owned_staging_dir`, the inner tree's held parent identity must equal the pin's parent
  identity, otherwise `Error::Conflict("archive staging parent changed concurrently")` and nothing
  is installed. `install_extracted_tree` therefore no longer opens any pathname.
* `archive_install_names` keeps its refusal of archive payloads outside process-owned staging
  (`"archive extract needs process-owned staging"`, `"archive target does not match its
  staging"`); its derived names are no longer needed as the install target, because the pin is.
* Cancellation, limits, member validation and cleanup-on-error behaviour are unchanged
  (`OwnedStagingDir` drop removes the inner leaf by identity under its own held parent).

* After O2 and O3, `fs.rs` has no `create_dir_all`, no `DirBuilder`, no pathname

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the callers.** The callers keep
  their signatures; the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle; and `f-20260919-02`'s open question (what the download caller holds for its
  readers) is not decided here.
* **D2 — delete the mkdirs instead of converting them.** Every production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — rename `NativeExportDest` to `PinnedLeaf` and add `pin`**, keeping `from_save_path` and
  every property `d-20260919-06` chose. The new evidence is the second instance (rule 11).
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The checker count is the structural guard; behaviour is
  pinned by V2–V4 and V6.

## Threat model and non-goals

Frozen in round 1.

* **In scope (accidental and hostile namespace races):** another process renames, removes or
  replaces the parent directory of the core's target between the moment the core starts
  committing and the moment the commit lands. The guarantee is: every byte and every directory
  the core commits lands under the one parent it pinned, or the call fails closed
  (`Error::Conflict` or an I/O error) with nothing installed at the target leaf. A removed
  parent is never recreated.
* **Environments:** Linux, macOS, Windows. The pin uses the same parent-open primitive the
  pathname commit already uses on each platform (traced premise P6), so no platform gains or
  loses a refusal.
* **Out of scope:** an adversary that can already write inside the pinned 0700 staging
  directory; the pathname readers of the committed payload after the core returns
  (`f-20260919-02`); publication of the engine tree onto its authority-resolved target
  (`ResolvedPath`, `infra/path_authority`); the outer staging directories themselves

  archives, `d-20260918-11`).

## Approach

### O1 — One shared pinned-leaf type in `infra/fs.rs`

MANDATE words: "go through an existing dest descriptor (… `open_parent_no_follow` + … /
descriptor-relative replace)".

`NativeExportDest` becomes the shared type `PinnedLeaf` (rule 11: the download target is its
second instance, P5). Contract:

* Holds only a no-follow-opened parent `File` and a single-component leaf; it never stores a
  pathname.
* `PinnedLeaf::pin(path)` is the general constructor: refuses a path without a single-component
  leaf (`single_leaf`), then opens the parent with `open_parent_no_follow`. It creates nothing.
* `PinnedLeaf::from_save_path(path, expected_extension)` keeps `d-20260919-06`'s export
  constructor unchanged in behaviour: extension check first, before anything is opened, then
  the same pin.
* `replace(write_fn)` commits with `atomic_replace_at` on the held parent.
* The parent's identity and the leaf are readable for the archive install (O3).
* `save_native_export_blocking` keeps its behaviour; only the type name at its call site and
  the strings of its existing source pin (`main.rs` test) change.

### O2 — The core commits plain and plain-gzip payloads through the pin, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core pins `path` once, at the start of its blocking commit closure, before format
  detection. Every commit in that call uses that one pin. The pin is dropped when the closure
  returns; the network download itself holds no directory handle (D1).
* Plain payload: `PinnedLeaf::replace`, same write loop, same cancellation checks, same
  `require_durable(…, ArchiveFileReplacement)`.
* Plain gzip (`extract_gz_cancellable`, non-tar): `PinnedLeaf::replace`, same bounded copy and
  ratio check, same `require_durable(…, GzipFileReplacement)`.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a parent rename after the pin no longer yields the pathname precommit's
  `Conflict`; the commit lands in the pinned directory (P7, same as `d-20260919-06`). A missing
  or symlinked parent fails at the pin, before any byte is written. Errors keep their existing
  types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned leaf, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* `create_private_dir_all` and its three calls are deleted (D2).
* `extract_zip_cancellable`, `extract_tar_cancellable` and the tar-in-gzip branch of
  `extract_gz_cancellable` receive the pin from O2 as their install destination.
* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created
  by the tempfile crate in the parent's pathname (P8, D4). The binding to the pin is the existing
  identity check, moved from a pathname reopen to the pin: before
  `install_owned_staging_dir`, the inner tree's held parent identity must equal the pin's parent
  identity, otherwise `Error::Conflict("archive staging parent changed concurrently")` and nothing
  is installed. `install_extracted_tree` therefore no longer opens any pathname.
* `archive_install_names` keeps its refusal of archive payloads outside process-owned staging
  (`"archive extract needs process-owned staging"`, `"archive target does not match its
  staging"`); its derived names are no longer needed as the install target, because the pin is.
* Cancellation, limits, member validation and cleanup-on-error behaviour are unchanged
  (`OwnedStagingDir` drop removes the inner leaf by identity under its own held parent).

### O4 — The surface count records the shrink

MANDATE words: "`fs.rs` counted surface is 7".

* After O2 and O3, `fs.rs` has no `create_dir_all`, no `DirBuilder`, no pathname
  `atomic_replace` call and no `atomic_replace` import. `INITIAL_FS_SURFACE_COUNTS` for

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the callers.** The callers keep
  their signatures; the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle; and `f-20260919-02`'s open question (what the download caller holds for its
  readers) is not decided here.
* **D2 — delete the mkdirs instead of converting them.** Every production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — rename `NativeExportDest` to `PinnedLeaf` and add `pin`**, keeping `from_save_path` and
  every property `d-20260919-06` chose. The new evidence is the second instance (rule 11).
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The checker count is the structural guard; behaviour is
  pinned by V2–V4 and V6.

## Approach

### O1 — One shared pinned-leaf type in `infra/fs.rs`

MANDATE words: "go through an existing dest descriptor (… `open_parent_no_follow` + … /
descriptor-relative replace)".

`NativeExportDest` becomes the shared type `PinnedLeaf` (rule 11: the download target is its
second instance, P5). Contract:

* Holds only a no-follow-opened parent `File` and a single-component leaf; it never stores a
  pathname.
* `PinnedLeaf::pin(path)` is the general constructor: refuses a path without a single-component
  leaf (`single_leaf`), then opens the parent with `open_parent_no_follow`. It creates nothing.
* `PinnedLeaf::from_save_path(path, expected_extension)` keeps `d-20260919-06`'s export
  constructor unchanged in behaviour: extension check first, before anything is opened, then
  the same pin.
* `replace(write_fn)` commits with `atomic_replace_at` on the held parent.
* The parent's identity and the leaf are readable for the archive install (O3).
* `save_native_export_blocking` keeps its behaviour; only the type name at its call site and
  the strings of its existing source pin (`main.rs` test) change.

### O2 — The core commits plain and plain-gzip payloads through the pin, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core pins `path` once, at the start of its blocking commit closure, before format
  detection. Every commit in that call uses that one pin. The pin is dropped when the closure
  returns; the network download itself holds no directory handle (D1).
* Plain payload: `PinnedLeaf::replace`, same write loop, same cancellation checks, same
  `require_durable(…, ArchiveFileReplacement)`.
* Plain gzip (`extract_gz_cancellable`, non-tar): `PinnedLeaf::replace`, same bounded copy and
  ratio check, same `require_durable(…, GzipFileReplacement)`.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a parent rename after the pin no longer yields the pathname precommit's
  `Conflict`; the commit lands in the pinned directory (P7, same as `d-20260919-06`). A missing
  or symlinked parent fails at the pin, before any byte is written. Errors keep their existing
  types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned leaf, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the callers.** The callers keep
  their signatures; the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle; and `f-20260919-02`'s open question (what the download caller holds for its
  readers) is not decided here.
* **D2 — delete the mkdirs instead of converting them.** Every production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — rename `NativeExportDest` to `PinnedLeaf` and add `pin`**, keeping `from_save_path` and
  every property `d-20260919-06` chose. The new evidence is the second instance (rule 11).
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The checker count is the structural guard; behaviour is
  pinned by V2–V4 and V6.

## Approach

### O1 — One shared pinned-leaf type in `infra/fs.rs`

MANDATE words: "go through an existing dest descriptor (… `open_parent_no_follow` + … /
descriptor-relative replace)".

`NativeExportDest` becomes the shared type `PinnedLeaf` (rule 11: the download target is its
second instance, P5). Contract:

* Holds only a no-follow-opened parent `File` and a single-component leaf; it never stores a
  pathname.
* `PinnedLeaf::pin(path)` is the general constructor: refuses a path without a single-component
  leaf (`single_leaf`), then opens the parent with `open_parent_no_follow`. It creates nothing.
* `PinnedLeaf::from_save_path(path, expected_extension)` keeps `d-20260919-06`'s export
  constructor unchanged in behaviour: extension check first, before anything is opened, then
  the same pin.
* `replace(write_fn)` commits with `atomic_replace_at` on the held parent.
* The parent's identity and the leaf are readable for the archive install (O3).
* `save_native_export_blocking` keeps its behaviour; only the type name at its call site and
  the strings of its existing source pin (`main.rs` test) change.

### O2 — The core commits plain and plain-gzip payloads through the pin, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core pins `path` once, at the start of its blocking commit closure, before format
  detection. Every commit in that call uses that one pin. The pin is dropped when the closure
  returns; the network download itself holds no directory handle (D1).
* Plain payload: `PinnedLeaf::replace`, same write loop, same cancellation checks, same
  `require_durable(…, ArchiveFileReplacement)`.
* Plain gzip (`extract_gz_cancellable`, non-tar): `PinnedLeaf::replace`, same bounded copy and
  ratio check, same `require_durable(…, GzipFileReplacement)`.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a parent rename after the pin no longer yields the pathname precommit's
  `Conflict`; the commit lands in the pinned directory (P7, same as `d-20260919-06`). A missing
  or symlinked parent fails at the pin, before any byte is written. Errors keep their existing
  types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned leaf, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* `create_private_dir_all` and its three calls are deleted (D2).
* `extract_zip_cancellable`, `extract_tar_cancellable` and the tar-in-gzip branch of
  `extract_gz_cancellable` receive the pin from O2 as their install destination.
* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created
  by the tempfile crate in the parent's pathname (P8, D4). The binding to the pin is the existing
  identity check, moved from a pathname reopen to the pin: before
  `install_owned_staging_dir`, the inner tree's held parent identity must equal the pin's parent
  identity, otherwise `Error::Conflict("archive staging parent changed concurrently")` and nothing
  is installed. `install_extracted_tree` therefore no longer opens any pathname.
* `archive_install_names` keeps its refusal of archive payloads outside process-owned staging
  (`"archive extract needs process-owned staging"`, `"archive target does not match its
  staging"`); its derived names are no longer needed as the install target, because the pin is.
* Cancellation, limits, member validation and cleanup-on-error behaviour are unchanged
  (`OwnedStagingDir` drop removes the inner leaf by identity under its own held parent).

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the callers.** The callers keep
  their signatures; the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle; and `f-20260919-02`'s open question (what the download caller holds for its
  readers) is not decided here.
* **D2 — delete the mkdirs instead of converting them.** Every production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — rename `NativeExportDest` to `PinnedLeaf` and add `pin`**, keeping `from_save_path` and
  every property `d-20260919-06` chose. The new evidence is the second instance (rule 11).
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The checker count is the structural guard; behaviour is
  pinned by V2–V4 and V6.

## Threat model and non-goals

Frozen in round 1.

* **In scope (accidental and hostile namespace races):** another process renames, removes or

  the core commits lands under the one parent it pinned, or the call fails closed

  parent is never recreated.
* **Environments:** Linux, macOS, Windows. The pin uses the same parent-open primitive the
  pathname commit already uses on each platform (traced premise P6), so no platform gains or
  loses a refusal.
* **Out of scope:** an adversary that can already write inside the pinned 0700 staging
  directory; the pathname readers of the committed payload after the core returns
  (`f-20260919-02`); publication of the engine tree onto its authority-resolved target
  (`ResolvedPath`, `infra/path_authority`); the outer staging directories themselves
  (`tempfile::tempdir()` for downloads, `private_tempdir_in(".archive", …)` for engine
  archives, `d-20260918-11`).

## Approach

### O1 — (withdrawn in r5) shared `PinnedLeaf` type

Withdrawn by the r5 correction of R5-02: its only reason was the core's plain-file commit as the
second instance of `NativeExportDest`'s pinned-leaf replace (rule 11), and P9 shows that commit
has no production success path. `NativeExportDest`, `main.rs` and `d-20260919-06` are untouched.

### O2 — The core pins its target's parent once, refuses non-archive payloads, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core opens its target's parent once with `open_parent_no_follow(path)` at the start of its
  blocking commit closure, before format detection, and holds that `File` (the pin) for the
  rest of the closure. Every archive install in that call is bound to that one pin (O3). The pin
  is dropped when the closure returns; the network download itself holds no directory handle
  (D1). The pin creates nothing.
* A payload that is not an archive — a plain payload, or a gzip payload whose decompressed head
  is not a ustar header — is refused with one fixed `Error::InvalidInput` (no path in the
  message) before anything is written at or beside the target. The core's plain-file tail and
  `extract_gz_cancellable`'s plain-gzip branch are deleted, not converted (D3). The existing
  refusal of an archive payload for a non-`Archive` op class
  (`"Archive payload is not allowed for this operation"`) is unchanged.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a missing or symlinked parent fails at the `.download` buffer or the pin,
  before any byte is committed. Errors keep their existing types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned parent, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* `create_private_dir_all` and its three calls are deleted (D2).
* `extract_zip_cancellable`, `extract_tar_cancellable` and the tar-in-gzip path of
  `extract_gz_cancellable` receive the pin from O2 together with the target leaf as their
  install destination.
* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created
  by the tempfile crate in the parent's pathname (P8, D4). The binding to the pin is the existing
  identity check, moved from a pathname reopen to the pin: before
  `install_owned_staging_dir`, the inner tree's held parent identity must equal the pin's
  identity, otherwise `Error::Conflict("archive staging parent changed concurrently")` and nothing
  is installed. `install_extracted_tree` therefore no longer opens any pathname.
* `archive_install_names` keeps its refusal of archive payloads outside process-owned staging
  (`"archive extract needs process-owned staging"`, `"archive target does not match its
  staging"`); its derived names are no longer needed as the install parent, because the pin is.
* Cancellation, limits, member validation and cleanup-on-error behaviour are unchanged
  (`OwnedStagingDir` drop removes the inner leaf by identity under its own held parent).

### O4 — `fs.rs` leaves the filesystem-surface allowlist

MANDATE words: "`fs.rs` counted surface is 7. Emptying the allowlist entry waits on dest-parent
mkdir and dest-file replace".

* After O2 and O3, `fs.rs` has no `create_dir_all`, no `DirBuilder`, no `atomic_replace` call and

* No change to the checker's rules: `PATHNAME_FNS`, `FS_FN_NAMES` and the allowlist mechanism

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the caller.** The caller keeps
  its signature, and the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle.
* **D2 — delete the mkdirs instead of converting them.** The production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — delete the plain-file and plain-gzip commits instead of pinning them** (r5, replaces
  the withdrawn rename of `NativeExportDest`). After `f-20260919-02` the core's one production
  caller can only reach those commits with a directory target that the driver refuses (P9), so a
  descriptor-relative replace would convert a branch that only tests can complete and would
  rename a type for a second instance with no production success path. An explicit refusal
  states the contract the caller already depends on, as `d-20261005-02` did for the payload
  route in the opposite direction.
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The emptied checker baseline is the structural guard;
  behaviour is pinned by V2–V4 and V6.

# Plan: f-20260919-03 — download commits and archive installs through a pinned parent

## Goal

The download core in `src-tauri/src/fs.rs` stops creating destination parents and stops
replacing a destination file by pathname. Its archive installs (zip, raw tar, tar-in-gzip) happen
relative to one parent directory descriptor pinned once per call; the plain-file and plain-gzip
commits, which no production caller can complete since `f-20260919-02` moved the payload route
off the core, are deleted and refused. `fs.rs`'s counted filesystem surface shrinks from 6 to 0
and `fs.rs` leaves the filesystem-surface allowlist.

## MANDATE

Verbatim, `f-20260919-03`:

* **Where:** `src-tauri/src/fs.rs:563` and `:685` (`std::fs::create_dir_all` of a destination parent in `download_file_core_control_with_integrity` when `path` is not a tempfile leaf), `:686` (`atomic_replace` of that dest file), `:1375` (`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents at `:1471`, `:1532`, `:1639`), `:1641` (`atomic_replace` in `extract_gz_cancellable`), plus the R4 import of `atomic_replace` at `:20`.
* **Defect:** after `f-20260905-08` removed inner tempfile `OpenOptions`, these counted sites remain. They name destination parents or destination files, not the process-owned inner extract tree. `create_private_dir_all` exists only for those dest parents. `d-20260901-03` already recorded that `PathRef` cannot represent every destination; `f-20260905-09` owns the save-dialog case separately.
* **Why it matters:** `fs.rs` counted surface is 7. Emptying the allowlist entry waits on dest-parent mkdir and dest-file replace (and on the download-staging follow-on when those lines are the tempfile caller).
* **Related:** `f-20260905-08` (split out of; Root `-`). `f-20260905-09` (dialog dest). `d-20260901-03`.
* **Open question:** Should dest-parent mkdir and dest-file `atomic_replace` in `fs.rs` go through an existing dest descriptor (`ResolvedPath` / `open_parent_no_follow` + `ensure_directory_at` / descriptor-relative replace), or does a remaining pathname helper stay because some callers have no held parent?

## Threat model and non-goals

Frozen in round 1.

* **In scope (accidental and hostile namespace races):** another process renames, removes or
  replaces the parent directory of the core's target between the moment the core starts
  committing and the moment the commit lands. The guarantee is: every byte and every directory
  the core commits lands under the one parent it pinned, or the call fails closed
  (`Error::Conflict` or an I/O error) with nothing installed at the target leaf. A removed
  parent is never recreated.
* **Environments:** Linux, macOS, Windows. The pin uses the same parent-open primitive the
  pathname commit already uses on each platform (traced premise P6), so no platform gains or
  loses a refusal.
* **Out of scope:** an adversary that can already write inside the pinned 0700 staging
  directory; the pathname readers of the committed payload after the core returns
  (`f-20260919-02`); publication of the engine tree onto its authority-resolved target
  (`ResolvedPath`, `infra/path_authority`); the outer staging directories themselves
  (`tempfile::tempdir()` for downloads, `private_tempdir_in(".archive", …)` for engine
  archives, `d-20260918-11`).

## Approach

### O1 — (withdrawn in r5) shared `PinnedLeaf` type

Withdrawn by the r5 correction of R5-02: its only reason was the core's plain-file commit as the
second instance of `NativeExportDest`'s pinned-leaf replace (rule 11), and P9 shows that commit
has no production success path. `NativeExportDest`, `main.rs` and `d-20260919-06` are untouched.

### O2 — The core pins its target's parent once, refuses non-archive payloads, and creates no parent

MANDATE words: "dest-parent mkdir and dest-file `atomic_replace` in `fs.rs`".

* The core opens its target's parent once with `open_parent_no_follow(path)` at the start of its
  blocking commit closure, before format detection, and holds that `File` (the pin) for the
  rest of the closure. Every archive install in that call is bound to that one pin (O3). The pin
  is dropped when the closure returns; the network download itself holds no directory handle
  (D1). The pin creates nothing.
* A payload that is not an archive — a plain payload, or a gzip payload whose decompressed head
  is not a ustar header — is refused with one fixed `Error::InvalidInput` (no path in the
  message). The refusal installs nothing at the destination and leaves no temporary leaf beside
  it (the network stage's `.download` buffer is unnamed by then). The core's plain-file tail and
  `extract_gz_cancellable`'s plain-gzip branch are deleted, not converted (D3). The existing
  refusal of an archive payload for a non-`Archive` op class
  (`"Archive payload is not allowed for this operation"`) is unchanged.
* The two `DurabilityStage` variants that only the deleted commits constructed
  (`ArchiveFileReplacement`, `GzipFileReplacement`, P11) are removed with them — enum, `Display`
  arms and label-list test entries — and `src/bindings/generated.ts` is regenerated with
  `pnpm bindings:generate`, never hand-edited. No renderer code names them; no command or event
  changes.
* Both `std::fs::create_dir_all(target_dir)` calls are deleted, not converted (D2). A parent that
  no longer exists is an I/O failure, and nothing recreates it.
* Failure semantics: a missing or symlinked parent fails at the `.download` buffer or the pin,
  before any byte is committed. Errors keep their existing types; no new message carries a path.

### O3 — Archive extraction installs onto the pinned parent, and creates no parent

MANDATE words: "`DirBuilder` in `create_private_dir_all` for zip/tar/gz dest parents".

* `create_private_dir_all` and its three calls are deleted (D2).
* `extract_zip_cancellable`, `extract_tar_cancellable` and the tar-in-gzip path of
  `extract_gz_cancellable` receive the pin from O2 together with the target leaf as their
  install destination.
* The inner staging directory and the tar-in-gzip buffer stay process-private temporaries created
  by the tempfile crate in the parent's pathname (P8, D4). The binding to the pin is the existing
  identity check, moved from a pathname reopen to the pin: before
  `install_owned_staging_dir`, the inner tree's held parent identity must equal the pin's
  identity, otherwise `Error::Conflict("archive staging parent changed concurrently")` and nothing
  is installed. `install_extracted_tree` therefore no longer opens any pathname.
* `archive_install_names` keeps its refusal of archive payloads outside process-owned staging
  (`"archive extract needs process-owned staging"`, `"archive target does not match its
  staging"`); its derived names are no longer needed as the install parent, because the pin is.
* Cancellation, limits, member validation and cleanup-on-error behaviour are unchanged
  (`OwnedStagingDir` drop removes the inner leaf by identity under its own held parent).

### O4 — `fs.rs` leaves the filesystem-surface allowlist

MANDATE words: "`fs.rs` counted surface is 7. Emptying the allowlist entry waits on dest-parent
mkdir and dest-file replace".

* After O2 and O3, `fs.rs` has no `create_dir_all`, no `DirBuilder`, no `atomic_replace` call and

* The checker's "cleared files" pin gains `src-tauri/src/fs.rs`, so re-adding it to both

* No change to the checker's rules: `PATHNAME_FNS`, `FS_FN_NAMES` and the allowlist mechanism

## Decisions and trade-offs

* **D1 — pin inside the core's blocking commit closure, not in the caller.** The caller keeps
  its signature, and the network download (up to `DOWNLOAD_DEADLINE`, one hour) holds no
  directory handle.
* **D2 — delete the mkdirs instead of converting them.** The production target's parent is a
  directory the caller created moments earlier (P2, P3). Converting to `ensure_directory_at`
  would need a held ancestor that no caller has and would recreate a directory that was removed
  concurrently — recreating it is itself the unauthorized write.
* **D3 — delete the plain-file and plain-gzip commits instead of pinning them** (r5, replaces
  the withdrawn rename of `NativeExportDest`). After `f-20260919-02` the core's one production
  caller can only reach those commits with a directory target that the driver refuses (P9), so a
  descriptor-relative replace would convert a branch that only tests can complete and would
  rename a type for a second instance with no production success path. An explicit refusal
  states the contract the caller already depends on, as `d-20261005-02` did for the payload
  route in the opposite direction.
* **D4 — process-private temporaries stay tempfile-crate creations in the parent's pathname.**
  They are uncounted by design (`d-20260901-03`, P8); the inner tree is bound to the pin by
  identity before it is installed, so a pathname swap fails closed. A descriptor-relative
  temporary-creation primitive would turn that `Conflict` into a success inside the pinned
  directory, which no MANDATE obligation needs.
* **D5 — no new source-scan test.** The emptied checker baseline is the structural guard;
  behaviour is pinned by V2–V4 and V6.
