* **ID:** f-20260926-07 · **Status:** open · **Area:** engine-uci · **Root:** - · **Entry:** build · **Blocked:** none

## Approach

### O1. Ownership after committed abort

Authority: MANDATE "local guard from removal until ... finish_retired ... completed, spawning the same remainder on drop" and "keeping its Ok + log-not-return contract".

Reuse and generalize the existing removed-session retirement owner for replacement and abort. The owner is armed synchronously after successful exact removal, before the first subsequent await. Do not arm it before removal commits. Its cleanup is the existing finish_retired sequence, including unconditional exact termination even when another caller took the loop join handle. Keep it armed until both join and direct termination have completed, disarming on completion whether cleanup succeeded or failed. Dropping the abort future transfers the same remainder to the existing asynchronous drop path. Replacement keeps its current return semantics. Abort retains stale-session and failed-commit refusal, returns Ok once committed, and reports a completed cleanup failure once through the keyed game-level retirement log. Share the owner and completion/logging implementation across both removed-session callers rather than duplicating a second domain contract. Existing per-generation failure logs and renderer-safe aggregate errors stand.

Proof level: portable behavioral backend tests through the actual manager methods and shared guard. The held-controller cancellation case proves signal, join consumption, tombstone, both exact generations gone and unrelated generation survival. Check owns_generation, not just get_exact, since teardown moves actors into pending ownership. A failed-termination abort proves Ok plus one retirement entry and per-generation diagnostic evidence. Exercise abort cancellation after join handle acquisition as well, preserving restoration before the remainder finishes. Cancellation before removal and a stale expected session must leave the current game and its engines untouched. Existing replacement cancellation and failure tests remain green.

### O2. Shutdown retry requires cleanup

Authority: MANDATE "next call ... empty join slot ... retires the session without terminating anything" and "switch shutdown_all's per-session call to finish_retired".

Each shutdown session attempt awaits finish_retired before its existing success-based retirement. A cancelled attempt retains the session in GameManager for retry. An empty join slot is never cleanup evidence. Keep manager sealing, registration barrier, snapshot discipline, repeated collection and failure aggregation. Do not add a removed-session drop owner to a session still published in games. Preserve exact-session removal so natural completion or a different session cannot be removed by stale teardown. Keep the configured budgets and supervisor semantics unchanged. Update the nearby shutdown comment to reflect unconditional exact cleanup.

Proof level: portable behavioral tests cancel shutdown after a pending loop timed out, the join slot emptied and both delayed terminations started. Before retry, verify the same session remains reachable. Retry must finish both exact generations before retiring it, with shutdown signal true, join slot empty and unrelated actor alive. Observe the state at the retirement boundary, not just eventual generation absence. Existing no-op, sealing, slipped-session collection, stuck-loop error and parallel supervisor termination cases remain green. Retain the first non-cancelled timeout/error aggregation behavior.

## Approach

### O1. Ownership after committed abort

Authority: MANDATE "local guard from removal until ... finish_retired ... completed, spawning the same remainder on drop" and "keeping its Ok + log-not-return contract".

Do not arm it before removal commits. Its cleanup is the existing finish_retired sequence, including unconditional exact termination even when another caller took the loop join handle. Keep it armed until both join and direct termination have completed, disarming on completion whether cleanup succeeded or failed. Dropping the abort future transfers the same remainder to the existing asynchronous drop path. Replacement keeps its current return semantics. Abort retains stale-session and failed-commit refusal, returns Ok once committed, and reports a completed cleanup failure once through the keyed game-level retirement log. Share the owner and completion/logging implementation across both removed-session callers rather than duplicating a second domain contract. ### O2. Shutdown retry requires cleanup

Authority: MANDATE "next call ... empty join slot ... retires the session without terminating anything" and "switch shutdown_all's per-session call to finish_retired".
