### core-join-ceiling

Claim: the round-1 plan changed the interactive-stop core join from 2 s to 12 s and proved it with a hook delay after `release_rx` and a hook that never returns. Those controls cannot reach the timed join.

Witnesses:

- lens `plan`, round 1, finding 1, blocker. Raw: `[blocker] /tmp/drain-plan-drain-90a2aa88-slot0/build/plan-r1.md:108 — The core-join controls cannot exercise the changed ceiling. start_interactive_search holds the lifecycle lock at src-tauri/src/engine/process.rs:2229 while awaiting warm.start at line 2315, which awaits this hook at src-tauri/src/chess.rs:199. Meanwhile, stop_generation must acquire that same lock at src-tauri/src/engine/process.rs:2523. The test awaits stop at src-tauri/src/chess.rs:4816 before starting the core timeout at line 4818. Consequently, the four-second hook delay finishes before the timed join begins, so it cannot fail the old ceiling. Making the hook never return, as prescribed at plan line 110, instead hangs at the untimed stop.await. Replace these controls with a completion stall after lifecycle release and verify that the missing-completion control reaches the timed join. (confidence: 100)`
- lens `correctness`, round 1, finding 1, blocker. Raw: `[blocker] /tmp/drain-plan-drain-90a2aa88-slot0/build/plan-r1.md:108 — The core-join producer cannot outlast stop.await as specified. start_interactive_search holds the lifecycle lock while awaiting this hook, and stop_generation acquires that same lock before returning. A four-second hook delay therefore finishes before the core timeout starts. Keeping the hook pending, as line 110 requires, hangs at the unbounded stop.await instead of producing the required timeout failure. The proposed observation boundary disagrees with the caller’s execution order. (confidence: 100)`

Disposition: Fix. The requested post-release stall was not adopted. Source shows the cancellation path returns through `?` when the lifecycle lock drops, so no in-flight core remains for that stall unless production code drops the lock and then sleeps. That would time a path with no production work. The join stays at 2 s. The entered and cancelled-flag waits stay at 5 s, with producers that run before the lock is taken by stop.

MANDATE obligation: check whether each named timeout is the contract, and raise only bounds that measure ordering.

## Approach

### Class answer

The repair is narrowed option 1. A wait whose job is to observe an event, and whose following asserts are ordering, cancellation, bytes, or terminal state, is a safety ceiling. It moves to the event-observation ceiling already used beside it. A number that is the product deadline, the operation timeout passed into production code, a sleep that must outlast a deadline, a speed or budget assert, or a promptness expect stays at its current value.

Option 2 is rejected. The heavy-gate lock already admits this gate, and foreign pytest or vitest are outside this repo. Another flock on `heavy-gate.lock` is forbidden. Option 3 is rejected. No PSI threshold exists, and a pressure refusal would not tell the tree from the machine either. Local Rust lanes are already serial, so restoring or further serializing them is not this repair. `d-20261023-12` rejects a pressure gate and gate serialization as the wall-clock fix.

### Event-observation ceiling

Five seconds, written inline at the call site as `Duration::from_secs(5)`. This matches the existing wire-capture observation, the chesscom progress and drain waits, and the `BoundedHook` release wait. Do not add a cross-crate helper or a new named constant. Each site is one literal. A shared helper would be a new abstraction with no second contract.

The interactive-stop core join is the actor-completion ceiling: twelve seconds, inline, matching the existing real-child cleanup join in the same file. The entered wait and the cancelled-flag poll in that test stay on the five-second event ceiling. They wait for a signal, not for actor teardown.

### Duration contracts that stay

These values are the contract and do not change:

- Every duration passed into `run_owned_export`, including 2 s and 500 ms.
- The 600 ms sleep that lets the 500 ms staging deadline expire before release.
- `staging_deadline_fails_terminally_without_publication`, including both of its 2 s waits. It is the same shape of entered wait and is intentionally not swept. Its task timeout expects `Error::EngineTimeout` from the 500 ms operation deadline.
- `MULTI_PREDECESSOR_COMPLETION_BOUND` (1050 ms) and the assert that each predecessor received a fresh retirement budget.
- `SIGNAL_TIMEOUT` (10 s). It is already the shared hang ceiling. One unexplained miss is not authority to raise it.
- `COMPLETION_BOUND` where it is the retirement speed contract.
- `shutdown_cancel_case`'s 2 s expect "shutdown must cancel the blocked worker".
- Production engine deadlines (readyok 10 s, quit 3 s, kill/reap 2 s) and `POOL_CONNECTION_TIMEOUT` (30 s).
- `SHORT_POOL_CONNECTION_TIMEOUT` and the test that uses it.

### Proof pattern

For each changed wait, in order, on a disposable edit that is restored byte-for-byte before the phase commit:

1. Put a healthy delay longer than the old ceiling on the producer side of that wait. The unrepaired ceiling fails. After the ceiling change, the same delay passes, and the test's existing semantic asserts still pass.
2. Remove the delay. The test passes with no injected sleep.
3. Omit the signal the wait exists to observe. The test still fails. Restore the send.

The committed tree contains no injected sleep and no new fault API. The delay and the missing signal are local uncommitted edits. If a delay is consumed before the timed section starts, move that disposable delay so it still falls inside the timed wait. Do not commit the relocation.

The entered producer for interactive stop is the body of `set_interactive_before_go_hook`, before `entered_tx.send`. The cancelled-flag producer is the start of the spawned `stop_generation` task. The core-join producer is work after `release_rx` resolves and before the hook returns; the delay must still be running when the core timeout starts, so it has to outlast `stop.await`. Use four seconds there. The chesscom producer is the send inside `HoldAtomicPoint::inject`, and the probe runs only the three named tests before restoring the function. The file-workspace producer is the send inside `BoundedHook::notify_and_wait`, and the probe runs only the named workspace test before restoring that function byte-for-byte. `pgn.rs` is not a committed file.

Missing-signal controls: do not send `entered` for the entered waits; do not call `stop_generation` for the cancelled-flag wait; do not let the hook return after release for the core join; do not send from `HoldAtomicPoint::inject`; do not send from `notify_and_wait`. Each must fail, then the function is restored.

### Failure, ownership, and integration

Failure stays the existing timeout error. `unwrap`, `expect`, or `?` on `Elapsed` remains a test failure. There is no retry, no new error variant, and no conversion of timeout into success. A missing event still fails closed. A late but healthy event within the new ceiling is success only when the existing semantic asserts pass.

Ownership does not change. These are cfg(test) waits on oneshots the tests already own. No production task, engine child, pool, or cancellation token gains a new owner or a longer deadline.

Integration boundary: the tests observe the same channels they observe today. No command, event, capability, or stored key changes.

### Verification level

Phase proof is the filtered `cargo test` for that phase, plus the disposable delay and missing-signal controls above, with the proof output recorded and the disposable edits removed. A green run without the delay does not prove the ceiling moved. The delay control is what fails on the old ceiling and passes on the new one. The missing-signal control is what stays red.

Local proof is Linux. The literals are not `cfg`-gated. The adopter's pre-review `pnpm rust:windows:check` is the local Windows compile check and does not run Windows tests. Hosted runtime proof after push is `rust-windows-test` and `rust-macos-test`. No `target_os = "freebsd"` probe is required because no `cfg(target_os)` line changes. Final `pnpm gates:push -- --rust` belongs to the adopter's gate step, not to a phase proof.

## Approach

### Class answer

The repair is narrowed option 1. A wait whose job is to observe an event, and whose following asserts are ordering, cancellation, bytes, or terminal state, is a safety ceiling. It moves to the event-observation ceiling already used beside it. A number that is the product deadline, the operation timeout passed into production code, a sleep that must outlast a deadline, a speed or budget assert, or a promptness expect stays at its current value.

Option 2 is rejected. The heavy-gate lock already admits this gate, and foreign pytest or vitest are outside this repo. Another flock on `heavy-gate.lock` is forbidden. Option 3 is rejected. No PSI threshold exists, and a pressure refusal would not tell the tree from the machine either. Local Rust lanes are already serial, so restoring or further serializing them is not this repair. `d-20261023-12` rejects a pressure gate and gate serialization as the wall-clock fix.

### Event-observation ceiling

Five seconds, written inline at the call site as `Duration::from_secs(5)`. This matches the existing wire-capture observation, the chesscom progress and drain waits, and the `BoundedHook` release wait. Do not add a cross-crate helper or a new named constant. Each site is one literal. A shared helper would be a new abstraction with no second contract.

The interactive-stop entered wait and cancelled-flag poll use that five-second ceiling. They observe signals while the before-go hook still holds the lifecycle lock. The core join stays at two seconds. It is not an event ceiling: it starts only after stop has taken that lock and returned, and on this cancellation path the core task has already returned. Widening it would not be reached by a hook delay or by a hook that never returns.

### Proof pattern

For each changed wait, in order, on a disposable edit that is restored byte-for-byte before the phase commit:

1. Put a healthy delay longer than the old ceiling on the producer side of that wait. The unrepaired ceiling fails. After the ceiling change, the same delay passes, and the test's existing semantic asserts still pass.
2. Remove the delay. The test passes with no injected sleep.
3. Omit the signal the wait exists to observe. The test still fails. Restore the send.

The committed tree contains no injected sleep and no new fault API. The delay and the missing signal are local uncommitted edits. If a delay is consumed before the timed section starts, move that disposable delay so it still falls inside the timed wait. Do not commit the relocation.

The entered producer for interactive stop is the body of `set_interactive_before_go_hook`, before `entered_tx.send`. The cancelled-flag producer is the start of the spawned stop task, before `stop_generation` is called. Do not delay inside the hook after `release_rx`, and do not withhold the hook's return, as a control for the core join. That join is not changed. The chesscom producer is the send inside `HoldAtomicPoint::inject`, and the probe runs only the three named tests before restoring the function. The file-workspace producer is the send inside `BoundedHook::notify_and_wait`, and the probe runs only the named workspace test before restoring that function byte-for-byte. `pgn.rs` is not a committed file.

Missing-signal controls: do not send `entered` for the entered waits; do not call `stop_generation` for the cancelled-flag wait; do not send from `HoldAtomicPoint::inject`; do not send from `notify_and_wait`. Each must fail, then the function is restored. There is no missing-completion control for the unchanged core join.

### Failure, ownership, and integration

Failure stays the existing timeout error. `unwrap`, `expect`, or `?` on `Elapsed` remains a test failure. There is no retry, no new error variant, and no conversion of timeout into success. A missing event still fails closed. A late but healthy event within the new ceiling is success only when the existing semantic asserts pass.

Ownership does not change. These are cfg(test) waits on oneshots the tests already own. No production task, engine child, pool, or cancellation token gains a new owner or a longer deadline.

Integration boundary: the tests observe the same channels they observe today. No command, event, capability, or stored key changes.

### Verification level

Phase proof is the filtered `cargo test` for that phase, plus the disposable delay and missing-signal controls above, with the proof output recorded and the disposable edits removed. A green run without the delay does not prove the ceiling moved. The delay control is what fails on the old ceiling and passes on the new one. The missing-signal control is what stays red.

Local proof is Linux `cargo test`. Phase 1's test is already `#[cfg(unix)]` and stays that way, so `rust-windows-test` does not run it. Its non-Linux runtime proof is `rust-macos-test`. No `target_os = "freebsd"` probe is required because no `cfg(target_os)` line changes. Final `pnpm gates:push -- --rust` belongs to the adopter's gate step, not to a phase proof.

## Approach

### Class answer

The repair is narrowed option 1. A wait whose job is to observe an event, and whose following asserts are ordering, cancellation, bytes, or terminal state, is a safety ceiling. It moves to the event-observation ceiling already used beside it. A number that is the product deadline, the operation timeout passed into production code, a sleep that must outlast a deadline, a speed or budget assert, or a promptness expect stays at its current value.

Option 2 is rejected. The heavy-gate lock already admits this gate, and foreign pytest or vitest are outside this repo. Another flock on `heavy-gate.lock` is forbidden. Option 3 is rejected. No PSI threshold exists, and a pressure refusal would not tell the tree from the machine either. Local Rust lanes are already serial, so restoring or further serializing them is not this repair. `d-20261023-12` rejects a pressure gate and gate serialization as the wall-clock fix.

### Event-observation ceiling

Five seconds, written inline at the call site as `Duration::from_secs(5)`. This matches the existing wire-capture observation, the chesscom progress and drain waits, and the `BoundedHook` release wait. Do not add a cross-crate helper or a new named constant. Each site is one literal. A shared helper would be a new abstraction with no second contract.

The interactive-stop entered wait and cancelled-flag poll use that five-second ceiling. They observe signals while the before-go hook still holds the lifecycle lock. The core join stays at two seconds. It is not an event ceiling: it starts only after stop has taken that lock and returned, and on this cancellation path the core task has already returned. Widening it would not be reached by a hook delay or by a hook that never returns.

### Duration contracts that stay

These values are the contract and do not change:

- Every duration passed into `run_owned_export`, including 2 s and 500 ms.
- The 600 ms sleep that lets the 500 ms staging deadline expire before release.
- `staging_deadline_fails_terminally_without_publication`, including both of its 2 s waits. It is the same shape of entered wait and is intentionally not swept. Its task timeout expects `Error::EngineTimeout` from the 500 ms operation deadline.
- `MULTI_PREDECESSOR_COMPLETION_BOUND` (1050 ms) and the assert that each predecessor received a fresh retirement budget.
- `SIGNAL_TIMEOUT` (10 s). It is already the shared hang ceiling. One unexplained miss is not authority to raise it.
- `COMPLETION_BOUND` where it is the retirement speed contract.
- `shutdown_cancel_case`'s 2 s expect "shutdown must cancel the blocked worker".
- The interactive-stop core join, which stays at 2 s.
- Production engine deadlines (readyok 10 s, quit 3 s, kill/reap 2 s) and `POOL_CONNECTION_TIMEOUT` (30 s).
- `SHORT_POOL_CONNECTION_TIMEOUT` and the test that uses it.

### Proof pattern

For each changed wait, in order, on a disposable edit that is restored byte-for-byte before the phase commit:

1. Put a healthy delay longer than the old ceiling on the producer side of that wait. The unrepaired ceiling fails. After the ceiling change, the same delay passes, and the test's existing semantic asserts still pass.
2. Remove the delay. The test passes with no injected sleep.
3. Omit the signal the wait exists to observe. The test still fails. Restore the send.

The committed tree contains no injected sleep and no new fault API. The delay and the missing signal are local uncommitted edits. If a delay is consumed before the timed section starts, move that disposable delay so it still falls inside the timed wait. Do not commit the relocation.

The entered producer for interactive stop is the body of `set_interactive_before_go_hook`, before `entered_tx.send`. The cancelled-flag producer is the start of the spawned stop task, before `stop_generation` is called. Do not delay inside the hook after `release_rx`, and do not withhold the hook's return, as a control for the core join. That join is not changed. The chesscom producer is the send inside `HoldAtomicPoint::inject`, and the probe runs only the three named tests before restoring the function. The file-workspace producer is the send inside `BoundedHook::notify_and_wait`, and the probe runs only the named workspace test before restoring that function byte-for-byte. `pgn.rs` is not a committed file.

Missing-signal controls: do not send `entered` for the entered waits; do not call `stop_generation` for the cancelled-flag wait; do not send from `HoldAtomicPoint::inject`; do not send from `notify_and_wait`. Each must fail, then the function is restored. There is no missing-completion control for the unchanged core join.

### Failure, ownership, and integration

Failure stays the existing timeout error. `unwrap`, `expect`, or `?` on `Elapsed` remains a test failure. There is no retry, no new error variant, and no conversion of timeout into success. A missing event still fails closed. A late but healthy event within the new ceiling is success only when the existing semantic asserts pass.

Ownership does not change. These are cfg(test) waits on oneshots the tests already own. No production task, engine child, pool, or cancellation token gains a new owner or a longer deadline.

Integration boundary: the tests observe the same channels they observe today. No command, event, capability, or stored key changes.
