## MANDATE

### A database target keeps the caller's leaf spelling, so in-memory keys split across case aliases of one file

* **ID:** f-20261008-07 · **Status:** open · **Area:** native-fs · **Root:** - · **Entry:** build · **Blocked:** none
* **Filed from:** b9090559-f6be-4db2-b5a3-72a102d2f492
* **Where:** `src-tauri/src/infra/path_authority/mod.rs:2073` (`canonical_binding`: canonicalises only the parent and appends the leaf unchanged), `:917` (`DatabaseFileTarget::path()` returns that spelling), `:5851` (persistent-entry reuse compares stored paths lexically). In-memory keys built from `target.path()`: `SearchCache::collision_lock` (`src-tauri/src/db/search.rs:664`, `:918`), `SearchCache::generation_lock` via `get_index_path(read_target.path())` (`src-tauri/src/db/search.rs:256`), `PuzzleCache` (`src-tauri/src/puzzle.rs:64`), and — once `f-20260927-07` lands — the search-cache identity and its invalidation.
* **Defect:** on a case-insensitive filesystem (Windows NTFS, macOS APFS default) one database can be authorized under two leaf spellings (`GameCase.db3` and `gamecase.db3`): reuse lookups compare spellings lexically, and the target keeps the caller's leaf spelling. Every in-memory key derived from `target.path()` then splits into two keys for one file. Measured by reading the source at `3a4d7e43`; not reproduced on a case-insensitive volume. Consequences: the per-index generation lock and the position-search collision lock do not serialize across the two spellings; after `f-20260927-07`, an external replacement of the database followed by invalidation through the other spelling leaves the earlier entry cached until LRU eviction (it is never served, because the key also carries the probed database object and revision). Before `f-20260927-07`, `SearchCache` hid the split by canonicalising the full path by pathname, which is the reach that finding removes.
* **Open question:** should the authority bind a database target to the on-disk leaf spelling (descriptor-derived, inside `infra/`), refuse a second persistent entry for an object already registered under another spelling, or should in-memory keys move off pathnames entirely onto the authority-bound object identity?
* **Why it matters:** the generation lock exists so that two searches do not regenerate one sidecar concurrently; a key split defeats it for aliased handles, and cache invalidation loses its "no cached mapping outlives an invalidation" property (`d-20261005-06`) for the combined alias-plus-replacement case.
* **Related:** `f-20260927-07` (plan `tasks/plans/2026-10-08-search-index-identity-descriptor.md`, review issue raised by `review-platform-semantics` round 1; Root `-`, so named here), `f-20260914-36` (handled; rebound symlinked-ancestor spellings, the lexical reuse comparison noted there).
* **Found by:** Claude Code, PLAN-ONLY planner for `f-20260927-07`, drain session b9090559-f6be-4db2-b5a3-72a102d2f492, 2026-10-08, from Codex `review-platform-semantics` (round 1, confidence 94).
* **Correction (2026-10-08, records lens on the f-20260927-06 push range, verified by the orchestrator):** `PuzzleCache` does not belong in the list of keys that split across case aliases. `PuzzleCacheKey::eq` (`src-tauri/src/puzzle.rs:29-36`) compares `database` (the probed object identity), ratings and theme, not the path spelling; the path spelling can affect only which entry an invalidation names, not key equality. The `SearchCache` locks remain the affected keys.

## Approach

### O1 — Object-owned search leases

Generation leases use the authority-bound database object. Collision leases use query plus that object at both callers. Equal objects share exclusion across spellings and hard links. Distinct database objects remain independent. Existing cancellation, panic recovery, live-lease retention and quiescent reclamation remain. Generation must not proceed under a lease for an object different from its post-wait resolved target.

### O2 — Descriptor-owned cache identity and conservative eviction

Search-index identity replaces its database pathname with the retained parent object's identity. Sidecar identity, length and time still come from the exact descriptor mapped, and database provenance remains in IndexSource. Equivalent aliases in one parent therefore yield equal keys when they map the same sidecar. Descriptor metadata failures propagate through the existing typed error path before publication.

Invalidation evicts both results and indexes for the same retained parent or the same database object. Parent scope survives simultaneous object replacement and alias spelling changes. Object scope retains hard-link eviction across parents. Unrelated directories remain cached. A parent-identity observation failure conservatively evicts both caches, since failure to narrow an optional cache operation cannot leave an invalid mapping retained. No pathname lookup or database open is added.

Preserve counter-before-eviction ordering, snapshot-before-probe publication protection, and dropping displaced mappings after releasing the mutex. Readers keep their mapped generations. Existing clear and lease ownership semantics remain.

### O3 — Regression and platform proof

Runtime tests must distinguish object-owned leases from pathname-owned leases, exercise both collision integrations, and prove alias-plus-replacement eviction of both caches with surviving mapped readers and late-publication protection intact. Cover independent objects, hard links, selective retention across directories, and conservative same-parent eviction. Native alias tests determine filesystem applicability and report it explicitly. Windows and macOS tests run in their existing Test workflow jobs, while local Windows GNU checking proves compilation only. Linux behavioral failure witnesses keep the new tests and withdraw only production fix hunks, with adapters disclosed if old APIs cannot compile unchanged.

A runtime parent-identity failure witness must prove both caches are evicted and an insertion using the pre-invalidation snapshot remains uncached. Alias-equivalent targets mapping the same sidecar must produce equal identities and share a cached index and result. These assertions distinguish the intended fallback and equality contracts from early-return invalidation or retained pathname equality.

## Decisions and trade-offs

Decided autonomously: use object-owned leases plus parent-or-object invalidation. Rejected on-disk leaf normalization, which requires platform-specific spelling discovery and registration migration and still fails replacement that changes on-disk case. Rejected global cache clearing, which unnecessarily evicts other directories. Rejected object-only eviction, which misses replacement. This extends d-20261008-15 for its explicitly deferred alias/replacement case and preserves d-20261005-06's publication and surviving-reader contracts.
