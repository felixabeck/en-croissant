# Plan: Retain failed engine cleanup ownership

## Goal

Resolve f-20261001-14. A failed engine teardown stays discoverable and retryable by its exact native generation. Game replacement and application shutdown cannot report successful cleanup after the production game loop lost a failed reap.

## MANDATE

### A failed engine termination drops the actor from the supervisor, so no later owner can retry or confirm cleanup

* **ID:** f-20261001-14 · **Status:** open · **Area:** engine-uci · **Root:** - · **Entry:** build · **Blocked:** none
* **Where:** `src-tauri/src/engine/process.rs:1448-1461` (`terminate_exact`: `let result = current.actor.terminate().await; self.actors.remove(key); result`), used by `retire_engine`, `retire_executables`, `kill_engine`, `kill_engines` and tab termination.
* **Defect:** when `actor.terminate()` returns an error, the actor is removed from the registry anyway. The child process may still be alive (kill-on-drop is best effort), and nothing — tab close, app shutdown via `RunEvent::ExitRequested`, a later retirement — can find it again.
* **Why it matters:** `.claude/rules/async-resource-invariants.md` requires cleanup on every exit path; an engine with a large hash (8 GB in Felix's configuration) can outlive its owner unseen.
* **Open question:** keep failed actors in a bounded "reaping" set that shutdown and later retirements retry, or make termination escalate (kill, wait with deadline) until it is confirmed before removal — and how the renderer learns that a process could not be confirmed dead.
* **Found by:** Codex `review-engine-protocol` lens, round 2 of the Stockfish 19 upgrade plan review (`tasks/plans/2026-10-01-stockfish-19-upgrade.md`, issue R2 retirement-failure), confirmed by the orchestrator from source, 2026-10-01.
* **Additional review evidence (2026-10-09):** f-20260926-07 cumulative review traced the normally joined production game loop. src-tauri/src/game.rs logs a terminate_game_engines failure at the loop tail and returns (). Shared pending teardown subsequently removes the failed generation, so finish_retired's unconditional exact termination finds no registered or pending owner and returns Ok. This can make replacement and shutdown_all report success after an unconfirmed reap. Existing clean-join failure tests use a loop that skips engine cleanup and do not exercise that production loss path. The cause is this finding's failed-actor/result retention contract, not an empty-join cancellation gap. Preserve the completed outcome or failed generation until the owning game/shutdown path has observed failure. Verification for this finding must include the production-loop cleanup path, not only direct fallback teardown. The separate design question remains open at build tier. review-error-handling confidence 95, adopting drain a51461c5-317b-40c0-8297-ab16a2fc6904.

Ordinary user actions overlap teardown, replacement, tab close, engine removal and shutdown. An engine can be silent, exit unexpectedly, or fail an OS kill or wait. Callers can be cancelled while teardown proceeds. Support Linux, macOS and Windows. A permanently unkillable OS process cannot be guaranteed dead within a finite deadline, so retain its authority and report the unconfirmed outcome honestly.

Do not add an adversarial child-descendant threat model, PID-based signalling, new renderer controls, IPC events, persistent cleanup journals, configurable retry policy, or a background retry service. Warm-search ownership, closed-tab admission and post-shutdown late publication remain their separately recorded work. Planner co-located joiners are not planned here.

## Approach

### O1 — Own the child until confirmed reaped

One shared cleanup owner carries the original child handle, executable/resource leases and exact generation across runtime teardown and actor-task exit. Route initial graceful teardown and later forced cleanup through the existing bounded child termination domain primitive. Successful OS wait is the condition that releases the child authority. Failed kill, failed wait, timeout, cancelled requester and incomplete IO construction preserve a supervisor-reachable cleanup owner. Keep protocol service permanently closed after termination starts. Actor completion must not hold a request open waiting for an unbounded reaper.

Verification level: deterministic child-control tests plus a real child fixture. After an injected failed wait, assert the same owned child can be reaped on a later bounded attempt and that successful reaping releases ownership. Keeping the old consume-and-drop implementation must fail this assertion. Test partial IO construction through its production cleanup boundary.

### O2 — Retain failed generations and share each attempt

Use the existing generation-keyed pending ownership, without a second cleanup registry. A failed attempt leaves its entry discoverable, cancelled and unusable for new UCI work. All exact and matching teardown operations, replacement cleanup, rejected publication and dropped-owner cleanup use this ownership. A later explicit teardown invocation may start one bounded retry of a completed failed attempt. Concurrent callers attached to one attempt receive that attempt's identical result, even if a later attempt recovers. Requester cancellation cannot cancel the owned attempt. Retain actor-join failure separately from child-reap confirmation so a successful child retry does not erase an actor task error.

Each drain processes a generation at most once per invocation, including generations handed off while scanning. A failed retained entry cannot cause an immediate repeat or infinite loop. Preserve the first generation's identity if the same key acquires a newer actor. Exact cleanup never touches another generation. Matching tab/id/executable drains include older failed entries even after renderer removal. Remove the pending entry only after confirmed child cleanup and safe terminal-result publication to attached owners.

Verification level: supervisor integration tests. A failed exact teardown followed by a tab/global/identity drain must return the retained failure or the result of a real bounded retry, and the owner remains until confirmation. Controlled concurrent terminators and cancelled waiters must observe one attempt, with original error category, display, diagnostic and root failure intact. A repeated-failure drain must return within its deadline and leave ownership. Same-name/path engines and a newer generation must remain independent.

### O3 — Bound ownership without evicting unresolved children

Reserve capacity before every production supervisor-owned child creation. The native limit is 4096 concurrently owned child generations, including active, spawning and unresolved cleanup. Capacity follows the child rather than a mutable key or replaceable admission. Full capacity refuses a new spawn with the existing renderer-safe `ResourceLimit`, without creating a child or deleting a failed owner. An admission abandoned before spawn releases its reservation. After spawning, only confirmed cleanup releases the reservation. No eviction or expiration of a live or unconfirmed child. This bound prevents an endless sequence of failed retirements accumulating handles and processes.

Verification level: capacity tests with a smaller test-only limit. Assert refusal happens before the production spawn boundary, unresolved teardown keeps its slot, pre-spawn cancellation returns its slot, and confirmed reaping makes capacity available. Exercise concurrent admission and key replacement so map removal cannot prematurely return capacity.

### O4 — Preserve the production game cleanup outcome

The live game session retains the production loop's engine cleanup outcome, including on natural completion. Retirement, replacement and shutdown that own the session observe that outcome even if a later supervisor retry succeeds or the loop has already joined. Combine it with fallback cleanup and join failures using the existing shared error representation. Both game sides are attempted. Concurrent game and supervisor shutdown must share generation teardown without consuming each other's failure. Natural completion keeps an unobserved failed session reachable in existing game ownership, while completed-game snapshots and events keep their current meaning. The first completed retirement observation may release this failed-session ownership, even when returning the failure, because unresolved children remain supervisor-owned under O2. Callers already holding the session still receive its retained result. Bound unobserved failed-session retention at 4096, reserving its place before game launch and refusing overflow before resources are created, without silently pruning failures. Game shutdown processes a captured session once per invocation and cannot rescan a failed session indefinitely.

Verification level: actual game-loop integration tests. Drive the production loop through its cleanup tail with injected reap failure, then retire/replace/shut down. Assert the owning caller receives that failure, including after a successful later retry. Keep normal natural completion, join timeout/abort and stale-session replacement green. A stand-in loop that skips production cleanup cannot satisfy this obligation.

### O5 — Keep existing error and exit contracts

Direct renderer commands return the current stable error mapping for unconfirmed cleanup. Native logs carry generation and diagnostic context, while OS paths and raw diagnostic details stay native. No new binding, event, UI copy or capability scope is required. Verify the existing consumer paths for Kill, tab close, removal and game replacement rather than creating another notification route. Global shutdown reports failure through its existing aggregation and remains within `SHUTDOWN_BUDGET`, even with retained failed entries and concurrent game cleanup.
Committed game abort retains its existing public `Ok` contract after the abort has committed. Its cleanup failure remains logged and supervisor-owned, without making the already committed action appear uncommitted.

Verification level: existing command/error mapping tests and native shutdown integration tests. Assert unconfirmed cleanup cannot produce `Ok` or a successful native shutdown result, and that repeated failures do not extend the bounded process exit path. Use cross-platform deterministic child controls for the ownership protocol, real process proof on Unix, Windows GNU compile locally and the required Windows/macOS CI runtime jobs before release.

## Approach

### O1 — Own the child until confirmed reaped

One shared cleanup owner carries the original child handle, executable/resource leases and exact generation across runtime teardown and actor-task exit. Route initial graceful teardown and later forced cleanup through the existing bounded child termination domain primitive. Successful OS wait is the condition that releases the child authority. Failed kill, failed wait, timeout, cancelled requester and incomplete IO construction preserve a supervisor-reachable cleanup owner. Keep protocol service permanently closed after termination starts. Actor completion must not hold a request open waiting for an unbounded reaper.

Verification level: deterministic child-control tests plus a real child fixture. After an injected failed wait, assert the same owned child can be reaped on a later bounded attempt and that successful reaping releases ownership. Keeping the old consume-and-drop implementation must fail this assertion. Test partial IO construction through its production cleanup boundary.

### O2 — Retain failed generations and share each attempt

Use the existing generation-keyed pending ownership, without a second cleanup registry. A failed attempt leaves its entry discoverable, cancelled and unusable for new UCI work. All exact and matching teardown operations, replacement cleanup, rejected publication and dropped-owner cleanup use this ownership. A later explicit teardown invocation may start one bounded retry of a completed failed attempt. Concurrent callers attached to one attempt receive that attempt's identical result, even if a later attempt recovers. Requester cancellation cannot cancel the owned attempt. Retain actor-join failure separately from child-reap confirmation so a successful child retry does not erase an actor task error.

Each drain processes a generation at most once per invocation, including generations handed off while scanning. A failed retained entry cannot cause an immediate repeat or infinite loop. Preserve the first generation's identity if the same key acquires a newer actor. Exact cleanup never touches another generation. Matching tab/id/executable drains include older failed entries even after renderer removal. Remove the pending entry only after confirmed child cleanup and safe terminal-result publication to attached owners.

Verification level: supervisor integration tests. A failed exact teardown followed by a tab/global/identity drain must return the retained failure or the result of a real bounded retry, and the owner remains until confirmation. Controlled concurrent terminators and cancelled waiters must observe one attempt, with original error category, display, diagnostic and root failure intact. A repeated-failure drain must return within its deadline and leave ownership. Same-name/path engines and a newer generation must remain independent.

### O3 — Bound ownership without evicting unresolved children

Reserve capacity before every production supervisor-owned child creation. The native limit is 4096 concurrently owned child generations, including active, spawning and unresolved cleanup. Capacity follows the child rather than a mutable key or replaceable admission. Full capacity refuses a new spawn with the existing renderer-safe `ResourceLimit`, without creating a child or deleting a failed owner. An admission abandoned before spawn releases its reservation. After spawning, only confirmed cleanup releases the reservation. No eviction or expiration of a live or unconfirmed child. This bound prevents an endless sequence of failed retirements accumulating handles and processes.

Verification level: capacity tests with a smaller test-only limit. Assert refusal happens before the production spawn boundary, unresolved teardown keeps its slot, pre-spawn cancellation returns its slot, and confirmed reaping makes capacity available. Exercise concurrent admission and key replacement so map removal cannot prematurely return capacity.

### O4 — Preserve the production game cleanup outcome

The live game session retains the production loop's engine cleanup outcome, including on natural completion. Retirement, replacement and shutdown that own the session observe that outcome even if a later supervisor retry succeeds or the loop has already joined. Combine it with fallback cleanup and join failures using the existing shared error representation. Both game sides are attempted. Concurrent game and supervisor shutdown must share generation teardown without consuming each other's failure. Natural completion keeps an unobserved failed session reachable in existing game ownership, while completed-game snapshots and events keep their current meaning. The first completed retirement observation may release this failed-session ownership, even when returning the failure, because unresolved children remain supervisor-owned under O2. Callers already holding the session still receive its retained result. Bound unobserved failed-session retention at 4096, reserving its place before game launch and refusing overflow before resources are created, without silently pruning failures. Game shutdown processes a captured session once per invocation and cannot rescan a failed session indefinitely.

Verification level: actual game-loop integration tests. Drive the production loop through its cleanup tail with injected reap failure, then retire/replace/shut down. Assert the owning caller receives that failure, including after a successful later retry. Keep normal natural completion, join timeout/abort and stale-session replacement green. A stand-in loop that skips production cleanup cannot satisfy this obligation.

### O5 — Keep existing error and exit contracts

Direct renderer commands return stable existing error categories for unconfirmed cleanup. Native logs carry generation and diagnostic context, while OS paths and raw diagnostic details stay native. Actor and game task-join failures use one shared renderer-safe conversion, retaining native diagnostic detail in the owning log. Never interpolate raw JoinError text into a public Conflict. Keep the existing serialized ErrorPayload shape and its consumers. No new binding, event, UI control or capability scope is required. Verify the existing consumer paths for Kill, tab close, removal and game replacement rather than creating another notification route. Global shutdown reports failure through its existing aggregation and remains within `SHUTDOWN_BUDGET`, even with retained failed entries and concurrent game cleanup.
Committed game abort retains its existing public `Ok` contract after the abort has committed. Its cleanup failure remains logged and supervisor-owned, without making the already committed action appear uncommitted.

Verification level: command/error serialization tests and native shutdown integration tests. For actor and game task panics carrying a unique private-path marker, assert serialized results and composite cleanup errors omit that marker while native logs retain diagnostic context. Assert unconfirmed cleanup cannot produce `Ok` or a successful native shutdown result, and that repeated failures do not extend the bounded process exit path. Use cross-platform deterministic child controls for the ownership protocol, real process proof on Unix, Windows GNU compile locally and the required Windows/macOS CI runtime jobs before release. After cumulative code review and repairs, build the release app through `pnpm gate:ensure tauri-build`, then run `pnpm verify:app`. This proves the actual product's normal IPC and close-control exit, without claiming to exercise a live engine registered through the native picker. Failed-reap retry and engine process facts remain covered by the native real-child and actual game-loop tests. No custom verifier or picker bypass is required.
