# Plan: lossless progress generation wire contract

## Goal

Close f-20260925-02 by making every native progress generation lossless over JSON, keeping renderer generation arithmetic and stale-event fencing coherent, and proving the real Tauri transport.

## MANDATE

### Progress generations use incompatible JSON and TypeScript types

* **ID:** f-20260925-02 · **Status:** open · **Area:** bindings-ipc · **Root:** - · **Entry:** build · **Blocked:** none
* **Where:** `src-tauri/src/progress.rs:35-57`, `src/bindings/generated.ts:1041,1250-1252`, `src/hooks/useProgress.ts:70-102` and the progress-clear button.
* **Defect:** Rust serializes `u64` progress generations as JSON numbers, while Specta declares them as `bigint`. The renderer passes native event values through without normalization. A failed clear can call `fence(null)` while a progress item is displayed; `current.generation + BigInt(1)` then mixes a runtime number with a BigInt and throws. Comparisons and clear-command return values rely on the same mismatched wire contract. This predates the player-statistics memory plan and affects all progress consumers.
* **Proof:** The Rust fields are `u64`, generated bindings say `bigint`, and `useProgress.ts:92` adds `BigInt(1)` to the event-derived value. The `review-ipc-contract` lens found the mismatch while reviewing `f-20260907-05` on 2026-09-25 (confidence 94). # Plan: lossless progress generation wire contract

## Goal

Close f-20260925-02 by making every native progress generation lossless over JSON, keeping renderer generation arithmetic and stale-event fencing coherent, and proving the real Tauri transport.

## MANDATE

### Progress generations use incompatible JSON and TypeScript types

* **ID:** f-20260925-02 · **Status:** open · **Area:** bindings-ipc · **Root:** - · **Entry:** build · **Blocked:** none
* **Where:** `src-tauri/src/progress.rs:35-57`, `src/bindings/generated.ts:1041,1250-1252`, `src/hooks/useProgress.ts:70-102` and the progress-clear button.
* **Defect:** Rust serializes `u64` progress generations as JSON numbers, while Specta declares them as `bigint`. The renderer passes native event values through without normalization. A failed clear can call `fence(null)` while a progress item is displayed; `current.generation + BigInt(1)` then mixes a runtime number with a BigInt and throws. Comparisons and clear-command return values rely on the same mismatched wire contract. This predates the player-statistics memory plan and affects all progress consumers.
* **Proof:** The Rust fields are `u64`, generated bindings say `bigint`, and `useProgress.ts:92` adds `BigInt(1)` to the event-derived value. The `review-ipc-contract` lens found the mismatch while reviewing `f-20260907-05` on 2026-09-25 (confidence 94). Verify on the actual Tauri IPC path, including a rejected clear and a generation beyond JavaScript's safe integer range; a TypeScript-only mock would hide the serialization boundary.
* **Open question:** choose one wire-safe generation representation for events, command arguments and returns, and preserve the monotonic stale-event fence across every consumer. Regenerate bindings and cover the real IPC boundary. The current player-statistics plan does not change these shared types or `useProgress`; this is a separate cross-app contract repair.
* **Related:** `f-20260904-02` and `f-20260906-07` addressed other progress subscription/cancellation paths, not the generation wire type. `f-20260919-12` concerns a stored running bar after `begin_progress` emission failure.

## Approach

### O1 — One lossless native progress contract

Derived from MANDATE: "choose one wire-safe generation representation for events, command arguments and returns" and "a generation beyond JavaScript's safe integer range".

Use a progress-specific generation value wrapping u64 with canonical unsigned decimal string JSON and a Specta string declaration. Every generation-bearing field and the scalar clear result uses that same value. Internal comparison stays numeric. Accept canonical strings from "0" through "18446744073709551615" and reject malformed or out-of-range values rather than rounding or coercing them. Command names, argument keys, progress scales, IDs, states and registry entries remain the same. Regenerate bindings through `pnpm bindings:generate`.

The store must allocate a strictly newer generation or return a typed, renderer-safe conflict without replacing/removing entries, evicting another job, or advancing the clock. Allocate before destructive start/clear changes. A live running download clear still returns its existing generation and emits nothing, even at exhaustion. Other existing error and terminal semantics remain intact. This exhaustion obligation prevents the changed full-range contract from authenticating a retired producer at its upper bound.

Native serializer/deserializer and store tests establish exact values on both sides of 2^53, adjacent high generations, maximum generation, rejection and non-mutating exhaustion. An assertion on serialized JSON string type and exact digits must fail if numeric serialization is restored. An assertion that an old lease stays stale must fail if saturation is restored.

### O2 — Explicit wire and renderer types

Derived from MANDATE: "preserve the monotonic stale-event fence across every consumer" and "Comparisons and clear-command return values rely on the same mismatched wire contract".

Generated progress types describe strings. Renderer progress types describe bigint, using the existing bindings barrel's domain-type override pattern. The platform facade converts generation strings exactly once on every event, snapshot, start lease and clear acknowledgement, and converts outgoing setProgressState leases back to strings. Its public command and subscription types expose the renderer types. All production and test consumers use the correct side of this boundary. A progress-specific codec handles this contract without changing the safe-number codec for game counters or timestamps.

Keep existing ID and stale-result guards, subscription ownership, terminal preference and cancellation ordering. Malformed incoming events take the existing listener error path without changing displayed state or its generation floor. Malformed command results reject through the existing command error path. Invalid outgoing leases reject before native invocation. fence(null) and the press-time null-acknowledgement fence remain bigint operations, including a local floor of u64::MAX + 1, which is a visibility sentinel and is never sent as a native lease.

Facade and hook/button regression tests use raw string wire payloads through the real adapter. Update every fixture at the generated-command/event boundary to canonical-string generations, including the DatabaseLoader generated-event mock and the account download/conversion e2e start-progress response. Facade-level mocks retain bigint domain values. Tests establish adjacent large generations remain distinct, old events and snapshots cannot resurrect cancelled progress, a failed clear can safely fence the displayed generation, and a late null cancel acknowledgement cannot hide a newer retry. Existing download cancellation and AccountCard lease consumers remain type-correct. ## Decided autonomously

* Question: Which progress wire representation preserves the native generation range? Chosen: canonical decimal strings on all progress surfaces and bigint in renderer domain state. Rejected: numeric JSON with a native safe-integer ceiling, blanket recursive bigint conversion, or strings used for lexicographic generation comparisons. Reason: strings preserve full u64 values and existing numeric fence semantics. Reversal path: a newly evidenced restricted generation domain plus native allocation bounds and equivalent transport proof.
* Question: What happens when the generation space is exhausted? Chosen: typed conflict before destructive start or clear mutation, with live-download no-op clears still returning their existing floor. Rejected: saturation or wraparound. Rejected: a shipped clock-seed environment variable, test IPC command, second driver, or TypeScript-only wire mocks. Reason: the original producer/serializer/transport must be measured.
