## Approach

### Import-safe state graph

Importing the affected state graph must not read or repair persisted values, discard document-dir, capture fixture owners or start native work. Defining atoms, schemas and empty document registries is allowed. Preserve the current browser environment assumption and storage encodings.

Replace eager hydration with a shared lazy mechanism for the eight uses of the same concept. Each keeps its persisted value synchronously available on the first real store read, existing write/update/reset/subscription semantics and document scope. Do not replace valid values with defaults until a component mounts. Preserve normal preference validation and translated diagnostics. Private helper names and shape belong to the executor.

### Original owner capture and repair

Make raw owner capture explicit and one-shot per document. Capture all owner families and engine attachment evidence before any owner-affecting hydration, normalization, migration, workspace cleanup or expansion repair. Startup takes this snapshot before it can mutate storage. Later reconciliation uses that exact evidence, including conservative treatment of malformed, lossy or refused reads. Repeated startup/path-owner calls do not resnapshot repaired values.

Keep expansion repair at startup even when Files never opens, and keep the standalone atom behavior. Remove document-dir at the corresponding explicit startup boundary. Preserve current workspace snapshot, retry and store-local edit behavior. Existing direct consumer tests adopt the explicit boundary at the point their fixtures represent a new document. Do not add a second ownership coordinator or a second reconciliation protocol.

### Explicit application bootstrap

Move the testable application startup body into an import-safe module. The actual index.html entrypoint invokes it once for its document. Unit tests statically import that module and explicitly start it after their fixture DOM/storage/mocks exist. No app mount, native request or storage initialization occurs merely by importing the testable module.

Keep synchronous workspace refusal before root creation/native bootstrap. Preserve root setup, previous-document reservation release, session sanitization, i18n fallback, terminal sanitation UI, splash/log behavior, download observer and path-owner/engine-completion order. The same completed or pending document start must not create another root, duplicate observers or replay reconciliation when requested again. A failed synchronous initialization must retain its current explicit retry behavior. No new catch-and-continue path or diagnostic copy.

### Collection transforms and test freshness

Warm only the safe affected graphs at collection in files that still dynamically import them in their first timed case or hook. Keep resetModules and the per-case dynamic import when they provide real document freshness. No shared setupFiles preload. Files that already import the relevant graph statically need no redundant warm-up.

Preserve FideInfo's single doMock/doUnmock action per case under d-20260920-09 and its real flag loader behavior. Preserve engine-owner fixtures, workspace cleanup and user preferences. Optional application feature loads such as selected locale catalogues remain asynchronous feature work, no claim promises every async module load is eliminated.
