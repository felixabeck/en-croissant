## Goal

Close f-20260929-03 by preventing FIFO opens from hanging the bound database identity read or a pool worker, while preserving SQLite locks, authority binding and regular-file operation.

## MANDATE

### A non-regular file planted as an authorized database's `-shm` can block SQLite's open inside the identity probe

* **ID:** f-20260929-03 · **Status:** open · **Area:** db-search · **Root:** - · **Entry:** build · **Blocked:** none
* **Where:** SQLite 3.39.2 unix VFS `unixOpenSharedMemory` (`libsqlite3-sys-0.25.2/sqlite3/sqlite3.c:40120-40135`), reached from `DatabaseRepository::read_revision` and the repository pool (`src-tauri/src/db/repository.rs`), after `f-20260929-01`'s binding also through `src-tauri/src/db/bound_sqlite.rs`.
* **Defect:** SQLite opens `<db>-shm` with `O_RDWR|O_CREAT|O_NOFOLLOW` and, if that fails, retries `O_RDONLY|O_NOFOLLOW`. Neither carries `O_NONBLOCK`, and SQLite does not check the file type, so a FIFO planted as `-shm` in the authorized directory can block the read-only fallback's `open()` indefinitely (a FIFO opened read-only blocks until a writer appears), hanging the identity probe or a pool worker. Pre-existing with pathname opens; unmeasured (no probe run yet).
* **Why it matters:** a hung native identity probe stalls search/index loading for that database; the actor needs write access to the authorized directory, which is also SQLite's own trust boundary for `-wal`.
* **Open question:** should the bound SQLite hooks refuse non-regular sidecars (open with `O_NONBLOCK`, `fstat` `S_ISREG`, clear `O_NONBLOCK`), and what error does the caller then see — or is an in-parent FIFO inside SQLite's accepted trust boundary and to be documented as a residual? Measure first whether the fallback path is reachable (it requires the `O_RDWR` open to fail).
* **Related:** `f-20260929-01` (the SQLite binding whose plan review surfaced it; withdrawn from that plan as outside its mandate by `review-correctness` and `review-minimalism`, round 3), `f-20260912-07`.
* **Found by:** Codex `review-tauri-security` lens, plan review round 2 of `tasks/plans/2026-09-29-sqlite-bound-vfs.md`, 2026-09-29 (drain session `1af0f1fc-ab06-4981-9a3d-47a89d71c541`).

**Widened 2026-09-30 (cumulative review of the `f-20260929-06` build run, commit `0e2d799b`; Codex `review-pgn-index` 93 and `review-tauri-security` 95):** the same blocking-open shape exists for the **database leaf itself on non-Linux unix**. `src-tauri/src/db/bound_sqlite.rs` `unix_hooks::open_hook_inner` (non-Linux branch) checks the leaf with `fstatat(AT_SYMLINK_NOFOLLOW)` and then calls `openat(parent, leaf, flags | O_NOFOLLOW)` without `O_NONBLOCK`; a writer that replaces the leaf with a FIFO between the two calls makes a read-only open (`read_revision`, `repository.rs` ~597) block until a FIFO writer appears, before the post-open identity check runs; four such requests can hold every `BLOCKING_GATEWAY` permit. Linux is no longer affected: since `0e2d799b` the leaf is opened `O_PATH | O_NOFOLLOW` (measured M5 in the f-06 plan: returns at once on a FIFO, `S_ISFIFO` → identity mismatch → `ESTALE`). ## Approach

### O1 — Bound Unix opens and acceptance

Authority: “a FIFO planted as `-shm` ... can block ... indefinitely”, plus the widened non-Linux leaf race.

Apply one shared nonblocking and regular-descriptor acceptance contract to every bound Unix sidecar open and every non-Linux Unix lockable leaf open. Preserve caller access, creation, exclusivity and mode flags, retained-parent resolution, no-follow protection and C variadic argument promotion. Add `O_NONBLOCK`, require successful descriptor metadata and a regular-file kind before returning the descriptor to SQLite, and leave `O_NONBLOCK` set on accepted regular descriptors. Do not add a fallible flag-clearing operation.

A failed syscall returns its original errno. A sidecar proven non-regular is closed and refused with `EINVAL` without an identity-refusal increment. A non-Linux leaf proven non-regular or wrong-identity is refused with `ESTALE` and the existing identity-refusal increment, using O2 cleanup. Preserve Linux leaf O_PATH verification and descriptor reopening. Unbound paths and bound directory opens retain their existing dispatch.

Existing non-regular sidecars must never become “absent” through `xAccess`. Keep its existing existence/error rules and empty-regular-file handling. No pathname-only precheck may replace descriptor acceptance.

Verification level: production syscall-hook witnesses for read-only and read-write FIFO sidecars, plus a native non-Linux precheck/open leaf-swap witness. A regression must fail on actual returned descriptors or a bounded subprocess result, not on source-text matches.

### O2 — Lock-safe failure ownership

Authority: the widened finding requires that “the hook must never close a lockable leaf descriptor of a possibly locked inode”. Descriptor validation introduced by O1 must not recreate that failure on a sidecar metadata-error path either.

Preserve the existing non-Linux leaf mismatch quarantine and admission contract of d-20260930-10. Successful classification of a non-regular sidecar proves that it cannot be a registered regular database inode, so closing that descriptor is safe. A failed sidecar descriptor inspection leaves its identity unknown. Retain that unclassified lockable descriptor on every Unix platform until no registration is live, preserving the inspection errno.

Extend the existing registry's unclassified ownership and cleanup to Linux for this new failure path. Reuse its admission threshold of 8 and its no-close-on-full behavior. Sidecar opens on every Unix must be refused with `EMFILE` when the unclassified bucket is at admission capacity. Non-Linux leaf admission continues to account for its identity buckets too. Already admitted concurrent opens may exceed the threshold, as in the existing contract. Admission exhaustion does not increment identity refusal. Linux O_PATH leaf refusals continue to close only their non-lockable descriptor and need no new lockable-leaf quarantine.

Keep registration cleanup serialized with existing acquisition and close retained descriptors only under the current last-live-registration rule. No second registry or independent cleanup owner.

Verification level: an isolated native subprocess holds a real POSIX SQLite lock on a bound inode, injects metadata failure when that inode is opened under a sidecar name, and asserts the lock remains held, errno is preserved, admission fails at the threshold, retained descriptors remain open while any registration lives, and cleanup occurs after the last registration. Existing non-Linux leaf quarantine witnesses must remain green. This test's hard link is a fault-injection fixture for cleanup, not a new hard-link acceptance policy.

### O3 — Repository outcome and regular-file compatibility

Authority: the finding asks “what error does the caller then see”.

Do not add a renderer or native error variant. Sidecar kind refusal leaves the bound identity counter unchanged. Establish-time failures therefore retain the existing unchanged-leaf mapping, revision-query failures retain their Diesel/SQLite result, and pooled acquisition retains its current bounded r2d2 error. A swapped leaf remains `Conflict`. Authority `PermissionDenied` and unrelated host failures retain current classification. Trace and pin the concrete existing result at both revision-read and pool boundaries, including SHM opening during a query after a successful establish. The contract promises syscall completion without a FIFO peer, not immediate r2d2 acquisition.

WAL/SHM reads, WAL writes and checkpointing, rollback-journal transactions and hot-journal recovery through the held parent must continue to work for regular files, including missing sidecars SQLite creates and its read-only regular-SHM fallback. Rejecting special files must not be reported as successful revision hydration or an absent hot journal.

Verification level: actual bundled SQLite repository witnesses cover the FIFO fallback without a cooperating writer, finite caller failure and recovery after replacement with a valid regular sidecar. Existing retained-parent, WAL/journal, authority and classification witnesses provide regression anchors.

# Plan: Refuse non-regular bound SQLite opens without FIFO waits

## Goal

Close f-20260929-03 by preventing FIFO opens from hanging the bound database identity read or a pool worker, while preserving SQLite locks, authority binding and regular-file operation.

## MANDATE

The pinned finding and its widened scope are reproduced verbatim below. No sibling finding is selected.

### A non-regular file planted as an authorized database's `-shm` can block SQLite's open inside the identity probe

* **ID:** f-20260929-03 · **Status:** open · **Area:** db-search · **Root:** - · **Entry:** build · **Blocked:** none
* **Where:** SQLite 3.39.2 unix VFS `unixOpenSharedMemory` (`libsqlite3-sys-0.25.2/sqlite3/sqlite3.c:40120-40135`), reached from `DatabaseRepository::read_revision` and the repository pool (`src-tauri/src/db/repository.rs`), after `f-20260929-01`'s binding also through `src-tauri/src/db/bound_sqlite.rs`.
* **Defect:** SQLite opens `<db>-shm` with `O_RDWR|O_CREAT|O_NOFOLLOW` and, if that fails, retries `O_RDONLY|O_NOFOLLOW`. Neither carries `O_NONBLOCK`, and SQLite does not check the file type, so a FIFO planted as `-shm` in the authorized directory can block the read-only fallback's `open()` indefinitely (a FIFO opened read-only blocks until a writer appears), hanging the identity probe or a pool worker. Pre-existing with pathname opens; unmeasured (no probe run yet).
* **Why it matters:** a hung native identity probe stalls search/index loading for that database; the actor needs write access to the authorized directory, which is also SQLite's own trust boundary for `-wal`.
* **Open question:** should the bound SQLite hooks refuse non-regular sidecars (open with `O_NONBLOCK`, `fstat` `S_ISREG`, clear `O_NONBLOCK`), and what error does the caller then see — or is an in-parent FIFO inside SQLite's accepted trust boundary and to be documented as a residual? Measure first whether the fallback path is reachable (it requires the `O_RDWR` open to fail).
* **Related:** `f-20260929-01` (the SQLite binding whose plan review surfaced it; withdrawn from that plan as outside its mandate by `review-correctness` and `review-minimalism`, round 3), `f-20260912-07`.
* **Found by:** Codex `review-tauri-security` lens, plan review round 2 of `tasks/plans/2026-09-29-sqlite-bound-vfs.md`, 2026-09-29 (drain session `1af0f1fc-ab06-4981-9a3d-47a89d71c541`).

**Widened 2026-09-30 (cumulative review of the `f-20260929-06` build run, commit `0e2d799b`; Codex `review-pgn-index` 93 and `review-tauri-security` 95):** the same blocking-open shape exists for the **database leaf itself on non-Linux unix**. `src-tauri/src/db/bound_sqlite.rs` `unix_hooks::open_hook_inner` (non-Linux branch) checks the leaf with `fstatat(AT_SYMLINK_NOFOLLOW)` and then calls `openat(parent, leaf, flags | O_NOFOLLOW)` without `O_NONBLOCK`; a writer that replaces the leaf with a FIFO between the two calls makes a read-only open (`read_revision`, `repository.rs` ~597) block until a FIFO writer appears, before the post-open identity check runs; four such requests can hold every `BLOCKING_GATEWAY` permit. ### O1 — Bound Unix opens and acceptance

Authority: “a FIFO planted as `-shm` ... can block ... indefinitely”, plus the widened non-Linux leaf race.

Apply one shared nonblocking and regular-descriptor acceptance contract to every bound Unix sidecar open and every non-Linux Unix lockable leaf open. Preserve caller access, creation, exclusivity and mode flags, retained-parent resolution, no-follow protection and C variadic argument promotion. Add `O_NONBLOCK`, require successful descriptor metadata and a regular-file kind before returning the descriptor to SQLite, and leave `O_NONBLOCK` set on accepted regular descriptors. Do not add a fallible flag-clearing operation.

A failed syscall returns its original errno. A sidecar proven non-regular is closed and refused with `EINVAL` without an identity-refusal increment. A non-Linux leaf proven non-regular or wrong-identity is refused with `ESTALE` and the existing identity-refusal increment, using O2 cleanup. Existing non-regular sidecars must never become “absent” through `xAccess`. Keep its existing existence/error rules and empty-regular-file handling. No pathname-only precheck may replace descriptor acceptance.

Successful classification of a non-regular sidecar proves that it cannot be a registered regular database inode, so closing that descriptor is safe. A failed sidecar descriptor inspection leaves its identity unknown. Retain that unclassified lockable descriptor on every Unix platform until no registration is live, preserving the inspection errno.

Extend the existing registry's unclassified ownership and cleanup to Linux for this new failure path. Reuse its admission threshold of 8 and its no-close-on-full behavior. Sidecar opens on every Unix must be refused with `EMFILE` when the unclassified bucket is at admission capacity. Non-Linux leaf admission continues to account for its identity buckets too. Already admitted concurrent opens may exceed the threshold, as in the existing contract. Admission exhaustion does not increment identity refusal. Linux O_PATH leaf refusals continue to close only their non-lockable descriptor and need no new lockable-leaf quarantine.

Keep registration cleanup serialized with existing acquisition and close retained descriptors only under the current last-live-registration rule. No second registry or independent cleanup owner.

Verification level: an isolated native subprocess holds a real POSIX SQLite lock on a bound inode, injects metadata failure when that inode is opened under a sidecar name, and asserts the lock remains held, errno is preserved, admission fails at the threshold, retained descriptors remain open while any registration lives, and cleanup occurs after the last registration. # Plan: Refuse non-regular bound SQLite opens without FIFO waits

## Goal

Close f-20260929-03 by preventing FIFO opens from hanging the bound database identity read or a pool worker, while preserving SQLite locks, authority binding and regular-file operation.

## MANDATE

The pinned finding and its widened scope are reproduced verbatim below. No sibling finding is selected.

### A non-regular file planted as an authorized database's `-shm` can block SQLite's open inside the identity probe

* **ID:** f-20260929-03 · **Status:** open · **Area:** db-search · **Root:** - · **Entry:** build · **Blocked:** none
* **Where:** SQLite 3.39.2 unix VFS `unixOpenSharedMemory` (`libsqlite3-sys-0.25.2/sqlite3/sqlite3.c:40120-40135`), reached from `DatabaseRepository::read_revision` and the repository pool (`src-tauri/src/db/repository.rs`), after `f-20260929-01`'s binding also through `src-tauri/src/db/bound_sqlite.rs`.
* **Defect:** SQLite opens `<db>-shm` with `O_RDWR|O_CREAT|O_NOFOLLOW` and, if that fails, retries `O_RDONLY|O_NOFOLLOW`. Neither carries `O_NONBLOCK`, and SQLite does not check the file type, so a FIFO planted as `-shm` in the authorized directory can block the read-only fallback's `open()` indefinitely (a FIFO opened read-only blocks until a writer appears), hanging the identity probe or a pool worker. Pre-existing with pathname opens; unmeasured (no probe run yet).
* **Why it matters:** a hung native identity probe stalls search/index loading for that database; the actor needs write access to the authorized directory, which is also SQLite's own trust boundary for `-wal`.
* **Open question:** should the bound SQLite hooks refuse non-regular sidecars (open with `O_NONBLOCK`, `fstat` `S_ISREG`, clear `O_NONBLOCK`), and what error does the caller then see — or is an in-parent FIFO inside SQLite's accepted trust boundary and to be documented as a residual? Measure first whether the fallback path is reachable (it requires the `O_RDWR` open to fail).
* **Related:** `f-20260929-01` (the SQLite binding whose plan review surfaced it; withdrawn from that plan as outside its mandate by `review-correctness` and `review-minimalism`, round 3), `f-20260912-07`.
* **Found by:** Codex `review-tauri-security` lens, plan review round 2 of `tasks/plans/2026-09-29-sqlite-bound-vfs.md`, 2026-09-29 (drain session `1af0f1fc-ab06-4981-9a3d-47a89d71c541`).

**Widened 2026-09-30 (cumulative review of the `f-20260929-06` build run, commit `0e2d799b`; Codex `review-pgn-index` 93 and `review-tauri-security` 95):** the same blocking-open shape exists for the **database leaf itself on non-Linux unix**. `src-tauri/src/db/bound_sqlite.rs` `unix_hooks::open_hook_inner` (non-Linux branch) checks the leaf with `fstatat(AT_SYMLINK_NOFOLLOW)` and then calls `openat(parent, leaf, flags | O_NOFOLLOW)` without `O_NONBLOCK`; a writer that replaces the leaf with a FIFO between the two calls makes a read-only open (`read_revision`, `repository.rs` ~597) block until a FIFO writer appears, before the post-open identity check runs; four such requests can hold every `BLOCKING_GATEWAY` permit.
