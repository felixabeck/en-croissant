## Why this review was worth eight rounds

Five adopted issues were refutations of things the plan asserted as fact about this repository, each
verified against source by the orchestrator before adoption, and each would have produced broken or
dishonest code:

1. **R1-01** (4 witnesses) — the plan claimed NTFS `FlushFileBuffers` fails on a directory handle
   even with `GENERIC_WRITE`, and built a whole uncertainty-mapping obligation on it. False:
   `resolved.rs:894-897` records the measurement that only a *read-only* handle fails. Rule 12b —
   the claim was never measured before being adopted.
2. **R1-06** (3 witnesses) — the plan claimed `create_pgn_export_destination` routes through
   `atomic_replace_at_identified`. False (`mod.rs:3503-3523`); following it would have replaced the
   fixture each of eleven PGN tests writes before calling it.
3. **R2-01 → R3-02** — two successive attempts to name the handle that actually gets flushed, both
   wrong, two call levels apart. The answer is *both* the ancestor parent and the leaf directory
   from `open_verified_directory`'s second `openat`.
4. **R3-01** — the plan claimed unix recursive removal unlinks a reparse point. It **refuses**
   (`fs.rs:1606`); following the plan would have deleted a workspace containing a junction and
   returned `Ok(())` where unix fails closed.
5. **R5-01** — the plan hedged that `tauri::test::mock_app` might not run on Windows. It already
   does (`progress.rs:607`, `main.rs:4560`), and taking the hedge would have left
   `create_workspace_directory` with no assertion at all.

Rounds 4, 5 and 6 each replaced a correction with a **smaller** one, twice by finding that an
existing test already covered what a new module was being written for.

The single most valuable thread was `review-tests`', held across rounds 1-6: **nothing in the plan
could distinguish a real port from a stub returning `Ok(vec![])`**, because every workspace test was
`#[cfg(unix)]`. That produced obligation D5 and its governing principle — an un-gated test beats a
`#[cfg(windows)]` one, because reverting a Windows arm then reddens the Linux run too. The
orchestrator falsified it after implementation: reintroducing a `#[cfg(not(unix))]` counterpart for
`mutation_target` turned two Linux-executing tests red.

## The standing limitation

**No Windows runtime executed one line of this port.** This machine has a MinGW cross-compiler
only. Every Windows claim rests on a cross-target type-check, on source pins in
`infra/platform_support.rs` that execute on Linux by comparing source text, and on tests whose first
real execution is the `rust-windows-test` CI job on this push. The preceding Windows port shipped
nine compile errors past four review lenses, and the review of *this* port still found a defect no
pin could see — `open_windows_child` opening asynchronous file objects — which is the honest measure
of what source pins can and cannot prove.
