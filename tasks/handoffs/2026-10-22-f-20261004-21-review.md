### O1 — Puzzle listing uses the existing root-only post-failure probe

After workspace selection, a failed puzzle child listing passes through `probe_listing_root_failure` with the same selected handle, `PuzzleRead` and request cancellation token. ### O2 — Engine root provenance is established at filesystem boundaries

Use the existing root-label mapping at proven engine-root validation/acquisition failures. Carry the validated engine-root context into the filesystem resolver's root portion so root metadata, identity and native open failures can be labelled without labelling capability admission, operation checks, components or descendant traversal. Scope this to actual EngineRoot use under DownloadArchive and EngineInstall, do not change all resolve callers or classify by message text. A permission failure from an open that requested write access is not sufficient evidence of read/search denial. Before assigning permission in that case, independently prove failure of read/search-only root access. If read/search access succeeds, retain the original unlabelled write failure. The independent check must retain the original operation's capability authorization while requesting only the filesystem access being diagnosed, it must neither grant installation authority through a weaker operation nor persist catalog-use state.

Cover destination acquisition, archive-child resolution, adoption, staging, publication and installed-executable registration. Label direct root acquisition errors at their producer, subject to the independent read/search-evidence requirement above. For a filesystem step that genuinely mixes retained-root access and child access, recheck only the same root after that step fails and after releasing the authority guard. Extend the shared root probe's internal acquisition path for the engine read/search-only check and reuse its cancellation/error-preservation behavior rather than copying it. Existing listing callers keep their original access and bound semantics. The engine use accepts only changed, missing, unusable or permission evidence, an enumeration bound is inconclusive for a non-listing operation and leaves the original failure unchanged. This must not impose a listing limit on successful engine installation.

Post-failure probing is limited to the relevant filesystem substep, never the entire install, catalog transaction or generic resolve result. Scratch, transport, digest/signature, archive validation, child inventory, registry persistence, commit/durability and configuration failures do not gain a label merely because a root also became unavailable. Distinguish these boundaries structurally rather than matching error strings. A root with revoked search permission must be diagnosed even if a retained descriptor or empty-component resolve still succeeds.

Preserve no-follow and identity checks, operation validation, retained-parent ownership, staging cleanup, pending provenance, publication/commit ordering, cancellation and recovery of the same selected root. Do not write probe artefacts, clear the active selection or create a default on failure. A cancellation check must not replace an already committed outcome with a claim that publication never occurred.
