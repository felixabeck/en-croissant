## Approach

### O1 — Guarded baseline writer (MANDATE 1)

* `--write-baseline` computes the new report as today, then compares it per area and per metric
  against the **prior baseline**: the version of the `--baseline` path at `git HEAD` when that path
  is tracked in the repository containing it; otherwise the file on disk if it exists; otherwise
  there is no prior (a first baseline, nothing can decrease).
* **Git semantics.** Run in the baseline file's directory: (1) `git rev-parse
  --is-inside-work-tree` — exit 0 → repository mode; exit non-zero with "not a git repository" on
  stderr → disk mode (prior = the file on disk, or none); anything else, including a spawn error
  (git missing), refuses. (2) In repository mode, `git ls-tree --full-name HEAD -- <file>` — exit 0
  with empty output → the path is not committed → disk mode; exit 0 with one entry → prior =
  `git show HEAD:<full name>`, which must exit 0 or the write refuses; non-zero exit (e.g. an
  unborn `HEAD`) refuses. Every refusal names the git command and its stderr, happens before
  anything is written, and leaves the baseline file byte-identical; a spawn failure's message
  includes the spawn error's `code` and `message` (git's stderr is empty then).
* **Prior validation.** Before comparing, the prior baseline must be `version: 1` with an `areas`
  object whose every area carries `lines`/`functions`/`branches` with non-negative integer
  `covered ≤ total`; anything else refuses before writing (a `"covered": "bad"` would otherwise
  make every comparison false and let a decrease through). Validation covers the metrics of the
  areas the prior records; a difference between the prior's and the report's **area sets**
  (a tracked `areas: {}`, a missing area, an added area) is not an invalid prior but an area-set
  change, handled by the next bullet.
* **Scope and area-set changes need the same authorization.** When a prior exists and its
  recorded `scope` differs from the new `scopeSignature(config)`, or its area set differs from the
  report's, the write refuses without `--instrument-change`/`--finding` exactly as a decrease does,
  and prints which scope keys and areas changed; with a valid authorization it is accepted (areas
  only in the report are printed as new, areas only in the prior as removed). A narrowing through an `exclude` glob can shrink
  totals, keep `covered`, raise every ratio, and would otherwise be recorded — overwriting the
  signature that exists to catch it (`docs/coverage.md`). (O4's re-record changes the scope, so it
  is authorized through the same flags.)
* A **decrease** is, per area and metric: `covered` lower than prior `covered`, or the ratio
  `covered/total` lower than the prior ratio (cross-multiplied, as `assertBaseline` does), where
  a metric with `total = 0` counts as 100 % exactly as `assertAreaFloors` reads it — so `0/0 → 0/1`
  is a decrease. No
  shrink allowance is applied — the writer is stricter than the ratchet by design
  (`docs/coverage.md`: an upward refresh uses no shrink allowance). An area present in the prior
  baseline and absent from the new report is a decrease of everything it recorded.
* It prints one line per area and metric, before → after (`covered/total` and percentage to two
  decimals), marking decreases, **before** deciding — both on a refused and on an accepted write.
* With any decrease and no `--instrument-change`, it refuses: non-zero exit, message naming each
  decreased area/metric and the flag, and **the baseline file is not touched** (the check runs
  before `writeBaseline` creates its temporary file).
* `--instrument-change <d-id> --finding <f-id>` authorizes decreases only when, in
  `tasks/decisions.md` (resolved from the process cwd, as every other path in this CLI), a
  `### <d-id> — …` entry exists whose `* **Governs:**` line names `<f-id>` as a whole id token.
  Each unmet condition (no decisions file, no such entry, `Governs:` does not name the finding)
  refuses with a message naming it. `--finding` is required with `--instrument-change` because
  "names the finding being landed" cannot be checked without knowing the finding; either flag
  without `--write-baseline`, or one without the other, is a usage error. (No further conditions
  — superseded status, finding existence — are added; MANDATE 1 names exactly this one.)
* The authorized write prints the decision and finding it was authorized by.
* Tests (`scripts/coverage-report-tests.mjs`), each red if the refusal is removed or weakened;
  **every refusal case asserts exit 1 and a byte-identical baseline file** (content compared
  before and after), and one refused and one accepted write each assert a delta line for every
  area × metric (`lines`/`functions`/`branches`) of a fixture with **at least two areas**:
  a covered-count decrease **with the ratio level** (10/20 → 9/18) is refused and leaves the file
  byte-identical; a ratio-only decrease
  (covered up, total up more) is refused; a removed area is refused; an increase-only write
  succeeds and prints deltas; `--instrument-change` with a decision that does not govern the
  finding / governs only an adjacent id (`f-20260829-040` when `f-20260829-04` is requested) /
  does not exist / a missing decisions file is refused; a valid decision authorizes the
  decrease; an invalid prior baseline refuses — `"covered": "bad"`, `covered: -1`,
  `covered > total`, fractional `covered: 1.5` and fractional `total: 2.5`, each as its own case;
  `0/0 → 0/1` refuses; an added area is refused without and accepted with authorization; a tracked prior with
  `areas: {}` and one missing a reported area refuse; a scope-only change that raises every ratio
  (an uncovered file moved to `exclude`) refuses without the flags and is accepted with them; the HEAD version is the prior when the path is tracked and the working copy was edited
  downward (scratch `git init` repo); an untracked baseline inside a repository uses the disk
  file, and an absent one in a repository is written as a first baseline; each git failure —
  spawn failure (a `PATH` without `git`; message asserted to name `ENOENT`), `rev-parse` failing
  with a message other than "not a git repository", `ls-tree` failing (unborn `HEAD`), `git show`
  failing for a committed path (the last two failures besides unborn `HEAD` staged with a scratch

* **Attribute groups.** On masked text, an outer attribute group is a maximal run of `#[…]`
  (bracket-balanced) separated only by whitespace. A group is **test-only** when any `cfg(…)`
  attribute in it evaluates to definite false under the three-valued rule: every atom in the
  configured list is false, every other atom (`unix`, `windows`, `target_os = …`, `feature = …`,
  `debug_assertions`, …) unknown; `not` negates (unknown stays unknown), `all` is false if any
  argument is false and true only if all are true, `any` is true if any is true and false only if
  all are false; `all()` true, `any()` false. `cfg_attr(P, a₁, …, aₙ)` applies its attributes
  only when `P` holds, so a `cfg(Q)` reached through nested `cfg_attr`s with conditions
  `P₁ … Pₖ` contributes `any(not(all(P₁, …, Pₖ)), Q)` — the enclosing conditions compose.
  `#[cfg_attr(not(test), cfg(test))]` therefore excludes, and
  `#[cfg_attr(test, cfg_attr(not(test), cfg(test)))]` does not (its inner `cfg` is never
  applied). So `cfg(test)`, `cfg(all(test, unix))`, `cfg(not(not(test)))` exclude;
  `cfg(any(test, windows))`, `cfg(not(test))`, `cfg(unix)`, `cfg_attr(test, allow(x))` do not. An
  unparseable `cfg(…)`/`cfg_attr(…)` predicate throws with file:line. Attribute *positions* are
  found on the masked text, but each predicate is parsed from the **original** source span at the
  same offsets (the masker blanks string literals including their quotes, so
  `#[cfg(target_os = "macos")]` at `src-tauri/src/main.rs:2120` would otherwise lose its value and

## Risks / open questions

  test-only item would leave test code measured. Mitigations: closers bound every extent to its
  enclosing construct; fixture tests per shape; the **production-map oracle** of O4 (checks (a)
  overrun and (b) under-exclusion against the compiler's own non-test coverage maps for Linux and
  Windows, macOS where buildable). The probe is disposable, not committed (rule 6d: a one-off
  probe answering one question for this landing; the permanent form is filed separately). The
  earlier strip-and-compile probe is withdrawn: the per-target maps subsume it (R4-06).
