## Threat model and non-goals

*Frozen in round 1.*

* **Adversary in scope:** the one path containment already defends against. That is a local
  process running as the same or another user that can create, rename or replace entries,
  including junctions and other reparse points, inside a directory the application writes to. It
  also covers a process that tries to open, rename or delete the private temporary between its
  creation and its commit.
* **What sharing protects:** the private temporary's sharing mask
  (`FILE_SHARE_PRIVATE_TEMP = FILE_SHARE_WRITE`) is what refuses a concurrent read, rename or
  delete opener while the handle is held (`d-20260917-09`). The traversal sharing
  (`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` under `allow_delete_share`) is
  what lets other openers coexist with the application's held handles. Sharing does not
  contribute to containment. Containment comes from `RootDirectory`, the single-leaf name,
  `OBJ_DONT_REPARSE`, `FILE_OPEN_REPARSE_POINT` and the post-open reparse refusal.
* **Environments that count:** Windows (MSVC and GNU targets). Linux and macOS never compile
  either function; they see only the source pins.
* **Non-goals:** changing the sharing, access, disposition or descriptor of any existing
  `open_windows_child` caller; widening `FILE_SHARE_PRIVATE_TEMP` (`d-20260917-09`); replacing
  `open_windows_child`'s positional `bool` arguments at its ~30 call sites; the non-NT
  `open_windows_nofollow` pathname open; the `FILE_RENAME_INFORMATION` and other NT calls in
  `win::rename_child`.

## Approach

### O1 — one NT child-create primitive

Rests on the MANDATE words "two hand-written `NtCreateFile` invocations with the same 40-line
shape" and "Should `open_windows_child` become the single NT open for this crate".

A new `#[cfg(windows)] pub(crate)` primitive in `infra/path_authority/mod.rs`, beside
`open_windows_child`, becomes the only `NtCreateFile` call in `src-tauri/src`. It takes the
directory handle, the leaf name and one request value: disposition, access mask, security
descriptor pointer, directory-or-file kind, and share mask. A request value is used because an
eighth positional parameter would trip clippy's `too_many_arguments` under `-D warnings` (P8),
and adding an `allow` is rejected. The primitive keeps every containment property P1 has today,
unchanged and unconditional:

* `single_leaf` refusal, followed by the checked `unicode_string_lengths` guard.
* `RootDirectory` set to the directory handle, with `OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE`.
* `CreateOptions = FILE_OPEN_REPARSE_POINT | FILE_SYNCHRONOUS_IO_NONALERT | (FILE_DIRECTORY_FILE
  or FILE_NON_DIRECTORY_FILE)`.
* `FileAttributes = 0`.
* Status mapping through `windows_open_status_error`.
* The post-open reparse refusal.

The share mask is the only value the caller supplies that P1 hardcodes today. No other field
becomes newly configurable.

**Failure semantics:** identical to P1 for every input (`InvalidInput` for a bad leaf or an
over-long name, the mapped NT status, `InvalidInput` for a reparse point).

### O2 — `open_windows_child` keeps its contract

Rests on the MANDATE words "a parameter that can weaken sharing for all eight existing callers".

`open_windows_child` keeps its exact signature and its traversal sharing policy
(`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` when `allow_delete_share`). It
delegates to O1. None of its ~30 call sites changes (P2), so no existing caller can be handed a
different sharing mask by this change. The boundary function grows no share parameter. The
share mask becomes a parameter only of the lower primitive, whose other caller is the private
temporary.

### O3 — the private temporary routes through O1

Rests on the MANDATE words "so `open_temp_child` can route through it" and "the temporary must
stay private until it is committed".

`open_temp_child` stops hand-laying NT structures. It calls O1 with `FILE_CREATE`,
`TEMP_ACCESS`, the `PrivateSecurityDescriptor` pointer, the file kind and
`FILE_SHARE_PRIVATE_TEMP`, which keeps its current value `FILE_SHARE_WRITE` (`d-20260917-09`).
The `PrivateSecurityDescriptor` must outlive the call; it already does, because `create_temp`
owns it across the retry loop. The function's own `OBJ_*` constants, and any imports in
`mod win` that only it used, are removed if no other user remains.

**Behaviour deltas for the temporary, all toward the stricter P1 behaviour:**

* It gains the `single_leaf` refusal and the checked length guard (P3).
* It gains the post-open reparse refusal.
* `FileAttributes` changes from `FILE_ATTRIBUTE_NORMAL` to `0`, matching `create_regular_at`'s
  existing `FILE_CREATE` through P1. Microsoft documents `FileAttributes` as defaulting to
  normal and as "applied only when the file is created". This is a documentation premise, not a
  measurement, and the Windows runner verifies it (O5).
* Collision mapping is unchanged (`windows_open_status_error`), so `create_temp`'s retry
  predicate is unaffected (P4).

### O4 — source pins follow the single site

Rests on the MANDATE word "single", and on `d-20260917-03`, which treats pins as necessary.

The pins in P6 are updated to read the new shape rather than deleted:

* **Single-site pin.** The two files that hold the NT FFI (`infra/fs.rs`,
  `infra/path_authority/mod.rs`) together contain exactly one `NtCreateFile(` call, and it sits
  in the O1 primitive. The pin turns red if a second hand-laid site returns.
* **Synchronous-I/O pin.** It asserts `FILE_SYNCHRONOUS_IO_NONALERT` in the one primitive's
  `CreateOptions`.
* **Single-leaf and length-guard pins.** They read the primitive.
* **Private-temporary pin.** It asserts that `open_temp_child` passes `FILE_CREATE`,
  `FILE_SHARE_PRIVATE_TEMP` and `security_descriptor.as_ptr()` to the primitive and never names
  `FILE_SHARE_READ`. It keeps the `const FILE_SHARE_PRIVATE_TEMP: u32 = FILE_SHARE_WRITE`
  assertion.
* **Traversal-share pin.** `open_windows_child`'s delegation passes
  `FILE_SHARE_READ|FILE_SHARE_WRITE` plus `FILE_SHARE_DELETE` gated on `allow_delete_share`.

Call-site pins (1095, 1100, 1131) stay untouched because no call site changes. Each changed or
new pin's assertions are seen to fail once by editing the source they read (the staged-failure
practice of `d-20260917-09`). The failure output is quoted in the phase report, and the source
is then restored.

### O5 — Windows runtime proof of privacy

Rests on the MANDATE words "a test that a second open of the private temporary is refused while
it is held, run on a Windows runner".

A new `#[cfg(windows)]` test in `infra/fs.rs`'s test module creates a private temporary through
`win::create_temp` on a `windows_test_parent` directory and holds the returned handle. The test
needs only the visibility change that makes `create_temp` callable from the tests module. While
the handle is held, the test asserts two things. A plain `std::fs::File::open` of the
temporary's path fails with `raw_os_error() == Some(ERROR_SHARING_VIOLATION)` (32) and not with
access denied. A `std::fs::rename` of it also fails with `ERROR_SHARING_VIOLATION`. The
constant is taken from `windows_sys`, not spelled locally. The test also writes and reads back
through the held handle, proving the handle is still a synchronous, usable file object after
the refactor. After the handle is dropped, the temporary is removed and the directory holds no
`.atomic-` entry.

A second `#[cfg(windows)]` test injects a non-single-leaf temp name (for example `"a\\b"`)
through `win::scoped_test_temp_names`. It asserts that `create_temp` returns
`Error::InvalidInput` and creates nothing, which proves the temporary open now goes through
O1's leaf refusal (P3).

**Verification level:** these execute only on `rust-windows-test` (P9). Locally they are proven
to compile and lint through `pnpm rust:windows:check`.

## Decisions and trade-offs

* **Answer to the open question: neither of the two offered shapes.** The single NT site is a
  lower primitive with a share-mask parameter (O1). `open_windows_child` keeps its signature and
  traversal sharing (O2). The temporary passes its private mask (O3). Rejected, (a): adding
  `share_access` to `open_windows_child` itself. That puts a raw mask on the boundary function's
  ~30 call sites (or a typed enum with the same churn) and exposes every traversal caller to a
  wrong mask, for no containment gain. Rejected, (b): keeping two sites. P3 shows the
  duplication has already cost the temporary three containment checks, which is the drift rule
  11 exists to stop.
* **Sharing is not containment** (threat model). Routing the temporary through the containment
  primitive strengthens it. The temporary's sharing stays exactly as private as today.
* **`FileAttributes = 0`** for every create, rather than carrying an attribute field only the
  temporary would set (O3).
* **The reparse refusal stays unconditional**, also on `FILE_CREATE`, as `create_regular_at`
  already has it. Rejected: skipping it on `FILE_CREATE` to save one query, which would make the
  primitive's guarantee depend on the disposition.

## Decided autonomously

* **Question:** Does `open_windows_child` become the single NT open with a `share_access`
  parameter, or does the private-temporary open stay a separate `NtCreateFile` site?
  **Chosen:** a lower `#[cfg(windows)]` primitive in `infra/path_authority/mod.rs` owns the only
  `NtCreateFile` call and takes the share mask in a request value. `open_windows_child` keeps
  its signature and traversal sharing and delegates to it, and `open_temp_child` delegates with
  `FILE_SHARE_PRIVATE_TEMP`. **Rejected:** (a) a share parameter on `open_windows_child`, with
  its ~30-call-site churn and a mask exposed to every traversal caller; (b) two sites, whose
  drift already dropped `single_leaf`, the length guard and the reparse refusal from the
  temporary. **Reason:** sharing is not part of containment, so one primitive with the mask as
  a parameter keeps the boundary function narrow and gives the temporary every containment
  check. A Windows runtime now exists in CI, which removes the original verification reason for
  deferring. **Governs:** f-20260916-11.
* **Question:** What `FileAttributes` does the unified create pass? **Chosen:** `0`, as
  `create_regular_at` already does through `open_windows_child`. **Rejected:** a per-call
  attribute field that preserves the temporary's `FILE_ATTRIBUTE_NORMAL`. **Reason:** the API
  documents normal as the default and attributes as applied only at creation. The runner
  verifies it. **Governs:** f-20260916-11.

## Risks / open questions

* **R1.** Windows-only behaviour (sharing violation codes, attribute default) is not observable
  on this machine. It is verified only by `rust-windows-test` after the push (P9). A red job
  returns to repair under push skill §4.
* **R2.** Known limit, not new in kind: if the post-open `metadata()` query fails after a
  successful `FILE_CREATE`, the created object stays on disk with no handle. `create_regular_at`
  has had this since the port. The temporary acquires it through O3. The query runs against a
  handle that holds `GENERIC_READ` and was just created, so it is not expected to fail.
* **R3.** `ERROR_SHARING_VIOLATION` versus `ERROR_ACCESS_DENIED` ordering. The DACL grants the
  token user (`d-20260917-07`), so access is expected to pass and sharing to refuse. The runner
  decides it, and if the runner contradicts it, O5's expectation is revisited with that
  evidence, never weakened to "any error".

* Any change to `FILE_SHARE_PRIVATE_TEMP`, `TEMP_ACCESS`, `TARGET_ACCESS` or
  `PrivateSecurityDescriptor`.
* `open_windows_nofollow`, `win::rename_child`, and every other NT call.
* f-20260916-08, f-20260916-09 and f-20260916-10.

## Threat model and non-goals

*Frozen in round 1.*

* **Adversary in scope:** the one path containment already defends against. That is a local
  process running as the same or another user that can create, rename or replace entries,
  including junctions and other reparse points, inside a directory the application writes to. It
  also covers a process that tries to open, rename or delete the private temporary between its
  creation and its commit.
* **What sharing protects:** the private temporary's sharing mask
  (`FILE_SHARE_PRIVATE_TEMP = FILE_SHARE_WRITE`) is what refuses a concurrent read, rename or
  delete opener while the handle is held (`d-20260917-09`). The traversal sharing
  (`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` under `allow_delete_share`) is
  what lets other openers coexist with the application's held handles. Sharing does not
  contribute to containment. Containment comes from `RootDirectory`, the single-leaf name,
  `OBJ_DONT_REPARSE`, `FILE_OPEN_REPARSE_POINT` and the post-open reparse refusal.
* **Environments that count:** Windows (MSVC and GNU targets). Linux and macOS never compile
  either function; they see only the source pins.
* **Non-goals:** changing the sharing, access, disposition or descriptor of any existing
  `open_windows_child` caller; widening `FILE_SHARE_PRIVATE_TEMP` (`d-20260917-09`); replacing
  `open_windows_child`'s positional `bool` arguments at its ~30 call sites; the non-NT
  `open_windows_nofollow` pathname open; the `FILE_RENAME_INFORMATION` and other NT calls in
  `win::rename_child`.

## Approach

### O1 — one NT child-create primitive

Rests on the MANDATE words "two hand-written `NtCreateFile` invocations with the same 40-line
shape" and "Should `open_windows_child` become the single NT open for this crate".

A new `#[cfg(windows)] pub(crate)` primitive in `infra/path_authority/mod.rs`, beside
`open_windows_child`, becomes the only `NtCreateFile` call in `src-tauri/src`. It takes the
directory handle, the leaf name and one request value: disposition, access mask, security
descriptor pointer, directory-or-file kind, and share mask. A request value is used because an
eighth positional parameter would trip clippy's `too_many_arguments` under `-D warnings` (P8),
and adding an `allow` is rejected. The primitive keeps every containment property P1 has today,
unchanged except for the outcome scoping of the reparse refusal below:

* `single_leaf` refusal, followed by the checked `unicode_string_lengths` guard.
* `RootDirectory` set to the directory handle, with `OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE`.
* `CreateOptions = FILE_OPEN_REPARSE_POINT | FILE_SYNCHRONOUS_IO_NONALERT | (FILE_DIRECTORY_FILE
  or FILE_NON_DIRECTORY_FILE)`.
* `FileAttributes = 0`.
* Status mapping through `windows_open_status_error`.
* The post-open reparse refusal, scoped by outcome as below.

The share mask is the only value the caller supplies that P1 hardcodes today. No other field
becomes newly configurable.

**The reparse refusal is scoped by outcome, not by disposition (r2, I1/I3).** It runs for every
object the call *opened*, meaning `IO_STATUS_BLOCK.Information` is anything other than
`FILE_CREATED`. It is skipped exactly when the call reports `FILE_CREATED`. A created object
did not exist before the call: `FILE_CREATE` and `FILE_OPEN_IF` create only when the name is
absent, and `OBJ_DONT_REPARSE` plus `FILE_OPEN_REPARSE_POINT` turn an existing reparse point at
the name into a collision or an opened object, never a traversal. No EA buffer is passed, so
the created object carries no reparse data. Nothing fallible then runs between a successful
create and the return of its handle, so the primitive has **no path that leaves a created
object on disk without returning its handle**. That is what lets `create_temp`'s caller own
cleanup from the first instant: `infra/fs.rs:806` propagates `create_temp` errors before it
holds the name. The `FILE_CREATED` value comes from `windows-sys` if the crate exports it;
otherwise a local constant carries it, with its value (2) pinned. The statement "created
implies not a reparse point" is a documented-API premise (NtCreateFile
`IoStatusBlock->Information`), not a measurement, and nothing on this machine can measure it.

**Failure semantics:** identical to P1 for every opened object (`InvalidInput` for a bad leaf
or an over-long name, the mapped NT status, `InvalidInput` for a reparse point). For a created
object the only failures are the pre-call refusals and the mapped NT status, and none of them
leaves anything on disk.

### O2 — `open_windows_child` keeps its contract

Rests on the MANDATE words "a parameter that can weaken sharing for all eight existing callers".

`open_windows_child` keeps its exact signature and its traversal sharing policy
(`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` when `allow_delete_share`). It
delegates to O1. None of its ~30 call sites changes (P2), so no existing caller can be handed a
different sharing mask by this change. The boundary function grows no share parameter. The
share mask becomes a parameter only of the lower primitive, whose other caller is the private
temporary.

### O3 — the private temporary routes through O1

Rests on the MANDATE words "so `open_temp_child` can route through it" and "the temporary must
stay private until it is committed".

`open_temp_child` stops hand-laying NT structures. It calls O1 with `FILE_CREATE`,
`TEMP_ACCESS`, the `PrivateSecurityDescriptor` pointer, the file kind and
`FILE_SHARE_PRIVATE_TEMP`, which keeps its current value `FILE_SHARE_WRITE` (`d-20260917-09`).
The `PrivateSecurityDescriptor` must outlive the call; it already does, because `create_temp`
owns it across the retry loop. The function's own `OBJ_*` constants, and any imports in
`mod win` that only it used, are removed if no other user remains.

**Behaviour deltas for the temporary, all toward the stricter P1 behaviour:**

* It gains the `single_leaf` refusal and the checked length guard (P3).
* It always reports `FILE_CREATED` (disposition `FILE_CREATE`), so under O1's outcome scoping
  it runs no post-create query and acquires no orphan path (r2, I1).
* `FileAttributes` changes from `FILE_ATTRIBUTE_NORMAL` to `0`, matching `create_regular_at`'s
  existing `FILE_CREATE` through P1. Microsoft documents `FileAttributes` as defaulting to
  normal and as "applied only when the file is created". This is a documentation premise, not a
  measurement, and the Windows runner verifies it (O5).
* Collision mapping is unchanged (`windows_open_status_error`), so `create_temp`'s retry
  predicate is unaffected (P4).

### O4 — source pins follow the single site

Rests on the MANDATE word "single", and on `d-20260917-03`, which treats pins as necessary.

The pins in P6 are updated to read the new shape rather than deleted:

* **Single-site pin over the whole claimed scope (r2, I2).** Every Rust source under
  `src-tauri/src`, enumerated by the existing `rust_source_paths()` inventory
  (`platform_support/tests.rs:2293`), together contains exactly one `NtCreateFile(` call, and
  it sits in the O1 primitive. The pin file itself is the only exclusion, because its
  assertions quote the name. Its staged failure adds a duplicate call in a module **other
  than** the two current files.
* **Reparse-scope pin (r2, I3).** The O1 primitive's reparse refusal is conditioned on the
  `FILE_CREATED` outcome and on nothing else: not on the disposition argument, and not
  removed. Staged failures: (a) changing the condition to test the disposition (`FILE_OPEN` or
  `FILE_CREATE`) turns it red; (b) deleting the refusal turns it red. The opened-object refusal
  itself stays exercised at runtime by the existing Windows junction tests that reach
  `open_windows_child` (the `windows_test_junction` users, for example `infra/fs.rs:5371`,
  `:8992` and `:9172`).
* **Synchronous-I/O pin.** It asserts `FILE_SYNCHRONOUS_IO_NONALERT` in the one primitive's
  `CreateOptions`.
* **Single-leaf and length-guard pins.** They read the primitive.
* **Private-temporary pin.** It asserts that `open_temp_child` passes `FILE_CREATE`,
  `FILE_SHARE_PRIVATE_TEMP` and `security_descriptor.as_ptr()` to the primitive and never names
  `FILE_SHARE_READ`. It keeps the `const FILE_SHARE_PRIVATE_TEMP: u32 = FILE_SHARE_WRITE`
  assertion.
* **Traversal-share pin.** `open_windows_child`'s delegation passes
  `FILE_SHARE_READ|FILE_SHARE_WRITE` plus `FILE_SHARE_DELETE` gated on `allow_delete_share`.

Call-site pins (1095, 1100, 1131) stay untouched because no call site changes. Each changed or
new pin's assertions are seen to fail once by editing the source they read (the staged-failure
practice of `d-20260917-09`). The failure output is quoted in the phase report, and the source
is then restored.

### O5 — Windows runtime proof of privacy

Rests on the MANDATE words "a test that a second open of the private temporary is refused while
it is held, run on a Windows runner".

A new `#[cfg(windows)]` test in `infra/fs.rs`'s test module creates a private temporary through
`win::create_temp` on a `windows_test_parent` directory and holds the returned handle. The test
needs only the visibility change that makes `create_temp` callable from the tests module. While
the handle is held, the test asserts two things. A plain `std::fs::File::open` of the
temporary's path fails with `raw_os_error() == Some(ERROR_SHARING_VIOLATION)` (32) and not with
access denied. A `std::fs::rename` of it also fails with `ERROR_SHARING_VIOLATION`. The
constant is taken from `windows_sys`, not spelled locally. The test also writes and reads back
through the held handle, proving the handle is still a synchronous, usable file object after
the refactor. After the handle is dropped, the temporary is removed and the directory holds no
`.atomic-` entry.

A second `#[cfg(windows)]` test injects a non-single-leaf temp name (for example `"a\\b"`)
through `win::scoped_test_temp_names`. It asserts that `create_temp` returns
`Error::InvalidInput` and creates nothing, which proves the temporary open now goes through
O1's leaf refusal (P3).

**Verification level:** these execute only on `rust-windows-test` (P9). Locally they are proven
to compile and lint through `pnpm rust:windows:check`.

## Decisions and trade-offs

* **Answer to the open question: neither of the two offered shapes.** The single NT site is a
  lower primitive with a share-mask parameter (O1). `open_windows_child` keeps its signature and
  traversal sharing (O2). The temporary passes its private mask (O3). Rejected, (a): adding
  `share_access` to `open_windows_child` itself. That puts a raw mask on the boundary function's
  ~30 call sites (or a typed enum with the same churn) and exposes every traversal caller to a
  wrong mask, for no containment gain. Rejected, (b): keeping two sites. P3 shows the
  duplication has already cost the temporary three containment checks, which is the drift rule
  11 exists to stop.
* **Sharing is not containment** (threat model). Routing the temporary through the containment
  primitive strengthens it. The temporary's sharing stays exactly as private as today.
* **`FileAttributes = 0`** for every create, rather than carrying an attribute field only the
  temporary would set (O3).
* **The reparse refusal is scoped by outcome (`FILE_CREATED`), not by disposition.** This
  replaces r1's "unconditional" (r2). Round 1 brought new evidence: an unconditional
  post-create `metadata()` query is a fallible step after creation, and `create_temp`'s caller
  propagates its error before it owns cleanup (`infra/fs.rs:806`), so a failure there would
  orphan a private temporary. Rejected, (a): keeping the refusal unconditional and deleting the
  created object on failure inside the primitive. That needs `DELETE` access the traversal
  callers do not request, and it pulls `fs::win`'s delete-by-handle into `path_authority`.
  Rejected, (b): keeping it unconditional and naming the orphan a known limit, because the
  orphan path is new for the temporary. Rejected, (c): scoping by the `disposition` argument,
  because `FILE_OPEN_IF` can open an existing object, which must still be checked.

## Decided autonomously

* **Question:** Does `open_windows_child` become the single NT open with a `share_access`
  parameter, or does the private-temporary open stay a separate `NtCreateFile` site?
  **Chosen:** a lower `#[cfg(windows)]` primitive in `infra/path_authority/mod.rs` owns the only
  `NtCreateFile` call and takes the share mask in a request value. `open_windows_child` keeps
  its signature and traversal sharing and delegates to it, and `open_temp_child` delegates with
  `FILE_SHARE_PRIVATE_TEMP`. **Rejected:** (a) a share parameter on `open_windows_child`, with
  its ~30-call-site churn and a mask exposed to every traversal caller; (b) two sites, whose
  drift already dropped `single_leaf` and the length guard from the temporary.
  **Reason:** sharing is not part of containment, so one primitive with the mask as a
  parameter keeps the boundary function narrow and gives the temporary every containment check
  that applies to a created object. A Windows runtime now exists in CI, which removes the original verification reason for
  deferring. **Governs:** f-20260916-11.
* **Question:** What `FileAttributes` does the unified create pass? **Chosen:** `0`, as
  `create_regular_at` already does through `open_windows_child`. **Rejected:** a per-call
  attribute field that preserves the temporary's `FILE_ATTRIBUTE_NORMAL`. **Reason:** the API
  documents normal as the default and attributes as applied only at creation. The runner
  verifies it. **Governs:** f-20260916-11.
* **Question:** Does the single NT primitive's reparse refusal run on created objects?
  **Chosen:** no. It runs on every object the call opened and is skipped exactly when
  `IO_STATUS_BLOCK.Information == FILE_CREATED`. **Rejected:** unconditional, which adds a
  fallible post-create step that orphans a private temporary, because `create_temp`'s caller
  owns cleanup only after `create_temp` returns; delete-on-failure inside the primitive, which
  needs `DELETE` access and an fs-to-path_authority dependency; scoping by the disposition
  argument, because `FILE_OPEN_IF` may open an existing object. **Reason:** a created object
  did not exist before the call and carries no reparse data. Scoping by outcome keeps every
  opened object checked and leaves no orphan path. **Governs:** f-20260916-11.

# Plan: one NtCreateFile site for descriptor-relative Windows child opens (f-20260916-11)

## Goal

The crate issues `NtCreateFile` from exactly one function. The private-temporary open in
`infra/fs.rs` and the traversal open `open_windows_child` both reach the OS through it. Each keeps
its own sharing intent. No caller's observable behaviour changes, with two exceptions: the
temporary open gains the leaf and length checks, and the post-open reparse query is dropped for
objects the call itself created (O1).

## Threat model and non-goals

*Frozen in round 1.*

* **Adversary in scope:** the one path containment already defends against. That is a local
  process running as the same or another user that can create, rename or replace entries,
  including junctions and other reparse points, inside a directory the application writes to. It
  also covers a process that tries to open, rename or delete the private temporary between its
  creation and its commit.
* **What sharing protects:** the private temporary's sharing mask
  (`FILE_SHARE_PRIVATE_TEMP = FILE_SHARE_WRITE`) is what refuses a concurrent read, rename or
  delete opener while the handle is held (`d-20260917-09`). The traversal sharing
  (`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` under `allow_delete_share`) is
  what lets other openers coexist with the application's held handles. Sharing does not
  contribute to containment. Containment comes from `RootDirectory`, the single-leaf name,
  `OBJ_DONT_REPARSE`, `FILE_OPEN_REPARSE_POINT` and the post-open reparse refusal.
* **Environments that count:** Windows (MSVC and GNU targets). Linux and macOS never compile
  either function; they see only the source pins.
* **Non-goals:** changing the sharing, access, disposition or descriptor of any existing
  `open_windows_child` caller; widening `FILE_SHARE_PRIVATE_TEMP` (`d-20260917-09`); replacing
  `open_windows_child`'s positional `bool` arguments at its ~30 call sites; the non-NT
  `open_windows_nofollow` pathname open; the `FILE_RENAME_INFORMATION` and other NT calls in
  `win::rename_child`.

## Approach

### O1 — one NT child-create primitive

Rests on the MANDATE words "two hand-written `NtCreateFile` invocations with the same 40-line
shape" and "Should `open_windows_child` become the single NT open for this crate".

A new `#[cfg(windows)] pub(crate)` primitive in `infra/path_authority/mod.rs`, beside
`open_windows_child`, becomes the only `NtCreateFile` call in `src-tauri/src`. It takes the
directory handle, the leaf name and one request value: disposition, access mask, security
descriptor pointer, directory-or-file kind, and share mask. A request value is used because an
eighth positional parameter would trip clippy's `too_many_arguments` under `-D warnings` (P8),
and adding an `allow` is rejected. The primitive keeps every containment property P1 has today,
unchanged except for the outcome scoping of the reparse refusal below:

* `single_leaf` refusal, followed by the checked `unicode_string_lengths` guard.
* `RootDirectory` set to the directory handle, with `OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE`.
* `CreateOptions = FILE_OPEN_REPARSE_POINT | FILE_SYNCHRONOUS_IO_NONALERT | (FILE_DIRECTORY_FILE
  or FILE_NON_DIRECTORY_FILE)`.
* `FileAttributes = 0`.
* Status mapping through `windows_open_status_error`.
* The post-open reparse refusal, scoped by outcome as below.

The share mask is the only value the caller supplies that P1 hardcodes today. No other field
becomes newly configurable.

**The reparse refusal is scoped by outcome, not by disposition (r2, I1/I3).** It runs for every
object the call *opened*, meaning `IO_STATUS_BLOCK.Information` is anything other than
`FILE_CREATED`. It is skipped exactly when the call reports `FILE_CREATED`. A created object
did not exist before the call: `FILE_CREATE` and `FILE_OPEN_IF` create only when the name is
absent, and `OBJ_DONT_REPARSE` plus `FILE_OPEN_REPARSE_POINT` turn an existing reparse point at
the name into a collision or an opened object, never a traversal. No EA buffer is passed, so
the created object carries no reparse data. Nothing fallible then runs between a successful
create and the return of its handle, so the primitive has **no path that leaves a created
object on disk without returning its handle**. That is what lets `create_temp`'s caller own
cleanup from the first instant: `infra/fs.rs:806` propagates `create_temp` errors before it
holds the name. The `FILE_CREATED` value comes from `windows-sys` if the crate exports it;
otherwise a local constant carries it, with its value (2) pinned. The statement "created
implies not a reparse point" is a documented-API premise (NtCreateFile
`IoStatusBlock->Information`), not a measurement, and nothing on this machine can measure it.

**Failure semantics:** identical to P1 for every opened object (`InvalidInput` for a bad leaf
or an over-long name, the mapped NT status, `InvalidInput` for a reparse point). For a created
object the only failures are the pre-call refusals and the mapped NT status, and none of them
leaves anything on disk.

### O2 — `open_windows_child` keeps its contract

Rests on the MANDATE words "a parameter that can weaken sharing for all eight existing callers".

`open_windows_child` keeps its exact signature and its traversal sharing policy
(`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` when `allow_delete_share`). It
delegates to O1. None of its ~30 call sites changes (P2), so no existing caller can be handed a
different sharing mask by this change. The boundary function grows no share parameter. The
share mask becomes a parameter only of the lower primitive, whose other caller is the private
temporary.

### O3 — the private temporary routes through O1

Rests on the MANDATE words "so `open_temp_child` can route through it" and "the temporary must
stay private until it is committed".

`open_temp_child` stops hand-laying NT structures. It calls O1 with `FILE_CREATE`,
`TEMP_ACCESS`, the `PrivateSecurityDescriptor` pointer, the file kind and
`FILE_SHARE_PRIVATE_TEMP`, which keeps its current value `FILE_SHARE_WRITE` (`d-20260917-09`).
The `PrivateSecurityDescriptor` must outlive the call; it already does, because `create_temp`
owns it across the retry loop. The function's own `OBJ_*` constants, and any imports in
`mod win` that only it used, are removed if no other user remains.

**Behaviour deltas for the temporary, all toward the stricter P1 behaviour:**

* It gains the `single_leaf` refusal and the checked length guard (P3).
* It always reports `FILE_CREATED` (disposition `FILE_CREATE`), so under O1's outcome scoping
  it runs no post-create query and acquires no orphan path (r2, I1).
* `FileAttributes` changes from `FILE_ATTRIBUTE_NORMAL` to `0`, matching `create_regular_at`'s
  existing `FILE_CREATE` through P1. Microsoft documents `FileAttributes` as defaulting to
  normal and as "applied only when the file is created". This is a documentation premise, not a
  measurement, and the Windows runner verifies it (O5).
* Collision mapping is unchanged (`windows_open_status_error`), so `create_temp`'s retry
  predicate is unaffected (P4).

### O4 — source pins follow the single site

Rests on the MANDATE word "single", and on `d-20260917-03`, which treats pins as necessary.

The pins in P6 are updated to read the new shape rather than deleted:

* **Single-site pin over the whole claimed scope (r2, I2).** Every Rust source under
  `src-tauri/src`, enumerated by the existing `rust_source_paths()` inventory
  (`platform_support/tests.rs:2293`), together contains exactly one `NtCreateFile(` call, and
  it sits in the O1 primitive. The pin file itself is the only exclusion, because its
  assertions quote the name. Its staged failure adds a duplicate call in a module **other
  than** the two current files.
* **Reparse-scope pin (r2, I3).** The O1 primitive's reparse refusal is conditioned on the
  `FILE_CREATED` outcome and on nothing else: not on the disposition argument, and not
  removed. Staged failures: (a) changing the condition to test the disposition (`FILE_OPEN` or
  `FILE_CREATE`) turns it red; (b) deleting the refusal turns it red.
* **Runtime anchor for the opened-object refusal (r3, I4).** None of the existing junction
  tests depends on this refusal alone: they reject the junction through pathname metadata,
  through `enumerated_kind`, or through a second reparse check in `directory_entry_at`. A new
  `#[cfg(windows)]` test goes into `infra/path_authority/mod.rs`'s Windows test module, beside
  `windows_child_open_maps_absence_and_refuses_wrong_target_types`. It creates a junction child
  with `windows_test_junction` and opens it directly through `open_windows_child` (`FILE_OPEN`,
  directory kind, read access). It asserts exactly
  `Error::InvalidInput("reparse points cannot be authorized")`. On that direct call
  `OBJ_DONT_REPARSE` plus `FILE_OPEN_REPARSE_POINT` open the junction object itself, and no
  other check exists that could produce that error. Deleting the primitive's refusal therefore
  turns the test red on `rust-windows-test`.
* **Synchronous-I/O pin.** It asserts `FILE_SYNCHRONOUS_IO_NONALERT` in the one primitive's
  `CreateOptions`.
* **Single-leaf and length-guard pins.** They read the primitive.
* **Private-temporary pin.** It asserts that `open_temp_child` passes `FILE_CREATE`,
  `FILE_SHARE_PRIVATE_TEMP` and `security_descriptor.as_ptr()` to the primitive and never names
  `FILE_SHARE_READ`. It keeps the `const FILE_SHARE_PRIVATE_TEMP: u32 = FILE_SHARE_WRITE`
  assertion.
* **Traversal-share pin.** `open_windows_child`'s delegation passes
  `FILE_SHARE_READ|FILE_SHARE_WRITE` plus `FILE_SHARE_DELETE` gated on `allow_delete_share`.

Call-site pins (1095, 1100, 1131) stay untouched because no call site changes. Each changed or
new pin's assertions are seen to fail once by editing the source they read (the staged-failure
practice of `d-20260917-09`). The failure output is quoted in the phase report, and the source
is then restored.

### O5 — Windows runtime proof of privacy

Rests on the MANDATE words "a test that a second open of the private temporary is refused while
it is held, run on a Windows runner".

A new `#[cfg(windows)]` test in `infra/fs.rs`'s test module creates a private temporary through
`win::create_temp` on a `windows_test_parent` directory and holds the returned handle. The test
needs only the visibility change that makes `create_temp` callable from the tests module. While
the handle is held, the test asserts two things. A plain `std::fs::File::open` of the
temporary's path fails with `raw_os_error() == Some(ERROR_SHARING_VIOLATION)` (32) and not with
access denied. A `std::fs::rename` of it also fails with `ERROR_SHARING_VIOLATION`. The
constant is taken from `windows_sys`, not spelled locally. The test also writes and reads back
through the held handle, proving the handle is still a synchronous, usable file object after
the refactor. After the handle is dropped, the temporary is removed and the directory holds no
`.atomic-` entry.

A second `#[cfg(windows)]` test injects a non-single-leaf temp name (for example `"a\\b"`)
through `win::scoped_test_temp_names`. It asserts that `create_temp` returns
`Error::InvalidInput` and creates nothing, which proves the temporary open now goes through
O1's leaf refusal (P3).

**Verification level:** these execute only on `rust-windows-test` (P9). Locally they are proven
to compile and lint through `pnpm rust:windows:check`.

## Decisions and trade-offs

* **Answer to the open question: neither of the two offered shapes.** The single NT site is a
  lower primitive with a share-mask parameter (O1). `open_windows_child` keeps its signature and
  traversal sharing (O2). The temporary passes its private mask (O3). Rejected, (a): adding
  `share_access` to `open_windows_child` itself. That puts a raw mask on the boundary function's
  ~30 call sites (or a typed enum with the same churn) and exposes every traversal caller to a
  wrong mask, for no containment gain. Rejected, (b): keeping two sites. P3 shows the
  duplication has already cost the temporary three containment checks, which is the drift rule
  11 exists to stop.
* **Sharing is not containment** (threat model). Routing the temporary through the containment
  primitive strengthens it. The temporary's sharing stays exactly as private as today.
* **`FileAttributes = 0`** for every create, rather than carrying an attribute field only the
  temporary would set (O3).
* **The reparse refusal is scoped by outcome (`FILE_CREATED`), not by disposition.** This
  replaces r1's "unconditional" (r2). Round 1 brought new evidence: an unconditional
  post-create `metadata()` query is a fallible step after creation, and `create_temp`'s caller
  propagates its error before it owns cleanup (`infra/fs.rs:806`), so a failure there would
  orphan a private temporary. Rejected, (a): keeping the refusal unconditional and deleting the
  created object on failure inside the primitive. That needs `DELETE` access the traversal
  callers do not request, and it pulls `fs::win`'s delete-by-handle into `path_authority`.
  Rejected, (b): keeping it unconditional and naming the orphan a known limit, because the
  orphan path is new for the temporary. Rejected, (c): scoping by the `disposition` argument,
  because `FILE_OPEN_IF` can open an existing object, which must still be checked.

## Decided autonomously

* **Question:** Does `open_windows_child` become the single NT open with a `share_access`
  parameter, or does the private-temporary open stay a separate `NtCreateFile` site?
  **Chosen:** a lower `#[cfg(windows)]` primitive in `infra/path_authority/mod.rs` owns the only
  `NtCreateFile` call and takes the share mask in a request value. `open_windows_child` keeps
  its signature and traversal sharing and delegates to it, and `open_temp_child` delegates with
  `FILE_SHARE_PRIVATE_TEMP`. **Rejected:** (a) a share parameter on `open_windows_child`, with
  its ~30-call-site churn and a mask exposed to every traversal caller; (b) two sites, whose
  drift already dropped `single_leaf` and the length guard from the temporary.
  **Reason:** sharing is not part of containment, so one primitive with the mask as a
  parameter keeps the boundary function narrow and gives the temporary every containment check
  that applies to a created object. A Windows runtime now exists in CI, which removes the original verification reason for
  deferring. **Governs:** f-20260916-11.
* **Question:** What `FileAttributes` does the unified create pass? **Chosen:** `0`, as
  `create_regular_at` already does through `open_windows_child`. **Rejected:** a per-call
  attribute field that preserves the temporary's `FILE_ATTRIBUTE_NORMAL`. **Reason:** the API
  documents normal as the default and attributes as applied only at creation. The runner
  verifies it. **Governs:** f-20260916-11.
* **Question:** Does the single NT primitive's reparse refusal run on created objects?
  **Chosen:** no. It runs on every object the call opened and is skipped exactly when
  `IO_STATUS_BLOCK.Information == FILE_CREATED`. **Rejected:** unconditional, which adds a
  fallible post-create step that orphans a private temporary, because `create_temp`'s caller
  owns cleanup only after `create_temp` returns; delete-on-failure inside the primitive, which
  needs `DELETE` access and an fs-to-path_authority dependency; scoping by the disposition
  argument, because `FILE_OPEN_IF` may open an existing object. **Reason:** a created object
  did not exist before the call and carries no reparse data. Scoping by outcome keeps every
  opened object checked and leaves no orphan path. **Governs:** f-20260916-11.

## Goal

The crate issues `NtCreateFile` from exactly one function. The private-temporary open in
`infra/fs.rs` and the traversal open `open_windows_child` both reach the OS through it. Each keeps
its own sharing intent. No caller's observable behaviour changes, with two exceptions: the
temporary open gains the leaf and length checks, and the post-open reparse query is dropped for
objects the call itself created (O1).

## Threat model and non-goals

*Frozen in round 1.*

* **Adversary in scope:** the one path containment already defends against. That is a local
  process running as the same or another user that can create, rename or replace entries,
  including junctions and other reparse points, inside a directory the application writes to. It
  also covers a process that tries to open, rename or delete the private temporary between its
  creation and its commit.
* **What sharing protects:** the private temporary's sharing mask
  (`FILE_SHARE_PRIVATE_TEMP = FILE_SHARE_WRITE`) is what refuses a concurrent read, rename or
  delete opener while the handle is held (`d-20260917-09`). The traversal sharing
  (`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` under `allow_delete_share`) is
  what lets other openers coexist with the application's held handles. Sharing does not
  contribute to containment. Containment comes from `RootDirectory`, the single-leaf name,
  `OBJ_DONT_REPARSE`, `FILE_OPEN_REPARSE_POINT` and the post-open reparse refusal.
* **Environments that count:** Windows (MSVC and GNU targets). Linux and macOS never compile
  either function; they see only the source pins.
* **Non-goals:** changing the sharing, access, disposition or descriptor of any existing
  `open_windows_child` caller; widening `FILE_SHARE_PRIVATE_TEMP` (`d-20260917-09`); replacing
  `open_windows_child`'s positional `bool` arguments at its ~30 call sites; the non-NT
  `open_windows_nofollow` pathname open; the `FILE_RENAME_INFORMATION` and other NT calls in
  `win::rename_child`.

## Approach

### O1 — one NT child-create primitive

Rests on the MANDATE words "two hand-written `NtCreateFile` invocations with the same 40-line
shape" and "Should `open_windows_child` become the single NT open for this crate".

A new `#[cfg(windows)] pub(crate)` primitive in `infra/path_authority/mod.rs`, beside
`open_windows_child`, becomes the only `NtCreateFile` call in `src-tauri/src`. It takes the
directory handle, the leaf name and one request value: disposition, access mask, security
descriptor pointer, directory-or-file kind, and share mask. A request value is used because an
eighth positional parameter would trip clippy's `too_many_arguments` under `-D warnings` (P8),
and adding an `allow` is rejected. The primitive keeps every containment property P1 has today,
unchanged except for the outcome scoping of the reparse refusal below:

* `single_leaf` refusal, followed by the checked `unicode_string_lengths` guard.
* `RootDirectory` set to the directory handle, with `OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE`.
* `CreateOptions = FILE_OPEN_REPARSE_POINT | FILE_SYNCHRONOUS_IO_NONALERT | (FILE_DIRECTORY_FILE
  or FILE_NON_DIRECTORY_FILE)`.
* `FileAttributes = 0`.
* Status mapping through `windows_open_status_error`.
* The post-open reparse refusal, scoped by outcome as below.

The share mask is the only value the caller supplies that P1 hardcodes today. No other field
becomes newly configurable.

**The reparse refusal is scoped by outcome, not by disposition (r2, I1/I3).** It runs for every
object the call *opened*, meaning `IO_STATUS_BLOCK.Information` is anything other than
`FILE_CREATED`. It is skipped exactly when the call reports `FILE_CREATED`. A created object
did not exist before the call: `FILE_CREATE` and `FILE_OPEN_IF` create only when the name is
absent, and `OBJ_DONT_REPARSE` plus `FILE_OPEN_REPARSE_POINT` turn an existing reparse point at
the name into a collision or an opened object, never a traversal. No EA buffer is passed, so
the created object carries no reparse data. Nothing fallible then runs between a successful
create and the return of its handle, so the primitive has **no path that leaves a created
object on disk without returning its handle**. That is what lets `create_temp`'s caller own
cleanup from the first instant: `infra/fs.rs:806` propagates `create_temp` errors before it
holds the name. The `FILE_CREATED` value comes from `windows-sys` if the crate exports it;
otherwise a local constant carries it, with its value (2) pinned. The statement "created
implies not a reparse point" is a documented-API premise (NtCreateFile
`IoStatusBlock->Information`), not a measurement, and nothing on this machine can measure it.

**Failure semantics:** identical to P1 for every opened object (`InvalidInput` for a bad leaf
or an over-long name, the mapped NT status, `InvalidInput` for a reparse point). For a created
object the only failures are the pre-call refusals and the mapped NT status, and none of them
leaves anything on disk.

### O2 — `open_windows_child` keeps its contract

Rests on the MANDATE words "a parameter that can weaken sharing for all eight existing callers".

`open_windows_child` keeps its exact signature and its traversal sharing policy
(`FILE_SHARE_READ | FILE_SHARE_WRITE`, plus `FILE_SHARE_DELETE` when `allow_delete_share`). It
delegates to O1. None of its ~30 call sites changes (P2), so no existing caller can be handed a
different sharing mask by this change. The boundary function grows no share parameter. The
share mask becomes a parameter only of the lower primitive, whose other caller is the private
temporary.

### O3 — the private temporary routes through O1

Rests on the MANDATE words "so `open_temp_child` can route through it" and "the temporary must
stay private until it is committed".

`open_temp_child` stops hand-laying NT structures. It calls O1 with `FILE_CREATE`,
`TEMP_ACCESS`, the `PrivateSecurityDescriptor` pointer, the file kind and
`FILE_SHARE_PRIVATE_TEMP`, which keeps its current value `FILE_SHARE_WRITE` (`d-20260917-09`).
The `PrivateSecurityDescriptor` must outlive the call; it already does, because `create_temp`
owns it across the retry loop. The function's own `OBJ_*` constants, and any imports in
`mod win` that only it used, are removed if no other user remains.

**Behaviour deltas for the temporary, all toward the stricter P1 behaviour:**

* It gains the `single_leaf` refusal and the checked length guard (P3).
* It always reports `FILE_CREATED` (disposition `FILE_CREATE`), so under O1's outcome scoping
  it runs no post-create query and acquires no orphan path (r2, I1).
* `FileAttributes` changes from `FILE_ATTRIBUTE_NORMAL` to `0`, matching `create_regular_at`'s
  existing `FILE_CREATE` through P1. Microsoft documents `FileAttributes` as defaulting to
  normal and as "applied only when the file is created". This is a documentation premise, not a
  measurement, and the Windows runner verifies it (O5).
* Collision mapping is unchanged (`windows_open_status_error`), so `create_temp`'s retry
  predicate is unaffected (P4).

### O4 — source pins follow the single site

Rests on the MANDATE word "single", and on `d-20260917-03`, which treats pins as necessary.

The pins in P6 are updated to read the new shape rather than deleted:

* **Single-site pin over the whole claimed scope (r2, I2).** Every Rust source under
  `src-tauri/src`, enumerated by the existing `rust_source_paths()` inventory
  (`platform_support/tests.rs:2293`), together contains exactly one `NtCreateFile(` call, and
  it sits in the O1 primitive. The pin file itself is the only exclusion, because its
  assertions quote the name. Its staged failure adds a duplicate call in a module **other
  than** the two current files.
* **Reparse-scope pin (r2, I3).** The O1 primitive's reparse refusal is conditioned on the
  `FILE_CREATED` outcome and on nothing else: not on the disposition argument, and not
  removed. Staged failures: (a) changing the condition to test the disposition (`FILE_OPEN` or
  `FILE_CREATE`) turns it red; (b) deleting the refusal turns it red.
* **Runtime anchor for the opened-object refusal (r3, I4).** None of the existing junction
  tests depends on this refusal alone: they reject the junction through pathname metadata,
  through `enumerated_kind`, or through a second reparse check in `directory_entry_at`. A new
  `#[cfg(windows)]` test goes into `infra/path_authority/mod.rs`'s Windows test module, beside
  `windows_child_open_maps_absence_and_refuses_wrong_target_types`. It creates a junction child
  with `windows_test_junction` and opens it directly through `open_windows_child` (`FILE_OPEN`,
  directory kind, read access). It asserts exactly
  `Error::InvalidInput("reparse points cannot be authorized")`. On that direct call
  `OBJ_DONT_REPARSE` plus `FILE_OPEN_REPARSE_POINT` open the junction object itself, and no
  other check exists that could produce that error. Deleting the primitive's refusal therefore
  turns the test red on `rust-windows-test`.
* **Synchronous-I/O pin.** It asserts `FILE_SYNCHRONOUS_IO_NONALERT` in the one primitive's
  `CreateOptions`.
* **Single-leaf and length-guard pins.** They read the primitive.
* **Private-temporary pin.** It asserts that `open_temp_child` passes `FILE_CREATE`,
  `FILE_SHARE_PRIVATE_TEMP` and `security_descriptor.as_ptr()` to the primitive and never names
  `FILE_SHARE_READ`. It keeps the `const FILE_SHARE_PRIVATE_TEMP: u32 = FILE_SHARE_WRITE`
  assertion.
* **Traversal-share pin.** `open_windows_child`'s delegation passes
  `FILE_SHARE_READ|FILE_SHARE_WRITE` plus `FILE_SHARE_DELETE` gated on `allow_delete_share`.

Call-site pins (1095, 1100, 1131) stay untouched because no call site changes. Each changed or
new pin's assertions are seen to fail once by editing the source they read (the staged-failure
practice of `d-20260917-09`). The failure output is quoted in the phase report, and the source
is then restored.

### O5 — Windows runtime proof of privacy

Rests on the MANDATE words "a test that a second open of the private temporary is refused while
it is held, run on a Windows runner".

A new `#[cfg(windows)]` test in `infra/fs.rs`'s test module creates a private temporary through
`win::create_temp` on a `windows_test_parent` directory and holds the returned handle. The test
needs only the visibility change that makes `create_temp` callable from the tests module. While
the handle is held, the test asserts two things. A plain `std::fs::File::open` of the
temporary's path fails with `raw_os_error() == Some(ERROR_SHARING_VIOLATION)` (32) and not with
access denied. A `std::fs::rename` of it also fails with `ERROR_SHARING_VIOLATION`. The
constant is taken from `windows_sys`, not spelled locally. The test also writes and reads back
through the held handle, proving the handle is still a synchronous, usable file object after
the refactor. After the handle is dropped, the temporary is removed and the directory holds no
`.atomic-` entry.

A second `#[cfg(windows)]` test injects a non-single-leaf temp name (for example `"a\\b"`)
through `win::scoped_test_temp_names`. It asserts that `create_temp` returns
`Error::InvalidInput` and creates nothing, which proves the temporary open now goes through
O1's leaf refusal (P3).

**Verification level:** these execute only on `rust-windows-test` (P9). Locally they are proven
to compile and lint through `pnpm rust:windows:check`.

## Decisions and trade-offs

* **Answer to the open question: neither of the two offered shapes.** The single NT site is a
  lower primitive with a share-mask parameter (O1). `open_windows_child` keeps its signature and
  traversal sharing (O2). The temporary passes its private mask (O3). Rejected, (a): adding
  `share_access` to `open_windows_child` itself. That puts a raw mask on the boundary function's
  ~30 call sites (or a typed enum with the same churn) and exposes every traversal caller to a
  wrong mask, for no containment gain. Rejected, (b): keeping two sites. P3 shows the
  duplication has already cost the temporary three containment checks, which is the drift rule
  11 exists to stop.
* **Sharing is not containment** (threat model). Routing the temporary through the containment
  primitive strengthens it. The temporary's sharing stays exactly as private as today.
* **`FileAttributes = 0`** for every create, rather than carrying an attribute field only the
  temporary would set (O3).
* **The reparse refusal is scoped by outcome (`FILE_CREATED`), not by disposition.** This
  replaces r1's "unconditional" (r2). Round 1 brought new evidence: an unconditional
  post-create `metadata()` query is a fallible step after creation, and `create_temp`'s caller
  propagates its error before it owns cleanup (`infra/fs.rs:806`), so a failure there would
  orphan a private temporary. Rejected, (a): keeping the refusal unconditional and deleting the
  created object on failure inside the primitive. That needs `DELETE` access the traversal
  callers do not request, and it pulls `fs::win`'s delete-by-handle into `path_authority`.
  Rejected, (b): keeping it unconditional and naming the orphan a known limit, because the
  orphan path is new for the temporary. Rejected, (c): scoping by the `disposition` argument,
  because `FILE_OPEN_IF` can open an existing object, which must still be checked.

## Decided autonomously

* **Question:** Does `open_windows_child` become the single NT open with a `share_access`
  parameter, or does the private-temporary open stay a separate `NtCreateFile` site?
  **Chosen:** a lower `#[cfg(windows)]` primitive in `infra/path_authority/mod.rs` owns the only
  `NtCreateFile` call and takes the share mask in a request value. `open_windows_child` keeps
  its signature and traversal sharing and delegates to it, and `open_temp_child` delegates with
  `FILE_SHARE_PRIVATE_TEMP`. **Rejected:** (a) a share parameter on `open_windows_child`, with
  its ~30-call-site churn and a mask exposed to every traversal caller; (b) two sites, whose
  drift already dropped `single_leaf` and the length guard from the temporary.
  **Reason:** sharing is not part of containment, so one primitive with the mask as a
  parameter keeps the boundary function narrow and gives the temporary every containment check
  that applies to a created object. A Windows runtime now exists in CI, which removes the original verification reason for
  deferring. **Governs:** f-20260916-11.
* **Question:** What `FileAttributes` does the unified create pass? **Chosen:** `0`, as
  `create_regular_at` already does through `open_windows_child`. **Rejected:** a per-call
  attribute field that preserves the temporary's `FILE_ATTRIBUTE_NORMAL`. **Reason:** the API
  documents normal as the default and attributes as applied only at creation. The runner
  verifies it. **Governs:** f-20260916-11.
* **Question:** Does the single NT primitive's reparse refusal run on created objects?
  **Chosen:** no. It runs on every object the call opened and is skipped exactly when
  `IO_STATUS_BLOCK.Information == FILE_CREATED`. **Rejected:** unconditional, which adds a
  fallible post-create step that orphans a private temporary, because `create_temp`'s caller
  owns cleanup only after `create_temp` returns; delete-on-failure inside the primitive, which
  needs `DELETE` access and an fs-to-path_authority dependency; scoping by the disposition
  argument, because `FILE_OPEN_IF` may open an existing object. **Reason:** a created object
  did not exist before the call and carries no reparse data. Scoping by outcome keeps every
  opened object checked and leaves no orphan path. **Governs:** f-20260916-11.

## Risks / open questions

* **R1.** Windows-only behaviour (sharing violation codes, attribute default) is not observable
  on this machine. It is verified only by `rust-windows-test` after the push (P9). A red job
  returns to repair under push skill §4.
* **R2.** Known limit, unchanged by this plan. `create_regular_at`'s *own* post-create checks
  (`opened_is_disk` and `opened_file_identity`, `infra/fs.rs:3233-3236`) can still fail after a
  successful create and drop the handle. That holds equally before and after this change and
  lies outside the MANDATE. O1 removes only the primitive's own post-create step.
* **R3.** `ERROR_SHARING_VIOLATION` versus `ERROR_ACCESS_DENIED` ordering. The DACL grants the
  token user (`d-20260917-07`), so access is expected to pass and sharing to refuse. The runner
  decides it, and if the runner contradicts it, O5's expectation is revisited with that
  evidence, never weakened to "any error".
