# Game citations in preparation

ChessBase result-prefixed citations such as `0-1 Beerdsen,T (2520)-Bluebaum,M (2651) Elllobregat op 3rd Sant Boi de Llobregat 2022 (3)` become keyboard-accessible actions in notation, including formatted comments and variation introductions. The preparation text is unchanged.

Activate a citation to search the Library's databases and supported linked PGN collections. A single verified match opens automatically only after a complete search. Multiple occurrences, incomplete searches or unverifiable citation context require an explicit choice. The dialog identifies each game's players, date, event, round and source. Search again starts a fresh read. Closing the dialog or replacing the originating notation cancels the lookup. A tab admission already in progress follows the existing opening contract.

Referenced games must be present locally. Export the relevant games from ChessBase as PGN and add them to the Library first. ChessFable does not download Mega Database games or read proprietary ChessBase formats.

Names match complete surnames and ordered initials, with Unicode normalization and case folding. Full given names contribute an initial per word regardless of capitalization or name order. Spaced or dotted initials also match. A compact token such as `JK` can be either initials or a short given name, so it remains an unverified choice in every casing and either name order. For example, `Smith,JO` rejects both `Smith, John` and `Smith, JOHN`, while `Smith,JK` offers both `Smith, JK` and `JK Smith` for explicit selection. Supplied ratings and outcome remain hard constraints. Lookup searches ordered player pairs and outcome before interpreting citation metadata. It uses each candidate's actual event and site prefixes, including parentheses and years within those headers, to resolve the remaining year and round. For example, `BEL-NED 2017 ICCF` can refer to the event `BEL-NED 2017` at `ICCF`, even when the game's date is unknown or later. A separate year after those headers constrains the actual game date. Contradictory identifiable dates, rounds, events or sites reject the candidate.

Citation context and verification status are transient. Matching retains the full tail through the end of the line or the next recognized player pair, independently of the visible action's end. Visible labels contain the result/player pair and extend through a lexically identifiable closing round. When event/site text could itself contain a year-round sequence and the visible boundary is ambiguous, the action conservatively contains only the player pair while matching still has the complete context. Candidate event/site headers resolve that boundary before the remaining anchored date and round are checked. A shorter matching header prefix alone cannot establish a closing round. Parenthesized or year-round-shaped header extensions must not hide later supplied constraints. Where later metadata has an established boundary, its contradictions still reject the game. Competing unresolved header, field and prose readings remain unverified and require explicit choice. A bare following year such as `2024: Better was Bd3.` can begin prose and cannot replace identifiable original date/round constraints without header evidence. That unresolved reading retains an otherwise matching game for explicit selection, while contradictions in the original metadata still reject it. Once the complete header boundary and closing round are established, ordinary following prose, including incidental parentheses and years, is outside game metadata. For example, `Tata Steel (A) Wijk aan Zee 2022 (3) Better was Bd3 (A).` retains the supplied 2022 and round 3 constraints and leaves the final `(A)` as prose. A later complete year-round tuple separated by that ordinary prose, such as `Better was Bd3 in 2024 (A).` or `Better was Bd3 2024 (A).`, is likewise incidental and cannot replace or cancel the original identifiable year and round.

When an original date/round reading and a later complete reading remain plausible, each is compared with the actual game metadata. A compatible reading retains an unverified choice even when another reading conflicts. Matching only the later reading also requires explicit selection. The game is rejected when every applicable reading contradicts identifiable metadata. Adjacency alone never makes the fitting reading verified. For example, `2022 (3) 2024 (A): Better was Bd3.` can retain a game matching either complete reading for explicit choice. A later boundary established by known site/header evidence keeps its constraints and priority. Bare prose years keep the original identifiable constraints. An unambiguous single reading remains strict and can verify normally.

Unknown actual metadata or remaining context that cannot be verified requires explicit selection, even when all Library sources were searched. A names-only citation with no remaining context keeps its ordinary complete-match behavior. Without an identifiable closing round, following text remains outside the label. After resolving actual event/site prefixes, an open tail that does not begin a year or round is unverified prose. For example, `White was better before 2020.` does not constrain the game's date, whether it follows the player pair, actual event or actual event/site. Exact event/site context still verifies without a closing round. Identifiable supplied metadata retains its constraints, including contradictory event/site rejection. Existing external Markdown links retain their behavior. No stored comment, formatting or PGN command changes.

Pending lookup belongs to the notation's tree store and the workspace document's physical tree key. Engine score updates keep that ownership. Replacing a file game changes the physical key and retires the search even when its store and tree content are retained. Results also check current workspace ownership and the live cached store before publication or automatic opening, covering replacement or close before React cleanup. Ephemeral previews use their store and mounted lifetime. Unmount cancels the search, including when file freshness removes notation during an in-place reload. Admission that has already begun retains its existing contract.

Search uses pages of 100, at most 256 query requests across 64 sources, retains at most 256 matching player IDs per side, 100 occurrences and 100 failure details, and reports limits as incomplete. Unread, unavailable, failed and partially indexed sources also prevent automatic opening and definitive absence. Failed sources retain safe source-qualified guidance. No citation metadata or search cache is persisted.
