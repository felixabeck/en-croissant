# Game citations in preparation

ChessBase result-prefixed citations such as `0-1 Beerdsen,T (2520)-Bluebaum,M (2651) Elllobregat op 3rd Sant Boi de Llobregat 2022 (3)` become keyboard-accessible actions in notation, including formatted comments and variation introductions. The preparation text is unchanged.

Activate a citation to search the Library's databases and supported linked PGN collections. A single verified match opens automatically only after a complete search. Multiple occurrences, incomplete searches or unverifiable citation context require an explicit choice. The dialog identifies each game's players, date, event, round and source. Search again starts a fresh read. Closing the dialog or replacing the originating notation cancels the lookup. A tab admission already in progress follows the existing opening contract.

Referenced games must be present locally. Export the relevant games from ChessBase as PGN and add them to the Library first. ChessFable does not download Mega Database games or read proprietary ChessBase formats.

Names match complete surnames and ordered initials, with Unicode normalization and case folding. Supplied ratings and outcome remain hard constraints. Lookup searches ordered player pairs and outcome before interpreting citation metadata. It uses each candidate's actual event and site prefixes to resolve the remaining year and round. For example, `BEL-NED 2017 ICCF` can refer to the event `BEL-NED 2017` at `ICCF`, even when the game's date is unknown or later. A separate year after those headers constrains the actual game date. Contradictory dates, rounds, events or sites reject the candidate.

Citation context and verification status are transient. Unknown actual metadata or remaining context that cannot be verified requires explicit selection, even when all Library sources were searched. A names-only citation with no remaining context keeps its ordinary complete-match behavior. Visible labels contain the result/player pair and extend through a closing round when one is present. Without a closing round, following text remains outside the label while the full tail stays available for candidate metadata verification. After resolving actual event/site prefixes, an unclosed tail that does not begin a year or round is unverified prose. For example, `White was better before 2020.` does not constrain the game's date, whether it follows the player pair, actual event or actual event/site. Exact event/site context still verifies without a closing round. Year-led metadata, identifiable rounds and citations through a closing round retain their supplied constraints, including contradictory event/site rejection. Surrounding prose after a closing round and external Markdown links retain their existing behavior. No stored comment, formatting or PGN command changes.

Pending lookup belongs to the notation's tree store and the workspace document's physical tree key. Engine score updates keep that ownership. Replacing a file game changes the physical key and retires the search even when its store and tree content are retained. Results also check current workspace ownership and the live cached store before publication or automatic opening, covering replacement or close before React cleanup. Ephemeral previews use their store and mounted lifetime. Unmount cancels the search, including when file freshness removes notation during an in-place reload. Admission that has already begun retains its existing contract.

Search uses pages of 100, at most 256 query requests across 64 sources, retains at most 256 matching player IDs per side, 100 occurrences and 100 failure details, and reports limits as incomplete. Unread, unavailable, failed and partially indexed sources also prevent automatic opening and definitive absence. Failed sources retain safe source-qualified guidance. No citation metadata or search cache is persisted.
